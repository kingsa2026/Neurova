## 1. 根因与修复点

**背景**：R6 诚实化把 `stream_call` 从 `pass` 空桩改为 `raise NotImplementedError`
（诚实暴露但能力缺位）。全仓 grep 复核无生产消费方（基类 `@abstractmethod` 占位之外
仅桩测试），本批为 adapter 能力面完整化，不强行造消费方。

**修复点**（`neurova/llm/adapters/openai_adapter.py`）：

- `stream_call` 实现为 async 生成器，复用 `call()` 的同一套形态：
  - 凭据校验：`api_key` 为空 → `ValueError`（与 `call()` 同文案同姿态）；
  - 依赖校验：aiohttp 惰性 import，缺失 → `RuntimeError`（与 `call()` 同）；
  - 沙箱闸：`validate_request`（预扣 1000 token，与 `call()` 无显式 max_tokens 时同尺）
    + `acquire_resource()` 并发闸贯穿整个流消费期；
  - 端点：`POST {base_url}/chat/completions`，`stream=true`，`temperature` 透传语义与
    `call()` 一致（`temperature or self.config.temperature`）；
  - 错误诚实：HTTP ≥ 400 → `RuntimeError("OpenAI 流式调用失败: HTTP {status}: {detail}")`
    并记 `_last_error`；SSE 帧损坏 → `RuntimeError` 点名坏帧；连接失败/中途断连由
    aiohttp 异常自然传播，不吞不包装。
- SSE 解析：逐行读 `response.content`；`data: {...}` → `choices[0].delta.content`
  非空即 yield；`data: [DONE]` 终止；空行/注释行（`: keep-alive`）/无 content 帧
  （role 帧、usage 帧）跳过。

**契约对齐**（`neurova/llm/interfaces/provider_interface.py`）：基类注解由
`Generator[str, None, None]` 改为 `AsyncGenerator[str, None]`——原注解与
`async def` 生成器实现形态冲突（async 生成器返回的是 `AsyncGenerator`），
以可运行为准同步注解，全仓该契约只剩这一处定义。

## 6. 遗留与移交项

- 流式 usage 统计：OpenAI 兼容流默认不回 usage（需 `stream_options.include_usage`，
  且属 provider 扩展），本实现不伪造 usage 数字，`update_usage` 未接——若后续需要
  流式计量，另立批次接 `stream_options` 并按返回的 usage 帧记账。
- SSE 多行 data 帧（规范允许一个事件拆多个 `data:` 行）未支持：OpenAI 兼容服务
  实践中不拆行，当前按单行帧处理；如接入拆行服务需在解析层合并。
- 基类注解对齐后，其他 provider 适配器（anthropic/gemini 等）若日后实现 `stream_call`，
  应直接按 `AsyncGenerator[str, None]` 契约实现，不得回退同步 Generator 形态。
