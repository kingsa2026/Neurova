## 2. 3.8-1 · KnowledgeApi 秒级时间戳

**根因**：后端 `knowledge_core.py:217` `datetime.timestamp()` 产**秒级** Unix 时间戳；
JS `new Date()` 只吃毫秒，`new Date(dto.created_at)` 直接透传 → 2025 年数据渲染成 1970 年。
修在映射单点 `toItem()`（KnowledgeApi.ets），不在页面逐处补——页面只消费已映射的 ISO 串。

**修复点**：`createdAt/updatedAt` 两行 `new Date(dto.created_at * 1000)`，文件头补口径注释。
**常驻钉**：KnowledgeApi.test.ets 的 `listScoped_maps_items_and_converts_seconds_timestamps`
与 `search_posts_query_and_limit_body` 两例断言 `getUTCFullYear()==2025`（秒 1763220000）。

## 3. 3.8-2 · status_* 三 token 单源增补

**根因**：ChannelIntegrationPage/SessionSyncPage/MonitorPage/StatsPage 四页的 ViewHelper
按「返回 token 名、页面 getColor 解析」契约返回 `status_success/status_error/status_warning`，
但 StyleManager 颜色表没有这三个键 → `getColor()` 回退 `#000000`，四页状态色全黑。
修在 token 表（事实源），不改四页消费面——页面逻辑本来正确，缺的是表。

**修复点**：StyleManager.ets `ColorToken` 联合类型 + LIGHT/DARK 两表各增三键；
**值一律派生**（`LIGHT_COLORS['status_success'] = LIGHT_COLORS['success']` 等），
不写第二份色值字面量——单一事实源不破，基 token 调色时状态色自动跟随。
**同批改**（3.8-2 拍板范围）：8 处 status_* ohosTest 断言加解析验证（§1 表末行）；
StyleManager.test 新增 `status_tokens_resolve_to_real_colors_not_fallback`（修复前该断言
`#000000 != success` 必红）与 `status_tokens_follow_theme_switch`（暗色表三值钉死）。

**命中点扫平**：全仓 grep `getColor('status_` 主源 4 文件（ChannelIntegration/Monitor
两处内联 + 两页经 ViewHelper），LogPage/NotificationPage 的命中仅为「为何避开该前缀」
的注释文字，非消费点；NotificationPage 的 `status_info` 无对应语义（info 已存在）不增补。

## 4. 3.8-3 · SessionListPage 排序比较器

**根因**：比较器 `return a.pinned ? 0 : 1` 与 `a.updated_at > b.updated_at ? 0 : 1`
只产 0/1——「a 应排前」时返回 0（等效相等），排序结果依赖输入次序不稳定，
置顶优先/最新在前两个承诺都不成立（对照安卓侧 `compareByDescending` 正确实现）。

**修复点**：三分支——置顶差异返回 ±1；时间相等返回 0；其余按 updated_at 倒序 ±1。
**行为钉**：R2 harness 对比较器函数体逐字求值断言五分支（置顶为负/非置顶为正/新时间为负/
旧时间为正/相等为 0），红灯 `置顶 a 对非置顶 b 未返回负数`，绿灯五分支全过。

## 5. 3.8-4 · SettingPage 空壳选择器 + applyTheme(auto)

**根因 1**：`showSelectPicker` 弹的对话框只有「取消/确定」两个无动作按钮，不渲染
`item.options`、点选不回写——select 类型设置项（主题/语言）实际改不了值。
**根因 2**：`applyTheme('auto')` 注释自认「当前简化为 light」——auto 名不副实。

**修复点**：
- 选择器改为每选项一个按钮（`AlertDialogParamWithOptions` + `AlertDialogButtonOptions[]`，
  显式类型规避联合重载解析失败，与文件既有写法同源）；当前选中项主题色高亮，
  点选经 `updateValue(item.key, opt.value)` 回写并走既有持久化链。
- auto 分支经 `systemPrefersDark()` 用 dark-mode 媒体查询实时探测系统深色
  （ShellPage 已有同款 `matchMediaSync` 用法先例），探测失败 warn + 按浅色兜底（只影响 auto 档初值）。

## 7. 3.8-6 · 硬编码色值收进令牌

## 8. 3.8-7 · Logger 默认级别 + 超时双口径

**根因 1**：Logger 默认 `LogLevel.DEBUG`，release 形态无人调 setLevel → 全量日志直进 hilog。
**根因 2**：`request_timeout` 两处字面量——ConfigManager 默认表 30000、HttpAdapter fallback
15000。配置键在时走 30000，键一旦缺失（clear 后未 init 等）静默降为 15000，口径漂移不可见。

**修复点**：Logger 默认 INFO（DEBUG 仅显式 setLevel 后开启，注释注明）；
ConfigManager 导出 `DEFAULT_REQUEST_TIMEOUT_MS = 30000`，默认表与 HttpAdapter fallback
都引用该常量——单源，删第二份口径。

## 11. 安卓 3.8-9/3.8-10 + LogPage 导出
