## 1. P1-28/29 · 信封契约归一（含 §11 命中点 9）

## 2. P1-30 · 双 /v1 路径与挂载点

**根因**：`ServerProfiles.getActiveApiBase()` = `{server}/api/v1`，HttpClient 以其为
baseUrl；PushApi/HealthApi/SettingsApi 的路径里再写 `/v1/` 字面量 → `/api/v1/v1/...` 404；
neuron.py 以模块自述 `prefix="/neuron"` 挂在 `/api` 下（挂载表前缀留空，无 /v1），移动端拼
`/api/v1/neuron/*` → 404。

**修复点**：
- `PushApi.ets` remove：`/v1/mobile/push/push-tokens/{id}` → `/mobile/push/push-tokens/{id}`。
- `HealthApi.ets`：getService `/v1/health/services/{name}`（路由不存在）→
  `/health/checks/{name}`（health.py 真实面）；check() 改为 /health + /health/checks 组装
  SystemHealth；getMetrics 后端无路由 → 诚实 throw 点名 /v1/stats/system。
- `SettingsApi.ets`：get/update `/v1/settings/{key}` → `/settings/{key}`；reset 后端无
  `/settings/reset` → 诚实 throw 点名（不冒充 clear-cache）。
- `MonitorApi.ets`：新增 `neuronUrl()` 从 baseUrl 剥去 `/api/v1` 还原源点再拼
  `/api/neuron/*`；四个 neuron 方法全部改走真实挂载点。
- 新增守卫 `entry/src/ohosTest/ets/test/ApiRouteGuard.test.ets`：录制型后端逐一触发 12 个
  模块的代表方法，断言全 URL 不含 `/v1/v1`、base 后路径段不以 `/v1/` 开头、neuron 走
  `/api/neuron/`。

**红灯/绿灯证据**：见 §1 共用 harness——红灯 `PushApi.remove 不再拼出 /v1/v1 :: 'https://s.example.com/api/v1/v1/mobile/push/push-tokens/device-1' == ...`（双 /v1 现场），绿灯同用例 PASS；neuron 挂载由 `ApiRouteGuard.test.ets` 的 `neuron_paths_mount_at_api_neuron_without_v1` 常驻钉死。

## 3. P1-31 · SettingsApi 形状不符

**根因**：后端 `settings.py` GET /v1/settings 返回 `SettingsResponse{settings: Dict,
updated_at}`（裸对象）；移动端期望 `SettingGroup[]` → `res.data.length > 0` 恒假，
SettingPage 永远渲染本地默认分组。

**修复点**：`SettingsApi.ets` list() 按 `{settings:Dict}` 真实形状解析——section（dict 值）
展开为 `${section}.${subkey}` 条目并按 section 分组，平铺键归入 general 组，值类型推断
SettingType（boolean→toggle，其余 input）；get/update 按 `{code,data:{key,value}}` 信封解出
SettingItem。update 路径同步修正（P1-30）。

**红灯/绿灯证据**：见 §1 共用 harness——红灯 `SettingsApi.list 解析 {settings:Dict} :: false == true`（旧实现原样透传非数组），绿灯同用例 PASS。

## 4. P1-32 · SessionsApi pin 缺必填字段

**根因**：后端 `console.py` `PinSessionRequest{pinned: bool}` 必填；移动端 pin 发空 body
`{}` → 422。

**修复点**：`SessionsApi.ets` pin(sessionId, pinned?)——显式传 pinned 直接提交；不传时保持
调用方既有"翻转当前态"语义（先查列表取当前 pinned 取反），body 为 `{pinned: bool}`。

**红灯/绿灯证据**：见 §1 共用 harness——红灯 `SessionsApi.pin 发送 {pinned:true} :: Expected values to be loosely deep-equal:`（旧 body 为 `{}`），绿灯同用例 PASS（body 深比较等于 `{pinned:true}`）。

## 7. P1-36 · 凭证与设备身份持久化

**根因**：StateManager 纯内存 Map、AuthStore 全部凭证只存内存；StorageAdapter（preferences
桥）全仓零生产引用。冷启动 isAuthenticated 恒 false → 必回登录页；WS 续签依赖的
pairingId/deviceSecret 重启即空。

**修复点**：
- `AuthStore.ets`：refresh_token/wsToken/wsUrl/pairingId/deviceSecret 经 StorageAdapter
  **写穿持久化**（setTokens/setDeviceIdentity/setWsPairing 同步落盘，失败经 ErrorManager
  上报不阻断内存态）；access_token **内存优先**不落盘；新增 `restore()`——回填持久化凭证后，
  内存无 access_token 且有 refresh_token 时走 /auth/refresh 续签并经 /auth/me 回填用户，
  续签失败清除本地凭证回登录；logout 同步清除持久化。
- `Index.ets`：冷启动先 `StorageAdapter.init(context)` 再 `authStore.restore()`，之后才按
  isAuthenticated 分发（恢复失败按未登录处理）。
- `StorageAdapter.ets`：init 入参放宽为 `common.Context`（Index 场景只有 Context）；
  **正式接线**（此前零生产引用），不退役。

**红灯/绿灯证据**：见 §1 共用 harness——红灯 `AuthStore.setTokens 持久化 refresh_token :: '' == 'rt-1'`
（旧实现不落盘）与 `AuthStore.restore 无凭证安全回落 :: store.restore is not a function`（旧实现无 restore），
绿灯两用例 PASS（refresh_token 落盘可读、logout 后清除；无凭证 restore 安全回落）。

**live-verify**（模拟器实跑，hdc + Mate 90 Pro 模拟器）：
- 主源 HAP 全量重编（hvigor assembleHap BUILD SUCCESSFUL）后装机启动：
  `Index: [INFO] 冷启动：无服务器档案，跳转连接页`——新冷启动链路（ServerProfiles →
  ConfigManager → StorageAdapter.init → AuthStore.restore → 分发）全程无崩溃。
- 后端真机形状核对：`curl http://127.0.0.1:9527/api/v1/health` 返回
  `{"status":"unhealthy","timestamp":...,"uptime":0.0,"checks_count":3,"healthy_count":2,...}`
  ——与 HealthApi 新映射所依的 HealthStatusResponse 裸对象形状逐字段一致。
