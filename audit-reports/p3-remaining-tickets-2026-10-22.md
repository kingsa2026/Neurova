## 票一｜根外信任锚：要不要把"摘要"搬到构件够不着的地方

**问题（现读，不是我推测）**：`artifact_digest.py:25-28` 自己把边界写在模块头——摘要钉在账本里，
而账本与被保护构件**同根同权限**：插件的 `state.json` 就在插件根内、技能的摘要就在
`<skills_dir>/manifest.json`。能整体改写磁盘的人，也能同时改写构件与它的摘要。
于是这块今天封的是**在途换包**与**落盘后的改动**，封不到"拿到机器后定向重算再改"。

**三态与影响面**：

- **甲｜建根外锚**（把摘要另落一份到构件写权限之外的地方，装载时两份都比）。三种落点各自代价不同：
  ① 仓外文件（`~/.neurova/…`）——本仓有先例（`AuditLogger` 默认落点就在数据根之外，§6-155 登记过），
  但"根外"只是**换个目录**，同一用户的进程仍可改写，防的是误改与并发写，防不到同权限攻击者；
  ② 系统凭据库（Windows 凭据管理器一类）——本仓从未用过，跨平台要三套实现，且密钥/锚点的备份
  会变成运维负担；③ 配置注入的公钥＋构件签名——这才是真封住"来源"的形态，但需要**签名体系**
  （谁签、用什么签、存量包怎么补签），是三档里唯一改变信任模型的，最贵也最不可逆。
  影响面：`plugin_manager.py:417/518-536`、`skill_service.py:748/822/2014`、`state.json`/`manifest.json`
  两处 schema（要加版本位）、数据根口径与仓库根污染守卫。
- **乙｜承认边界，不假装能力**（推荐）：不改代码，把这条边界在文档与判据期望值上收敛——
  摘要只声明"证同源，不证来源"。今天 `artifact_digest.py` 的模块头与 §6-176 已经这样写了，
  要做的是把散在别处的"供应链校验"措辞按这个口径统一（本会话已改四处，`3f01a76e`）。
  代价零；不覆盖的风险也如实留在案上。
- **丙｜为"便利"打开自动装载**：让 `loaded` 落盘、开机自动 exec。**不推荐**——它把 §6-164 那条
  裁定反过来了，而它声称依赖的前提（"等 P3 做完"）里的哈希部分**已经做完了**：也就是说
  现在打开自动装载，挡在中间的只剩"来源不证"这一条，而这正是丙解决不了的。

**不可逆点**：一旦把"锚不在/不符"改成**拒挂**，存量技能与插件会被全部挡在装载门外
（含内置链）——§6-176 为这条特意选了 TOFU 首钉而不是"无摘要即拒"。甲的任何一档都要先决定
存量怎么办（回填锚？一次性首钉？），而回填动作本身就是一次全库写。

**推荐**：**乙**（已随 `3f01a76e` 落了一半，剩下的是措辞统一），并把**甲①**作为下一刀的候选
单独评估——它便宜，但要如实写成"防误改与并发改动"，不许写成防篡改。

## 票二｜插件的远程源白名单：以及"到底要不要开远程取回"

**问题**：插件今天不接受远程源——`plugins/plugin_manager.py:268-270` 对 `http://`/`https://`/`ftp://`/`git+`
一律 `PluginError("remote_source")`，HTTP 面映射 501。**插件侧没有市场侧那样的域名白名单**
（市场那份在 `market_sources.py:220-237`，且它的下载已经过 `safe_archive` 咽喉＋装时钉摘要）。
所以这张票真正要拍的不是"怎么写白名单"，而是**开不开这个口**。

**三态与影响面**：

- **甲｜继续不开**（现状，最小面）：远程永远 501，插件要人手工放进插件根再过安装门。
  代价：插件生态全靠手工分发；收益：敞口为零，且 `loaded` 不落盘的边界依然干净。
- **乙｜开，但整体复用市场那条链**：白名单（注册源表，不是任意 URL）＋ `safe_archive` 咽喉
  （10MB/500 条目/zip-slip 三件现成）＋ 装时钉 `artifact_digest` ＋ 取回失败**结构化拒因**。
  要新增的只有：插件侧的注册源表与它的 admin 写面、取回侧的 HTTP 客户端选择（复用哪个咽喉，
  别新造一刀 `requests`）、以及"钉在取回瞬间还是落盘后"的次序（必须与门看到的字节同源）。
  影响面：`plugin_manager.resolveInstallSource`、`api/endpoints/plugin.py` 的 reason→status 闭集
  （要加档并过闭集守卫）、`state.json` 版本位、审计面（谁在什么时候从哪个 host 取了哪个包）。
  风险点：**顺序**——若先落盘再校验，中间窗口就是敞口；白名单必须打在**取回前**、摘要打在**门当时**。
- **丙｜开且允许任意 URL**：不推荐。那等于把今天一句响亮的 501 换成一条供应链敞口，
  而摘要只证同源不证来源（票一），挡不住"从一个任意 URL 取回一个自洽的包"。

**不可逆点**：一旦开了远程口，就有了"取回过什么"的运维与取证责任（审计留存、源失效后的重装语义）；
关掉容易（再退回 501），但那期间的每一次取回都在盘上留了件。

**已落（2026-10-22）**：用户拍「甲①＋乙」，`21fa261c`（台账 §6-388）——锚落 `~/.neurova/artifact_anchors.json`（数据根之外，理由是整库回滚会把数据根里的构件/账本/锚一起滚回去；审计库当年是反方向，别读混）、键按 `channel:id` 闭集、坏文件隔离并响亮报、`checkArtifact` 账本相符后再看锚且锚缺不挡存量、两个通道的钉写口都落锚、锚写失败只出声不回滚账本。11 格入子集，活体新增 [15]-[18] 四格（其中 [17] 是本批的核心：改构件＋把账本重钉一次、不碰锚 ⇒ 仍拒），**20 读数全 PASS**。边界写明：它**不**防同权限攻击，防的是只动数据根的整库回滚与重钉账本。

**已落（2026-10-22）**：用户拍乙，`a71d6d6f`（台账 §6-390）——白名单默认**空**（开箱仍不可远程安装，要管理员显式登记）、`sources.json` 源表＋三个仅管理员的写面、取回前判 host 且**复查重定向后的 host**、解包受 `safe_archive` 三件牙与单包/条目上限约束、装时钉摘要＋根外锚＋`state.json` 的 `install_source` 留痕、失败撤回网络字节。17 格入子集，活体（真 app＋真 JWT＋本机回环 http.server）17 读数全 PASS，其中「未登记 host 时一次请求都没发」与「改一个字节后装载按 mismatch 拒」是核心两格。边界：没有 TLS 固定与签名，来源只到 host 一级。

## 票三｜§6-177 那张甲/乙/丙票的复核：甲案已半落地，缺口换了形状（本格含一次自我作废）

**先记账上的错**：本节初稿写的是「`market_importer.import_skill` 全程不 import 摘要 ⇒ 市场安装的包没有『门当时的底』，只被装载前 TOFU 首钉兜住」。**那句作废**——它只看了 `market_importer` 一个文件，漏了端点在 importer 之后还有一步 `link_market_skill_to_agent`（`marketplace.py:405-413`），而那一步经 `_writeAgentManifestOutcome`（`market_registry.py:227-245`）走的就是 `install_skill` 那个咽喉。**只查一半就写结论**，是"把审过的面当成全貌"那一族的复发。

**活体复算**（`tests/manual/marketTicketThreeDigestPath.py`，真 `create_app()` ＋ 真 JWT，15 读数全 PASS）：

- 装 `builtin--multi-search-engine`（内置 bundle 那条**离线**支，不出网）→ 200；账本里**有这一条**、**钉了构件摘要**，且**钉值与运行时目录现算值同源**（读回 `sha256:51124c32…` == 现算 `sha256:51124c32…`）——所以 §6-183 那枚「钉的是影子目录」的形态在市场这条路上**不成立**，安装侧是干净的。
- **缺口在执行侧的第二条腿**：把运行时目录里的 `SKILL.md` 改一个字节之后——① 注册表那条腿（`market_registry._build_executable_skill(...).execute`，也就是 LLM 真正会走的那条）把**被篡改的指令体照原样交给模型**，且这一趟 `artifact_digest.checkArtifact` **被调 0 次**：不是"检查后放行"，是**根本没检查**；② 账本那条腿（`skill_service.call_skill`）对同一份篡改回 `artifact_digest_mismatch`（带 `expected_digest`/`actual_digest`）拒下来，`checkArtifact` 确实被调并读出 `mismatch`；③ 还原字节后重新一致；④ 校准格：不存在的技能回 `Skill not found`（不是摘要拒），证明 ② 的拒因不是"逢调用都拒"。
- 另两格否证了自己的推测：`call_skill` 的映射那条腿要求 `_entry()` 在册且执行体由**仓内代码**构造（`buildMappedExecutable`），它不读盘上字节，**不是**第二条敞口；`_register_metadata`（`skill_service.py:1329`）写的条目 `path` 恒为空串，自动/合成技能本就没有外部字节，它不是第三个钉点。

**所以票三要拍的不再是"接不接进咽喉"（那半已经做了），而是同一本账的两条腿要不要共用同一道闸**。三态：

- **甲｜注册表那条腿也过同一道闸**：`_build_executable_skill` 造出来的执行体在 `execute` 之前对账（口径仍取 `artifact_digest` 那一处，不新建第二份），不符就如实拒。代价：`execute` 有两支形状（映射腿刻意在锁外 await，见 `_callMappedSkill` 那段死锁说明），加对账要给两条腿同一个取径、同一个拒因；收益：**把"扫过的那份字节"与"交给模型的那份字节"真正绑住**——这正是 §6-176 立摘要时的原意。
- **乙｜把注册表那条腿收进账本腿**：工具面一律经 `call_skill`，不让注册表直接持有执行体。收益是一条腿一个闸、不用两处各写；代价最大——它改的是每次对话都走的面（`ExecutorBackedSkill` 的锁语义、`method` 契约、`registry.register` 的鸭子类型），回归面覆盖整轮回合。
- **丙｜只在文档与账本上把边界写明**（"完整性只保护账本那条腿"），不改代码。代价：篡改在现实那条腿上仍静默通过，而摘要的存在会让人**以为**已经管住了——这是把名实不符留在原地。

**已落（2026-10-22）**：用户拍甲，`04dbe9b9`（台账 §6-387）——注册表腿在 `execute` 前对账、未钉走 `onPin` 首钉（与 `call_skill` 同口径）、12 格入子集、活体 16 读数全 PASS。两处如实：① 没钉过的存量条目若出现在注册表腿上会被首钉一次并落账（与 `call_skill` 一致），**存量清单本批没出**（要看各 agent 的 `manifest.json` 里哪些已装条目没有摘要）——登记为待办；② `pinnedDigest=None` 的「不由闸管」口径仍在（直接构造做单元实验），由 AST 守卫扫全仓构造点兜住，不靠自觉。

## 补证的去向（一次自我作废的记录）

本节初稿在此写过一段"代码级追踪"，断言市场那条路"既不钉摘要、也进不了验摘要的读路"，并把"没证到执行侧"那条留在未证到清单里。**追踪方向对、结论错**：它只覆盖 `market_importer`，没覆盖端点在 importer 之后的 `link_market_skill_to_agent` 那一步。改判过程与证据都在上方「票三」一节（`tests/manual/marketTicketThreeDigestPath.py`，15 读数全 PASS），此处不再重复，只留下这条**为什么错**的记录：

按"某个文件里 grep 不到某符号"推"这件事没做"，在多步链路的路由面上一天就会犯一次——**要按接缝取数**（谁把字节交给执行），**不是按文件名取数**。同一族还有本档上面那处：把"方法零调用"读成"类零调用"。
