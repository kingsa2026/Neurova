# 工具/loop 域「死线」台账（T-01，Issue #175；形态复用上下文域 B6-1）
#
# 行格式：`符号 | 种类 | 判据类 | 阈值可达性 | 引用点数 | 处置 | 依据`（七列，`#` 注释与空行忽略）。
#
# ── 两轴分离（沿用上下文域的核心纪律） ──────────────────────────────
# ① **判据类**（第 3 列）：机器算出来的直接可达性，**不得人填**。
#    器械单源是 scripts/ci/tool_loop_deadline_ledger.py（符号级走
#    scripts/ci/context_deadline_ledger.py::classify，同词汇同规则），四值：
#      absent      ― 生产侧无定义、无赋值（符号不存在或已删除）
#      no_consumer ― 有定义/赋值，但生产侧零消费点
#      self_loop   ― 有定义，消费点全落在自己定义文件内（无外部消费者）
#      consumed    ― 有定义，且存在跨文件消费点
#    台账值与算出来的不一致 → 守卫报红。人改台账去迎合等于把判据降级成自述。
# ② **阈值可达性**（第 4 列）：**本域新增的第二判据轴，同样机器算**。
#    它不是判据类的第五态——判据类回答「AST 事实能证明的直接可达性」，
#    本轴回答「阈值的**值**在合法配置域够不够得到」，两者证据不同、必须分开，
#    否则四值分支不再能由 referenceSites() 的事实直接验算，且与上下文域不可比。
#      not_a_threshold     ― 非阈值型门控（check() 内无 `self.<阈值参数>` 比较）
#      unbound             ― 阈值型，但阈值参数无配置键绑定来源
#      single_source       ― 阈值型，配置键在生产侧只有一份尺度（阈值可达）
#      scaled_unreachable  ― 被同键的更小尺度守卫遮蔽，合法域内门控吃不到阈值
#      scaled_sparse       ― 同上，但合法域内极少数配置能让门控出声
#    证据三条（缺一条都不成立，由 thresholdAxis() 复算）：门控构造直接绑定配置键；
#    同键存在 `…[同键] // d`（d≥2）的更小尺度守卫；合法配置域内存在/不存在可达配置。
#    站点次序（同一轮内守卫先还是门控先）按**函数**分组输出，因为它是
#    scaled_unreachable 与 scaled_sparse 的唯一分界。
# ③ **引用点数**（第 5 列）：台账照抄实测总数，**与实测不符即报红**（Issue #175 显式要求）。
# ④ **处置**（第 6 列）：人对该条的决定，有限枚举、机器可判定（与上下文域同枚举）：
#      待处置 / 已接线 / 已删除 / 收口第二份
#    **本片（T-01）只建判据、不做处置**，故全部条目均为「待处置」。
#
# ── 取数口径（本域比上下文域多两种形态） ────────────────────────────
# 种类（第 2 列，机器算）：
#   symbol  ― 模块级符号：属/类/函数/import，走上下文域单源 referenceSites()
#   binding ― 函数内局部量：按 ast.Name 的 Store/Load 计写读，**限定在写入它的
#             最内层函数作用域内**（否则全仓同名局部会串台）
#   key     ― 字典字符串键：下标赋值记 write，下标取值/get/in 记 read，
#             pop/del 记 **write**（移除型访问证明有人动过它，不证明有人消费它的值）
# 另一条事实（**不参与机器判定**，只写进依据）：binding/key 的引用点带**接收者**
#   （局部量=函数名，键=被下标的表达式）。接收者归属需要类型推断，静态近似必然误判
#   ——上下文域已实测 `dedup` / `clear` 两面反例；故「唯一一处 read 落在另一个接收者上」
#   这类结论写在依据里逐条论证，不靠机器猜。
#
