严重断点 — 影响安全或功能

#1
eval() 代码注入风险
neurova/router.py:218 — _route_skill_request()
Skill 请求路由中使用 eval(params_str) 解析用户输入参数，注释写"尝试解析为 JSON"但实际用 eval()。应替换为 json.loads()。
#2
ChannelManager 端点直接构造
neurova/api/endpoints/channel.py:67 — _get_channel_manager()
直接 ChannelManager() 构造而非 ChannelManager.get_instance() 或 get_channel_manager()。每次请求创建新实例，渠道状态丢失。
#3
ToolRouter Skill/MCP 工具路由被阻断
neurova/tool_layers/tool_router.py:152-158
execute() 中 "if tool_name not in self._builtin_tools" 检查会导致 Skill 和 MCP 工具直接返回 "Tool not found"，永远不会到达 _execute_skill/_execute_mcp 分支。get_all_tools() 也只返回 _builtin_tools。
#8
EvolutionOrchestrator 初始化顺序问题
neurova/agent_core.py:478 vs 530-535
voice_memory_bridge 在第 478 行初始化时引用 self.evolution，但 evolution 在第 530 行才被赋值。导致 bridge 的 evolution_orchestrator 参数始终为 None。
#4
内置技能 MemorySkill / WebSearchSkill 为桩
neurova/skill_system.py — MemorySkill._search_memory() / WebSearchSkill._search_web()
MemorySkill 返回空列表，WebSearchSkill 返回空列表，注释标注"这里应该实现"。FileOperationSkill 已完整实现。

警告 — 潜在风险或待优化

#5
Token 估算 4 种不一致实现
injector.py / context_pool.py / context_compressor.py (2处)
中文 1.5~2 token/字，英文 0.25~1 token/word，或 len//4。同一段文本估算差异可达 1x-8x，导致预算控制和压缩行为不一致。
#6
Memory / Conversation pyc 骨架占位类
neurova/mem_core.py:35-46
两个类仅使用 setattr 动态赋值，注释自标"pyc骨架恢复占位"。不影响 MemCore 核心功能但缺乏类型安全和验证。
#7
knowledge/rag/ 源文件已删除，残留 .pyc
neurova/knowledge/rag/__pycache__/enhanced_retrieval.cpython-312.pyc
源 .py 文件已不存在，但 __pycache__ 中的编译缓存残留。可能导致 import 时加载旧代码。
#9
Image Pipeline build_image() 为模拟构建
neurova/image_pipeline/__init__.py:253
注释"模拟构建过程"，直接设置 SUCCESS 状态并生成假 image tag。数据模型和管理层完整但无实际 Docker 集成。
