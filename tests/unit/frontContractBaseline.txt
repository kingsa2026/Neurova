# 前端调用 ↔ 后端注册 差异的**裁决台账**（Issue #68 收口）
#
# 行格式：`模块 | 方法 | 路径 | 裁决 | 依据`
#
# 布局纪律：台账行必须集中在文件**头部**，正文注释不得插在行之间再回头续行。
# 写入侧 (`_frontContractRows()`) 只认「首个非空行」起的一段连续行。
#
# 收录口径：`scripts/generate_api_inventory.py::unmatchedFrontCallRows()` 报出的
# 每一条「前端调用在后端注册表里无对应路由」。清单第四节只登记「有哪些差异」，
# 本台账回答「每条的结论是什么、办了没有」——与未挂载端点台账同纪律。
#
# 裁决是**有限枚举**，机器可判定（FRONT_CONTRACT_VERDICTS）：
#   已修   ― 该调用现在命中真实路由表（改指正确契约或补齐后端端点）；
#   已退役 ― 该前端调用无任何非测试消费点，属幻影契约，连同函数一起删净；
#   待接线 ― 保留待办，必须写明依据与承接方（不得留空）。
#
# 判据单源在 scripts/generate_api_inventory.py；守卫
# tests/unit/api/test_route_mount_contract_guard.py 双向钉住
# （新增断链无裁决即红、裁决为「已修」却仍在差异表里亦红）。
