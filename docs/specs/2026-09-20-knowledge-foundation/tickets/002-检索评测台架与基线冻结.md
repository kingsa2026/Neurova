# 002 检索评测台架与基线冻结

**Blocked by**: 001
**阶段**: E0（设计文档 §8、§4.2 评测层三表、§9 E0 出口判据）

## 目标
一条命令跑出当前知识检索的真实读数（recall@5 / MRR / 零命中率）并落库为冻结基线，
后续每张切读票都能用同一把尺子对比。

## 涉及层
- [ ] 数据层：`evaluation_cases`（`query`、`expected_fact_keys_json`、`domain`、`created_by`、`frozen_at`）、
      `evaluation_runs`、`evaluation_findings` 三表，走既有版本化 migration 口径
      （参照 `neurova/knowledge/ingest_queue.py:34` 的 `apply_migrations` 用法）
- [ ] 逻辑层：`neurova/knowledge/evaluation/retrieval_benchmark.py` 的 `RetrievalBenchmark`——
      取真实 `KnowledgeRepository` + `hybrid.py:104` 检索路，逐案算 recall@5 / MRR / 零命中率
- [ ] 夹具：从 `data/knowledge/knowledge.json` 的 130 条真实条目抽样标注 ≥30 个 query→期望命中集；
      **严禁 MagicMock 冒充检索对象**
- [ ] API：`GET /api/v1/knowledge/evaluation/baseline`（只读读数与 `measure_state`）
- [ ] 测试：`tests/unit/knowledge/test_retrieval_benchmark.py`——指标数学正确性 + 空集三态

## 验收标准
- 台架对现有实现跑出**非零**读数（跑不出真实数字说明夹具注错，判未完成）。
- 读数缺失时返回 `unevidenced` 而非 0 或 1，且不按通过处理（ADR 0016）。
- 基线落库并带 `frozen_at`；再次运行生成新 `evaluation_runs` 行，不覆盖基线。
- 报告列出零命中率基线值——它与 §1.2 的 38 行纯冗余共同构成 E2 的对照锚。
