## 目标
检索命中的条目带上自己的治理行（`lineage_id` / `evidence_state` / 派生 `confidence` /
`adoption_outcome` / `recorded_at`），并把注入计数真正回写。排序**一字不动**。

## 为什么不是交织
011 已经用真数据否证过两池按秩合并：同一份内容在两个池子里各算一票，短事实凭 BM25
优势挤掉强叙述命中（recall@5 0.8555 → 0.7604）。"合一"的正确形态是
**一条知识一个候选，治理字段挂在它身上**，不是把同一份内容再端一遍。

## 一件试过又撤回去的事（证据在这儿）
把 `(agent, content_key)` 与三元组唯一索引改成"只管 active 行"，让 A→B→A 算新一代主张。
**实测代价**：回放里某行被冲突裁决自动取代后，同内容不再折叠而是另开一行 ——
130 行旧库从"预测 92 / 实跑 92"变成"预测 92 / 实跑 102"，E1 出口判据当场不一致。
也就是说代际语义会把**内容去重做成裁决顺序的函数**，这比它解决的问题更糟。
v6 已撤（含生产底座库重放到 v5：92 事实 / 87 主体），常驻用例
`test_supersededRowStillAbsorbsIdenticalContent` 钉住"同内容只能有一行"。
要真立代际，前提是让静态预测侧看得懂它，或把"哪条生效"从唯一索引里搬出去 —— 另立工单。
