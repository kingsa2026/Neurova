# 008 事实生命周期（G06）

**Blocked by**: 003
**阶段**: E1（§4.2 事实层、G06）

## 目标
事实有状态：被取代、到期、撤销都能表达，且撤销后仍可溯源（可撤销不可遗忘）。

## 涉及层
- [ ] 数据层：`knowledge_facts.status`（active/superseded/expired/retracted）、`supersedes_fact_id`、
      `valid_from`/`valid_until`、`retracted_at`、`evidence_state` 三值（沿用 EKB 词汇，
      见 `experience_knowledge_base.py:188-198`，不另造第二套）
- [ ] 逻辑层：`KnowledgeFactStore.expireFacts()` / `supersede()` / `retract()`；到期由显式调用驱动，
      不靠隐式后台扫描（避免与 `auto_expire` 旧语义混淆）
- [ ] 读侧约束：检索候选只允许 `active`；`retracted` 仅溯源查询可读
- [ ] 测试：`tests/unit/knowledge/test_fact_lifecycle.py`

## 验收标准
- `supersede` 后旧事实从检索候选消失但仍在账上，且能从新事实走到旧事实。
- `valid_until` 已过的事实不出现在检索候选，出现在溯源查询。
- `evidence_state` 三值可区分 evidenced / failed / unevidenced，NULL 专用于"从未回写"。


## 完成状态（2026-09-20，41 用例全绿，由并行代理实施、主线验收）

落位：`knowledge_facts.py` 只加行为（`supersede` / `expireDueFacts` / `retract` /
`setValidUntil` / `setEvidenceState` / `_requireFact` / `_instant`），未动 `_SCHEMA`；
`factsForSubject` 默认只出 active，`includeInactive=True` 仍可溯源读到 superseded/expired/retracted。

三处需主线定夺的偏差（已裁决）：
1. 原工单把"NULL 专用于从未回写"写在 `evidence_state` 上，与本表 `NOT NULL DEFAULT 'unevidenced'`
   冲突。**采纳代理方案**：`evidence_state` 管形成侧三值，"从未回写"由 `adoption_outcome`
   的 NULL 承载（工单 010 的域）。设计文档 §4.2 已补"两列三值的分工"。
2. 为使 `expireDueFacts` 可达而补了 `setValidUntil`（工单未列）。**采纳**：缺它该行为不可达。
   时效比较统一走 `_instant`（Z / +08:00 / naive → UTC 瞬时），读侧仍以 `status` 为唯一权威，
   不再二次比时钟，避免第二真源。
3. `supersede` 只允许两侧都是 active，非 active 即 `ValueError`——防"取代一个已被取代的"。
