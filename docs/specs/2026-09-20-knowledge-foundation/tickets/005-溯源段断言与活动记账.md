# 005 溯源段：断言与活动记账（G01）

**Blocked by**: 004
**阶段**: E1（§4.2 溯源层、§5 段6）

## 目标
任何一条事实都能回答"谁、何时、经哪条管线、依据什么原始陈述进来"，且**匿名知识进不来**。

## 涉及层
- [ ] 数据层：`knowledge_assertions`（`assertion_id`、`fact_id`、`actor_type`、`actor_id`、
      `activity_id`、`medium_ref`、`statement_text`、`asserted_at`、`weight`、`verification_state`）、
      `knowledge_activities`（`activity_kind` 七种、`inputs_json`、`outputs_json`、`basis`、`tool_version`）
- [ ] 逻辑层：`foundation/lineage.py` 的 `KnowledgeLineageLedger`；`admit()` 段6 写断言+活动；
      五条写路径（人工 / 导入 / 抓取 / 渠道同步 / 对话结晶）各自的 `actor_type` 与 `medium_ref` 定义清楚
- [ ] 硬约束：`assertions_json` 为空 ⇒ 拒绝入库（抛错，不降级、不补默认断言）
- [ ] 查询：`KnowledgeFactStore.trace_lineage(fact_id)` 正向回溯到原始陈述
- [ ] 测试：`tests/unit/knowledge/test_lineage_ledger.py`

## 验收标准
- 无断言的 admit 被拒绝，且错误信息指名缺哪一维（actor / medium / statement）。
- 任取一条 admit 成功的事实，`trace_lineage` 返回可打印的逐跳链。
- 既有 `repository.py:490` 的单字符串 `source` 仍可读（扩展期不破契约），但新写路径一律产断言。
