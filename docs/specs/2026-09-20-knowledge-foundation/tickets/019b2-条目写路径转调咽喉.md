# 019b-2 条目写路径转调咽喉

**Blocked by**: 019b-1
**阶段**: E3（§5 咽喉 + §4.1 投影层不持写权）

## 目标
闸开时，`create_knowledge` / `update_knowledge` / `delete_knowledge` 经
`productionAdmissionGate` 落一条 `record_kind='narrative'` 的治理行：
新增即 admit、正文编辑即"新行取代旧行"、删除即 retract。
条目上显示的 `confidence` 改由断言聚合回写，硬编码 0.7/0.5 在写侧就此失效（G11）。

## 只转调这三个动词（设计判断，不是偷懒）
其余 23 个写方法改的是**叙述属性**（可见性、共享名单、公共库审批状态、分块编辑簿记），
不改变"这条知识说了什么"，因此不该产生新的事实版本。
把它们也塞进咽喉会让每次共享操作都冒充一次知识更新，那是把治理账本写脏。
分块编辑（`update_chunk`）是例外候选——它会改正文，随 019b-3 的读面合一一起处理。

## 条目 → 治理行的解析口径
按 `content_key` 优先、`object_term`（就是 knowledge_id）回退。
理由：004 定的"同内容即同一知识"折叠在条目层同样成立——两条正文完全相同的条目
**必须**共享一条事实；若只按 knowledge_id 找，折叠发生时那个条目会查不到自己的治理行。

## 涉及层
- [x] 数据：无需新表（`record_kind` 已在 v5）
- [x] 逻辑：`foundation/entry_ledger.py` 的 `EntryLedger`（admit / 取代 / retract / 投影自检）
- [x] 集成：`KnowledgeRepository` 三个写动词在闸内接账本；`_save` 失败与账本失败都直抛
- [x] 测试：`tests/unit/knowledge/test_entry_ledger_019b2.py`

## 验收标准
- 闸外：三个写动词一字不改旧行为，底座库零触碰。
- 闸内：新增→1 条 active 叙述事实且带断言；编辑→旧行 `superseded`、新行 active；
  删除→`retracted` 且查不到 active 行。
- 闸内 `item["confidence"]` 等于聚合值（1 源 0.45），不等于调用方传的数。
- 混合写入后投影自检为空：每个 active 条目恰有一条 active 治理行。
- 账本抛错必须冒到调用方，不许被降级成日志。

## 完成状态

14 例（`test_entry_ledger_019b2.py` 9 + 追加在 019a/019b-1 里的 5 例口径修正）。
过程中撞到三件真事，都不是"改测试让它变绿"能了结的：

1. **叙述行的身份不能是条目 id**。条目 id 编辑前后不变，(主体, `documented_as`, 客体)
   三元组就条条相同，`upsertFact` 把每次正文改写吞回同一行——旧说法永不退场，
   编辑在治理层完全隐身。改法在咽喉里：叙述记录以**内容键**立身，
   无内容身份的条目仍按 id 立身；条目 id 另外记进 `source_turn_id`（`entry:` / 回填的 `legacy:`）。
   配套：`activeNarrativeFact` 两种口径分开查——传内容键时只认内容键，
   否则投影会把"还没改写"当成"已经对齐"。
2. **取代归冲突裁决，不归账本**。账本自己也 supersede 一次，同一对行被裁决两遍，
   第二遍必撞"取代只发生在 active 事实上"。账本只保留裁决做不到的那件事：
   按全集算认领关系再 retract，共享的事实因此不会被误撤。
3. **装载即对齐**。开闸后不必再手工跑回填：`_load` 走一遍投影，缺的治理行按同一口径补投
   （admit 幂等）。只报不修等于留一道人工断点。补投后仍不收敛才打 ERROR。

一处口径收窄要认账：019a 的"逐字段等于 JSON 时代"现在**不再覆盖 confidence**。
我把豁免写成了显式断言（非 confidence 字段深相等 + confidence 必须落在聚合格点上 +
至少一条真的变了），而不是悄悄把等式删掉。

019b-3 的入口条件因此明确：读路径按 `object_term`（内容键）/ `source_turn_id` 回查正文，
放开 `includeNarratives`，并把 `source` 也改成从断言 `medium_ref` 派生；之后才删 JSON 条目路径。
墓碑与冲突两本旁账仍未收编（019b-2 原计划的一半），它们与"检索合一"无依赖，排在 019b-3 之后。
