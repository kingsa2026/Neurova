# 007 冲突一等对象化（G03 / G04）

**Blocked by**: 006
**阶段**: E1（§4.2 治理层、§5 段4）

## 目标
同 subject + 同 predicate 的分歧成为可查询、可解释、可自动裁决（带依据）的一等对象，
不再只是"标题像不像"。

## 涉及层
- [ ] 数据层：`knowledge_conflicts`（`kind` 五类 value/qualifier/type/temporal/cardinality、`severity`、
      `recommended_policy`、`policy_basis`、`status` 四态、成员事实集）
- [ ] 逻辑层：`foundation/conflict_judge.py` 的 `KnowledgeConflictJudge`；作用域跨公私域与跨 agent
      （修 `repository.py:1119` 只在同 agent 桶内比对的局限）
- [ ] 三值收口：`contradicts` 分支由本票接管，产出账目而非静默丢弃
- [ ] 策略：`most_recent | highest_confidence | credibility_weighted | keep_both | manual` 起步五种，
      自动关闭必须能读出 `policy_basis`；读不出即 `unevidenced` 留人工
- [ ] 测试：`tests/unit/knowledge/test_conflict_judge_kinds.py`、`test_conflict_policy_basis.py`

## 验收标准
- 用 §1.2 真实数据回填后：`knowledge_conflicts` 不再为 0，且能区分"同值重复"与"真分歧"两类。
- 任何 `status='auto_resolved'` 记录都有非空 `policy_basis`；无依据的必须留在 `pending`。
- temporal 冲突（带不同时间窗口）判为 `temporal` 而非 `value`。
- `repository.py:1132` 的"内容一致即不算冲突"不再影响底座路径（旧路径留待 017 收缩）。

三条关键语义：
1. **依据前置**：`auto_resolved` 若无 `policy_basis` 在**落库处**被拒（不是调用方自觉）；
   无任一成员缺据、又无新近/置信/断言支持差异时，判 `manual` 而不是猜一个赢家。
2. **unevidenced 成员阻断自动裁决**，且依据里点名是哪个成员缺哪一维（ADR 0016）。
3. **跨 agent 成账**：候选按归一化标签跨 agent 取（旧实现 `repository.py:1119` 只在同
   agent 桶内比，这是它账本常年为空的根因之一）。

分类口径实测校准：`temporal` 只需**任一侧**有明确截止且早于另一侧起点（事实随时间更替），
不要求两侧都闭合；限定条件相同不构成豁免，仍报 `qualifier` 分歧。
