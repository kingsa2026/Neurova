# 022 推导账本与精确撤销

**Blocked by**: 021
**阶段**: E4

## 目标
规则修订或前提撤销时，受影响的推导事实能被精确定位并撤销，不牵连原始事实。

## 涉及层
- [x] 数据层：`knowledge_derivation_edges`、`ontology_rule_fires`
- [x] 逻辑层：`ontology/derivation_ledger.py` 的 `DerivationLedger`（按规则版本/前提集撤销）
- [x] 读侧：检索结果区分原始与推导事实，推导项带 `derived_from`
- [x] 测试：`tests/unit/knowledge/ontology/test_derivation_retract.py`

## 验收标准
- 撤销一条前提 ⇒ 仅依赖它的推导事实消失，其余仍在。
- 推导事实永不作为原始事实呈现（读侧可断言）。

### 撞到的根因：推导结论被取值裁决自己裁掉

四层链 `甲→乙→丙→丁` 跑出三条结论，`甲→丙` 却被判成 `superseded`——而 `甲→丁` 的依据恰恰是 `甲→丙`。原因在 `detect()`：同一 (主体, 谓词) 上客体不同即 value 冲突，再按新近自动裁决。对断言这是对的，对推导不是：同一条规则对同一主体给出多条后件实例（传递闭包天生如此），让它们互相取代等于推理自己裁掉自己的前提；而且被顶掉的行是 `superseded`，`reviveRetracted` 明确不管它，闭包再也长不回来。
修法：推导结论（`qualifier.derived_by` 非空）不进取值分组，生退只归推导账本管。

### 登记未做（不在本刀范围，写清免得后来者以为是漏了）

- **推导结论与断言打架**：现在两者不成组（qualifier 键本就不同），规则推出 `X=p` 而人写着 `X=q` 时不会升冲突对象。这需要判定"结论对断言的权威"是哪种（多半只能 pending 交人），属治理决策，未拍板前不做。
- **撤销边记到前提粒度**，不记到证明粒度：一条结论有两条独立证明时，撤一条前提会连带退掉结论（保守侧，重推能长回来）。
- `test_retiringAnUnrelatedFactTouchesNothing` 依赖"前提无推导边 ⇒ 级联 0 条"这一条不变式，账本 docstring 已写明"没有推导边的行是原始事实，任何撤销都不碰它"。
