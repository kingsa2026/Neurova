# 009 置信度由断言聚合（G11）

**Blocked by**: 005, 008
**阶段**: E1（§5 段5）

## 目标
`confidence` 不再是调用方随手传的常量，而由断言聚合得出；§1.2 的"126/130 恒 0.7"成为历史读数。

## 涉及层
- [ ] 数据层：`knowledge_facts.assertion_count`、`contradicted_by_json`、`source_turn_id` 参与聚合
- [ ] 逻辑层：`admit()` 段5 定义聚合式（同值互证计数 + 时间新近 + 矛盾标记）；
      **显式写明它不等于真值度量**，只回答"该来源历史采纳后的结果分布"
- [ ] 收缩：`repository.py` 的 `create_knowledge` 不再接受裸 `confidence` 默认值（雷区：该文件当前干净，可改可提）
- [ ] 测试：`tests/unit/knowledge/test_confidence_aggregation.py`

## 验收标准
- 传裸 confidence 的调用被拒或忽略并告警，且不落库为真值。
- 聚合后 confidence 值种数 > 5（对 §1.2 真实数据重跑），每值可回溯到断言。
- 无任何"无据即高分"路径：缺断言时该维度记 `unevidenced`。


## 完成状态（2026-09-20，10 用例全绿；全量 422 passed，ruff 通过）

落位：`foundation/credibility.py` 的 `ConfidenceAggregator`（定义式随 `definition()` 可读出）；
store 侧 `setConfidence` / `_refreshConfidence` / `markContradicted`；咽喉段5 注入即生效。

定义式（写死在一处，不第二份）：独立来源数基线 1→0.45 / 2→0.60 / 3→0.70 / ≥4→0.80，
异构来源种类 ≥2 加 0.10，有 `source_turn_id` 可回放加 0.05，被标记矛盾扣 0.25，
上下界 [0.05, 0.95]，**无断言则 NULL**。文档明写它不等于真值度量。

实施中定清并修掉的三处真问题：
1. **派生列会腐烂**：`confidence` 现在是派生值，因此断言增删、矛盾标记处必须就地重算
   （`insertAssertion` / `markContradicted` 内触发），否则它会长期停在旧值。
2. **证据态只做单向升级**：`unevidenced → evidenced` 可以由断言到来触发，但人为标记的
   `failed`/`unevidenced` 是判定结论，不能被"后来多了一条断言"抹掉。
3. **裁决阶梯去循环化**（工单 007 的连带修正）：`confidence` 既由断言聚合而来，
   `highest_confidence` 就不能再排在 `credibility_weighted` 之前，否则是拿派生值证明其输入。

**归因修正（原工单写错）**：全库 0.7 并非来自 `create_knowledge` 默认值（那是 0.5），
而是导入路径硬编码 `api/endpoints/knowledge_ingestion.py:208 confidence=0.7`。
设计文档 G11 已按实测改写。条目侧换口径落在工单 019（该处仍是叙述层默认值，属 API 契约面，
不在本票动，避免同批打破 8 个端点文件与 `knowledge.ts` 契约）。

矛盾回写补齐（007 遗留）：`KnowledgeConflictJudge.record()` 现在互写 `contradicted_by`，
否则读侧永远看不见矛盾对。
