## 完成状态（2026-09-20 实施）

**类型系统进了表**：迁移 v8 建 `ontology_terms`（kind / parent / domain / range / cardinality /
disjoint_with / required_props / version），`ontology/term_registry.py` 的 `OntologyTermRegistry`
是唯一读写面，SQL 由该模块持有、由 `foundation_schema` 统一注册（链尾 v8）。
构造时只登记两个由结构层固定的谓词：`documented_as`（019b-1）与 `is_a`（类型断言的固定谓词，
不登记它，"这条主体是什么"就没有共同写法）。

**五条校验接到咽喉段3 前半**（`ontology/validation.py`）：定义域、值域、父子一致性、不相交、
基数 + 必填属性（必填与基数同属"结构上不可能"一类，一起判）。violation 即拒写
（`ValueError: 本体校验未过：…`，报错带术语与主体定位）；被拒的写入**不留半条事实**（校验在
`upsertFact` 之前）。

**两处判定不是随手写的，记下来免得被"顺手简化"**：
- **不相交看 `is_a` 断言集，不看 `type_term_id` 那一列**：单列装不下"同时是 A 与 B"，
  而不相交判定的前提恰恰是同时性。所以 `assertedTypesOf()` = 列上的类型 ∪ 该主体全部
  active `is_a` 事实的客体。
- **父子一致性校验主体类型的祖先链**（悬空父类、链成环），不校验谓词的父类——关系类型按
  `register` 的规则根本不能有父类，拿它当校验对象就是一条永远空转的判据。悬空边只能来自
  存量或手工改库，新登记在 `register` 处就被拒（"父类未登记"）。

**一条刻意的保守：未登记术语免检，不是违规。** 主体没挂类型、客体不是已登记术语 ⇒ 记
`unregistered` 发现，由巡检与 018 的枚举收编消化。把"没登记"当"不合法"，注册表覆盖率一变
写入可用性就跟着抖——那不是治理是抽签。这条本身有判据（`test_unregisteredTermsAreReportedNotRejected`）。

**判据与实测**（`tests/unit/knowledge/ontology/test_ontology_gate.py`，12 例全绿）：
纯数据用例（一个 dict 数组就多出一条能拒绝的校验，**不改任何 .py**）、结构非法在写入处拒且
不留半行、五条规则各自命中与各自不误伤（重放同一说法不算基数违规、单类型不与自身不相交、
客体未登记只记免检）、咽喉端到端拒绝且 `factCount()==0`、
`pendingSegments()` 如实从 `["ontology_adjudication","indexing"]` 收敛到 `["indexing"]`。
