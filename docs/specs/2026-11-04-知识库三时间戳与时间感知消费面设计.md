# 知识库文档三时间戳细分与时间感知消费面设计（2026-11-04）

- **来源**：用户点单——知识库文档时间戳细分（创建/修改/入库）并作为检索精准度、冲突判断、重复度判断的时间感知条件。
- **纪律**：先红后绿 → 最小实现 → A/B → live-verify → 单任务单提交 → 台账落格；契约只增不改（存量 37 条叙述行的既有字段语义不动）。
- **台账**：本文整体登记待落格（随首批实施一并办理）。

## 0. 结论摘要（现状 → 缺口 → 方案）

**现状（本设计前的实态，全部现场核实）**：

1. **三时间戳只有"入库时间"存在**：`KnowledgeItem.created_at/updated_at` 的真语义都是入库/条目更新时刻（`repository.add()` 写 `now`）；文档管线（`document_pipeline._documentMetadata`）其实**已经抽取**源文档的 `created_at/modified_at`（docx core properties、PDF creationDate/modDate），但 `create_knowledge()` 签名不收这两个值——**在摄取边界即丢**。
2. **检索打分零时间信号**：`hybrid.py` 是加权 RRF（BM25＋向量），无 recency/衰减/时间过滤。
3. **冲突裁决无时间感知**：`conflict_judge.decide()` 分类矛盾与 supersede 时不读任何时间字段（仅 valid_until 窗口判定）。
4. **重复度判断无时间维度**：`admission.py` 按内容指纹去重——同一文档**修改后重新导入**：指纹变 ⇒ 当新条目**并存旧版**；指纹没变 ⇒ duplicate 跳过（入库时间不刷新）。

**方案骨架**：

- **契约只增**：`KnowledgeItem` 顶层新增 `source_created_at: str`（源文档创建时间）与 `source_modified_at: str`（源文档修改时间），ISO 串（沿用管线产形）；`created_at/updated_at` 语义不变＝入库/条目更新时间。存量 37 行回填不可考，如实留空。
- **摄取边界接线**：`create_knowledge()` 增两参，`knowledge_ingestion` 把管线 metadata 透传；`/import-url` 网页来源记抓取时刻为两者（诚实：网页无源时间可考）。
- **缺失不猜**（沿用管线"失败一律空值，不猜"的既有哲学）：元数据缺失 → 留空串；**不回退文件 mtime**（mtime 是复制/传输时刻，当作文档创建时间是编造）。
- **前端**：KnowledgePage"创建时间"列改名"入库时间"（真语义），新增"文档修改时间"列（空显 '—'）。

## 1. 消费面分批（拍板后实施）

### 批 TA · 三时间戳契约与摄取接线（先行的地基批）

- `KnowledgeItem`/`item_response`/`create_knowledge`/`repository.add()` 增 `source_created_at/source_modified_at`；
- 叙述库 payload 随 dict 自动携带（零 schema 改动）；
- FTI（`fts_index.py`）索引行随 item 增列（供过滤/排序用）——`updated_at` 列既有，`source_modified_at` 增列＋重建索引导航；
- 前端列改造＋时间列统一走 epoch 单源（已修）；
- 红灯：字段缺失即红的契约测试＋导入端到端断言（PDF 元数据 → 条目字段）。

### 批 TB · 重复度判断的时间感知（同源更新重入库）

- 现状断点：同一文件修改后重导入 ⇒ **新旧两版并存**（指纹不同各立条目），检索会同时命中两代内容；
- 方案：`create_knowledge` 的 dedupe 路径增加"同 `source_path` 判定"——`source_modified_at` **晚于**既有条目 ⇒ 走**更新重入库**（覆盖 content/chunks、刷新 ingested_at＝新 created_at 保留 knowledge_id、旧版本进 revisions 账本）；更早或相同 ⇒ 维持 duplicate 跳过；
- 无 `source_modified_at` 的来源维持现状（不猜）；
- 红灯：同路径重导入并存旧版的现状测试（修前红）→ 更新重入库绿。

### 批 TC · 冲突裁决的时间感知（新者胜读数）

- `conflict_judge.decide()` 的 supersede 分支增加时间读数：members 各自 `source_modified_at`（缺失回退 ingested_at）可全序比较时，**较新者为建议 winner**（decide 的产出是"建议＋证据"，人工审阅面不变——不自动改判，只把"新者胜"从人脑判断变成带读数的建议）；
- 红灯：构造两代矛盾 fact，winner 建议不随时间排序的现状测试（修前红）。

### 批 TD · 检索的时间感知（拍板定形态）

- 形态①（过滤）：搜索面增时间范围参数（`modified_after/modified_before`），FTS 列已就位，query 构造增两_clause；
- 形态②（打分）：RRF 融合后乘 recency 因子（半衰期具名常量、可配、默认温和）；
- 两形态可并存，先①后②。

## 3. 明确不做

- 不回退文件 mtime 当源时间（编造）；
- 不重定义既有 `created_at/updated_at` 语义（存量与消费者面太大）；
- 不做时区归一（管线元数据形状即 PDF/Office 原形，ISO/原串透传——归一是另一个专项）。

## 4. 实施顺序

批 TA（地基）→ 拍板 T-E → 批 TB → 拍板 T-D → 批 TC → 批 TD①（→②可配默认关）。每批独立红绿＋提交＋台账。
