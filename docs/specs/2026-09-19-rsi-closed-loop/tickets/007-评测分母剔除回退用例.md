# 007 · 评测集分母剔除回退用例（measurement_blind 上抛）

**Blocked by**: 003

## 目标

让"评测集无法区分好坏"这件事**被说出来**，而不是表现为一次满分 1.0 与恒定 gain=0。
这是 008 取消虚假收敛、009 打通升级通道的前置。

## 证据（审计实测）

`rsi/eval_harness.py:32-39`：

```python
def _param(live_params, system, name):
    value = (live_params or {}).get(system, {}).get(name)
    if value is None:
        return get_setpoint(system, name), True   # ← 回退 setpoint，满分
    return value, False
```

回退标志虽以 `fallback` 字符串尾巴进了 `detail`（`:69/:97/:108`），但 `:318` 的
`overall = sum(c["score"] for c in cases) / len(cases)` **照常把回退用例计入分子与分母**。
后果：系统未暴露该参数 → 该族用例恒满分。实测四系统里 sleep/emotion/experience 无参数暴露时，
`run()` 返回 `score=1.0`，于是棘轮前后之差恒为 0，`gain` 永远 0。
文件头注释（`:11-19`）自称"评测集是棘轮的行为安全地板，而非参数贴贴度复读机"
—— 现状恰是它声称不是的那个东西。

## 涉及层

- [x] 逻辑层：`rsi/eval_harness.py`、`rsi/orchestrator.py::_measure_performance`
- [x] 测试：`tests/unit/evolution/`（与既有 `eval/test_service_closed_loop.py` 同层）

## 交付内容

1. 每个用例返回三元组，显式携带 `evidenced: bool`（是否全部参数来自实测值）。
2. `run()` 的 `overall` 分母**只计 evidenced 用例**；同时输出
   `{"score": ..., "evidenced_cases": n, "blind_cases": m, "cases": [...]}`。
3. `evidenced_cases == 0` 时不再返回 `score=1.0`：`run()` 置
   `"state": "measurement_blind"`，由 `_measure_performance`（`orchestrator.py:108-132`）
   上抛，使 `run_iteration` 能区分"无差异"与"测不出差异"。
4. 四系统侧的参数暴露缺口**不在本单修**（属 002 事实源与后续实现）；本单只保证
   "缺口暴露为 blind，不暴露为满分"。

## 验收标准

- 用例 A：四系统全不暴露参数 → `run()["state"] == "measurement_blind"`
  且 `score is None`（当前必红：score==1.0）。
- 用例 B：仅 tool_memory 暴露 → `evidenced_cases==3`、`blind_cases==6`，
  score 分母为 3（当前必红：分母恒 9）。
- 用例 C：同参数集下重复 `run()` 两次结果逐字段相等（保持"确定性、零 LLM、毫秒级"契约，`:304-306`）。
- 回归：`run_iteration` 在 blind 态不得抛异常、不得进入 `record_iteration`。

## 净 LOC

预计接近 0（用例签名加一字段、分母换算法）。

## 执行结果（2026-09-19）

### 交付内容落地

1. **9 个用例全部返回 `(score, detail, evidenced)`**；`_sleep_fixture`/`_emotion_fixture`
   也返回 `(对象, evidenced)` —— 参数取不到时不再悄悄用 setpoint 造对象。
2. `run()` 输出 `{score, state, evidenced_cases, blind_cases, cases}`，
   `score` 只对 evidenced 用例取均值。
3. `evidenced_cases == 0` → `score = None` + `state = "measurement_blind"`
   （`STATE_MEASURED` / `STATE_BLIND` 两个模块级常量）。
4. **用例异常 ≠ 度量失明**：坏参数把子系统打崩是"有证据的失分"（`evidenced=True`、score 0），
   与"量不出来"分开 —— 否则参数越坏越容易逃过分母。
5. `orchestrator._measure_performance` 把 `state/evidenced_cases/blind_cases` 写进
   `_last_eval_outcome`，失明时仍返回信号估算值以兼容签名，但 `score=None` 且记 INFO；
   谁消费该结论由 008 决定。

### 一条被本单证伪的前提（重要）

审计原文把"应用了参数但测不出差异"当作恒发场景。007 落地后推得：
候选要求 `current_value is not None`，而"参数被真实系统暴露"正是评测用例 evidenced 的
**同一条件** ⇒ **applied-but-blind 在真实评测集下不可构造**。
真实停机路径因此是：唯一有梯度的参数走到 setpoint → 一串**有证据的零增益** →
`converged` 是合法结论 → 派发层把 `should_continue()==False` 读成"本进程内永不再跑"。
001 基线 B 因此改锁后者（"零证据不得判收敛"移到分析器接缝，见 008）。
失明场景仍可由评测集**自报口径**注入（`tests/unit/evolution/conftest.py::MeasuredHarness`），
那正是 `run_iteration` 读取的契约边界，不是绕过被测逻辑的捷径。

### 连带消费方收口（放大视角）

`harness.run()["score"]` 的另一处读点 `evolution/eval/bench_gate.py:82` 在 score 可空后
`float(None)` 直接崩（6 条用例红）。同批修：`_readout()` 读数可为 None，
失明时返回 `NEUTRAL_GAIN` 并打 WARNING —— 返回 0.0 与"测得 0 增益"数值相同，
不留痕迹就等于这道门在失明时与咬合时对外长得一模一样。
