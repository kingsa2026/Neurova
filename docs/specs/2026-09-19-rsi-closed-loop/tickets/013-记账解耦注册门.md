# 013 · 技能使用记账解耦 tool_memory 注册门

**Blocked by**: 001

## 目标

`tool_memory` 初始化失败时，技能使用记账与进化数据采集**照常进行**。
这是臂三的第一性断点：采集端整链静默关停，导致改进提案永不为零的唯一原因就是没有输入。

## 证据（本单已逐行核实）

`agent_core.py:1581-1587`：

```python
# 注册 ToolMemory 回调：Skill 成功执行后记录到 ToolMemory
if self.tool_memory and self._skill_registry:
    self._skill_registry.register_event_callback(
        SkillEvent.POST_EXECUTE, self._on_skill_post_execute,
    )
```

- `a.tool_memory` 在 `:590` 先置 None，仅 `ToolMemoryIntegration(...)` 构造成功（`:600`）才赋值；
  构造在 try/except 内，失败只 `logger.warning("ToolMemory 初始化失败")`（`:613`）。
- 但 `_on_skill_post_execute`（`:1624`）里的四条记账**与 tool_memory 无关**：
  `skill_improver.record_usage`（`:1640`）、`SkillService.record_skill_usage`（`:1653`）、
  `skill_experience.record_usage`（`:1661`）、`genetic_engine.record_reuse`（`:1687`）；
  真正需要 tool_memory 的只有最后一段（`:1692` 起，且该处**已有** `if not self.tool_memory: return`）。
- 一颗 AND 门把四件无关记账绑在第五件的可用性上。

**注意（更正先前审计表述）**：发射端是好的。
`skill_system.py:637/643/648` 确实调用 `SkillRegistry._emit_event`，
且生产执行路径确实走 `execute_skill`（`tool_executor.py:966`、`router.py:268`、
`agent/loops/base.py:253`、`agent_core.py:950`）。
零调用的是 `Skill._emit_event`（`skill_system.py:115`，实例级 handler 面），
`SkillRegistry._emit_event:771-775` 仍在遍历 `self._event_handlers` —— 该面本单一并判定去留。
断的是**注册**，不是发射。

## 交付内容

1. 注册门收严到真实前置：`if self._skill_registry:`（回调内部各段自行判空，其中 tool_memory 段已有守卫）。
2. 注册失败/未注册时 `logger.warning` 明示"进化采集未启用"，不得只有 debug 级。
3. 判定 `Skill._emit_event`（`:115`）与 `Skill._event_handlers` 的去留：
   若无真实消费方则删除（连同 `add_event_handler`），不许留第二套事件面。
   该判定结果写进本 PR 描述，并在 017 登记删除项。
4. 同源但互不相通的第二条链（`tool_executor.py:978 record_turn_skill_funnel` →
   `post_chat_pipeline.py:1703 → :1727 service.record_skill_funnel`）：
   本单**不合并**，但必须登记为已知重复采集（spec §6 范围外），避免下一轮审计重复提。

## 执行结果（2026-09-19 本单落地记录）

**修法与原计划的偏差（两处，均有理由）**

1. **抽出成模块不是为了"能测"，是为了过尺寸棘轮。**
   实测真 Agent（`Agent(workspace_path=..., enable_memory=False)` + `init_router()`）
   就能直接驱动这颗门，原以为需要的"抽函数以便测试"并不必要。
   但 `tests/unit/agent/test_agent_core_size_ratchet.py` 把 `agent_core.py` 锁在
   **2159 行基线、净增即红**（history 单调不升，防"改基线不改代码"）——
   在 `agent_core.py` 里写根因注释会直接撞线（实测 +18 行被拦）。
   故最终形态：装配体落到 `neurova/evolution/skill_recording.py::wire_skill_evolution_recording(agent)`，
   `agent_core.py:1585-1587` 只留 3 行调用，**净 −3 行**（2156），棘轮转绿。
   模块内用局部 import（`neurova.evolution.__init__` 会拉起 closed_loop 全家，
   顶层 import 触 `docs/evolution_init_order_fix.md` 记的初始化顺序雷）。
2. **交付项 1 的"注册门收严"改为"注册门前置只剩注册表"**，语义一致，
   并把根因解释写进新模块文档串（棘轮只盯生产文件 `agent_core.py`，与它无关）。

**撞出的并发冲突（需人工裁决，本单未擅自处置）**
`neurova/agent/skill_evolution_wiring.py::register_skill_evolution_callbacks`
是另一方独立写出的**同一工单**实现，根因诊断与本单一致，但：
- 全仓 grep **零引用**（未接线，死码）；
- 用的是 `neurova.skills.events.SkillEvent`，与本单走的 `neurova.skill_system.SkillEvent` 不同源。
本单实现在 `agent_core.py` 里只有唯一一处接线（`:1585-1587`），**无重复注册**。
→ 待办：二者择一保留。删他人未接线文件需先征询，本单不动。

**撞出的同名双类（登记给 014/017）**
`SkillResult` 有两套不兼容定义：`neurova.skill_system` 包导出
`skills/executor.SkillResult(success, output, error, metadata)`，
而 `Skill`/`SkillRegistry` 来自 standalone 模块，其
`SkillResult(success, data, error, metadata, execution_time)` 字段不同。
ADR 0011 统一了 SkillRegistry，**没统一 SkillResult**。
写探针技能时踩到（`data=` 参数不存在）。

**被揭露的测试替身缺陷**
`tests/unit/evolution/test_skill_creation_governance.py:160-164` 的 SimpleNamespace 假 Agent
缺 `_on_skill_post_execute` —— 它此前从未走过注册分支（`tool_memory=None` 直接短路），
门一收严即 `AttributeError`。补的是**替身的接口完备性**，
该用例的断言（待审模板恢复）未做任何放宽。
