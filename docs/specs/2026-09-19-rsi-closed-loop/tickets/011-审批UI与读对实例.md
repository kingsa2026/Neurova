## 目标

管理员在前端**看得见**全部提案（含已审）、点的批准作用在**正确那个 agent** 上。
完成后臂二才算端到端可演示：打开页面 → 看到待审 → 批准 → 页面显示 APPLIED → 下一轮对话生效。

## 证据（审计实测）

- 实例串写：`RSIOrchestrator` 按 agent 构造（`agent_core.py:1536`），
  再写入**全局单例**属性（`agent_core.py:854-855`），后构造者覆盖；
  `api/endpoints/governance.py:245` 只读 `getattr(get_evolution_orchestrator(), "rsi_orchestrator", None)`
  → 恒命中"最后构造的 agent"，与同文件 `_get_agent()`（`:50-60`，默认 agent）指向不同对象。
  本机 `data/agents/` 实有 default/kai/216fb777 三套，且 `agent.py:442`、`agent_package.py:413` 运行时还会再覆盖。
- 无闭环系统时 `rsi` 为 None，pending 端点仍返回 200 + `available:false` 静默（`:264-265`）。
- 状态不可见：唯一列表 `list_pending_proposals`（`:596-605`）只出 PENDING，已审项永久消失。
- 前端零消费：`NeurUI/src/api/governance.ts:46-99` 只封装 whitelist/approvals，
  **无** `rsi/proposals`；`NeurUI/src/` 全目录中除 `rsi_phase`（`SettingPage.vue:283-290`）外
  零 `rsi` 命中；`router/index.ts` 无相关路由。
  （`AgentSkillPage.vue:690-719` 的"待审提案"走另一通道 `/evolution/skills/{id}/proposals`，
  与 RSI 提案无关，勿混用。）
