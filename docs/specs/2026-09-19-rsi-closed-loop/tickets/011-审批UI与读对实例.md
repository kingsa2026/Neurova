## 目标

管理员在前端**看得见**全部提案（含已审）、点的批准作用在**正确那个 agent** 上。
完成后臂二才算端到端可演示：打开页面 → 看到待审 → 批准 → 页面显示 APPLIED → 下一轮对话生效。

## 执行结果（2026-09-21 凌晨）

### 后端：三个 RSI 端点改为按 agent 定位

`_get_rsi_orchestrator(agent_id=None)` 不再读进程级单例属性，改走与 `_get_agent()`
同源的 `get_app_state().get_agent(agent_id)`：

- 指名 agent 而它不在池中 ⇒ 返回 None ⇒ **503 + 带 agent 名的原因**，**不回落**默认 agent。
  回落到"随便某个 agent 的编排器"就是本单要拆的缺陷本身，不能当兜底留着。
- `pending` 端点取消 `available:false` 的静默 200（`test_rsi_approval_endpoints.py`
  里那条原契约用例改写到 503，改写理由写在 docstring）。
- 新增 `GET /rsi/proposals?state=all|pending|applied|rejected|rolled_back`
  （读工单 010 的 `list_all_proposals()`；非法 state 由 FastAPI 挡成 422）。
- `approve` / `reject` / `status` 共用同一定位器与同一个 503 口径。
- 反向锁：AST 扫 `governance.py`，可执行代码里再出现 `get_evolution_orchestrator` 即红
  （docstring 引用被拆掉的历史实现是正当的，所以扫 AST 而不是扫文本）。

新文件 `tests/unit/api/test_rsi_agent_scoped_endpoints.py`（233 行，7 条先红后绿：
`agent_id` 被无视、未装配回 200、全状态端点 404）。红因原文都是 404/200 而非 import 错误。

### 前端：`NeurUI/src/pages/RsiGovernancePage.vue` + `api/modules/rsiGovernance.ts`

路由 `rsi-governance`（name `RsiGovernance`）。页面三块：agent 选择与状态筛选、
状态读数（阶段只读 + 晋升判据三态 + **落盘两态** + 棘轮门通过率 + 升级通道结论）、
提案队列（全状态、批准/驳回、批准人可补交 `tool_sequence`、批准后就地回显生效证据）。

- `rsi_phase` 只读，写仍留在 `SettingPage` 的治理卡片 —— 票面明令不做第二处编辑入口。
- 503 时页面显示后端原因且不渲染"空队列"冒充正常（与工单 012 的 `not_ready` 口径一致）。
- `registry_hit=false` 时行内显示"回灌未命中，下一轮仍看不见"，不显示成功。
- 响应拆包沿用仓库既有口径（`api` 拦截器返回 body，而声明是 `ApiResponse<T>`，
  既有页面一律 `?.data?.data ?? ?.data`）；这里封成 `unwrap<T>()` 一处，不再散着写 as any。
- i18n：`rsiGovernance` 段 35 个键注入全部 **11** 份语言包（票面写"两份"，但项目有
  `locale-consistency.test.ts` 要求键集与 zh-CN 完全一致且不留空值）。
  **ru/ja/fr/de/es/it/ko/hi/ar 九份当前用英文文案**，待翻译 —— 键在、非空、值未本地化。
