## 待裁决（人工介入）

1. **并发重复实现**：`neurova/agent/skill_evolution_wiring.py::register_skill_evolution_callbacks`
   是另一方独立写出的工单 013 实现，根因诊断一致但**全仓零引用**（未接线），
   且走 `neurova.skills.events.SkillEvent`（与本单 `neurova.skill_system.SkillEvent` 不同源）。
   现网接线只有一处（`agent_core.py:1585-1587`），**无重复注册**。需决定二者取一。
2. **同名双 `SkillResult`**：`neurova.skill_system` 包导出 `skills/executor.SkillResult
   (success, output, error, metadata)`，standalone 模块的是
   `SkillResult(success, data, error, metadata, execution_time)`。
   ADR 0011 统一了 SkillRegistry 却没统一 SkillResult。登记给 014/017。
3. **预存红（本批结清后仍是这 16 条）**：`tests/unit/core/test_agent_skill_packer_init.py::test_has_correct_param_name`
   （断言 `min_pattern_occurrences=` 存在，HEAD 版本里也不存在）；
   `tests/unit/api/` 下 15 条属并发进行中的 wave h3/h4/v（`KeyError 'data'`、`404 != 409`）
   与 Windows SQLite 文件锁。复跑 `tests/unit/{evolution,api,agent,core}`：
   008 落地后 **5839 passed / 16 failed**，018 第 4 项后 **5846 passed / 16 failed**
   （+7 即本单新增用例），失败集合逐条不变，无一引用本批改动的模块。
4. **CI 清单里的预存超时**（2026-09-19 已修，见下）：`tests/unit/test_deploy_config_guard.py`
   的 12 条负向控制原先用**排除清单** `shutil.copytree` 整棵树（只列了
   .git/node_modules/models/dist/… 九个已知大目录）。工作树后来长出
   `NeurUI/src-tauri`（14.5 万文件）、`.venv`（5.6 万）、`data`（2.4 万）之后，
   单份副本实测 **216,335 个文件** → 撞穿 `pyproject.toml` 的全局 `timeout = 30`，
   单独跑与该清单合跑都被 pytest-timeout 强杀并中断整轮。
   **根因是复制范围用排除式表达**：它把耗时绑在"开发机碰巧有什么"上，永远追不上树的增长。
   修法：改为按门禁输入面的**正向清单**复制（`_gate_input_paths`，实测 1,586 个文件 / 0.61s），
   并加两条锁 —— 完整性锁（未改动的最小副本上门禁必须全绿，漏登记输入即红）
   与范围锁（清单 < 4000 项且禁含 `.venv`/`data`/`logs`/`tests`/`NeurUI/src-tauri` 等）。
   负向控制类另给 `timeout(180)`：每例固有成本是一次门禁子进程全量扫描（本机实测 8.3-8.5s）。
   复跑：本文件 27 passed / 103s；整份 `protected_tests.txt` 822 passed / 1 skipped / 135s 不再中断。

## 通用纪律（每张工单适用）

1. **红绿灯先行**：先写断言缺陷的失败测试，红→绿→重构，测试落 `tests/unit/evolution/rsi/`、
   `tests/integration/evolution/`、`tests/e2e/`，不得放 `tests/` 根目录。
2. **禁止 consumer-only guard**：不得在调用方/展示层加判空、吞异常、兜底默认来消除报错。
3. **放大视角**：每张工单点名的契约错位，须 grep 同契约全部消费方一并修或在本单内登记。
4. **提交说明须含**：live 验证输出原文 + 净 LOC 数（004-016 允许为正，017 必须为负）。
5. **CI 清单登记时机**：含刻意红灯的测试文件**不得**进 `scripts/ci/protected_tests.txt`
   （该清单原则"只进当前确定全绿的测试"）。每张工单的最后一条验收即"本单转绿后把对应
   文件登记进清单"：`test_parameter_source_of_truth.py` 在工单 018、
   `test_rsi_loop_baseline.py` 在工单 004 + 008（两条基线分别由它们转绿）。
   **008 落地后已登记 8 个文件**（逐文件单跑全绿后再登记，避免"合跑绿、单跑红"的顺序耦合）：
   `tests/unit/evolution/rsi/` 7 个 + `tests/unit/agent/test_rsi_dispatch_cadence.py`。
