# 018 · 缺席闭环系统的替身不得被当作进化对象

**Blocked by**: 003

## 目标

闭环系统缺席时，RSI 必须**明确拒绝**优化并报告"无对象可进化"，
而不是对着一个空对象回执"6 个参数应用成功、增益 +0.111"。

## 发现经过

本缺陷在工单 002 写一致性守卫时撞出，比原审计认定的"镜像表零消费方"严重一档。

`agent_core.py:1537-1540` 在真实闭环系统缺席时用替身顶位：

```python
self.rsi_orchestrator = RSIOrchestrator(
    sleep_system=sleep_system or _NullSystem(),
    emotion_system=emotion_system or _NullSystem(),
    experience_system=experience_system or _NullSystem(),
    tool_memory_system=tool_memory_system or _NullSystem(),
)
```

于是 `_NullSystem` 的类属性镜像表（`:381-392`）成为 RSI 眼中的"真实参数面"。
**实测**（四系统全为替身、phase=2、单轮迭代）：

```
applied_count = 6 | gain = +0.11111099999999996
applied_results = sleep.similarity_threshold 0.8→0.78 applied=True
                  emotion.emotional_protection_factor      applied=True
                  experience.crystallize_min_success_rate  applied=True
                  tool_memory.failure_penalty / decay_rate / muscle_memory_threshold  applied=True
```

没有任何真实子系统被改动。更糟的是**增益为正**：`_measure_performance`
（`rsi/orchestrator.py:118-127`）经 `get_optimizable_parameters()` 回读参数，
读到的恰是刚写进替身对象的那个值，`eval_harness._param():32-39` 于是判"参数更接近 setpoint"
→ 分数上升 → `gain>0` → **棘轮奖励自己编辑了一个空对象**，且因增益为正永不回滚。
`_NullSystem.get_feedback()`（`:394-396`）恒返回 `performance_score=0.5`，
所以这条假链路还能长期自持。

若 `NEUROVA_RSI_RECEIPTS` 开启，`integration_manager._write_optimization_receipt`
会把这些虚构的 old/new 值落成审计回执（`:227-249`）—— 审计面主动撒谎。

## 交付内容

1. 给替身一个**可判定身份**：`_NullSystem` 实现 `rsi_placeholder = True` 类属性
   （或更稳的 `is_placeholder()` 协议），不再靠 `get_status()` 返回 `"null_fallback"` 字符串识别。
2. `RSIIntegrationManager.get_optimizable_parameters()` 对占位系统返回空参数列表
   —— 从"看不见"这一步就断掉候选生成，比在 `apply_optimization` 里拒绝更靠根因
   （`orchestrator.py:444` 的 `current_value is None` 分支已会跳过候选）。
3. `apply_optimization` 仍保留占位拒绝（`:172-225`），作为第二道防线，
   且拒绝时返回 `False` 并写明 reason，**不得**回执 True。
4. `collect_feedback_signals` 对占位系统标注 `unevidenced`（接 003 的 `GateVerdict`），
   使"四系统里有几个是替身"进到 `run_iteration` 返回值与摘要面。
5. 装配侧：`agent_core.py` 用 `None` 而非 `_NullSystem` 传入缺席系统
   （或保留替身但明确它只服务 `get_feedback` 中性信号、不服务参数面）——
   择一后写进本 PR 描述。

### 为什么把兜底均值也算本单的命中点

审计记的 `gain=+0.111` 来自"回读刚写进替身对象的值"。018 前半段断了参数面，
但 `_measure_performance_from_signals` 仍在**对四个系统各估一次贴近度取均值** ——
替身那份依旧是拿它自己的镜像默认值算的。只修 `collect_feedback_signals` 会留下
"评测集缺席时又给不存在的系统算出个分"的第二个入口，属同一根因，故一并收。

人工升级通道同理：它今天没咬到替身，只因为 `_NullSystem` 恰好自报 0.5（门槛是 `< 0.5`）
—— 那是运气不是契约。
