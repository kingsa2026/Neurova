# 008 · 三态收敛判据 + 降频巡检取代永久自停

**Blocked by**: 007

## 目标

消除"跑满 20 轮 RSI 就永久自杀"，并让"什么都没做"不再被读成"已收敛"。
这是臂一对用户可见度最大的一张：修完后进化才是长期过程，而不是一次 20 轮的烟花。

## 证据（审计实测）

- 喂数门：`orchestrator.py:237-239`
  `if applied_count > 0 or gain != 0.0: record_iteration(gain=gain, cost=1.0)`。
  注释声称修掉"什么都没做却被判定收敛"，但只挡了 `applied_count==0`；
  **应用了、却因度量失明测不出差异**时照样喂 0。
- 判据：`convergence_analyzer.py:110` `abs(mean_gain) < 0.01 and abs(trend_slope) < 0.001` → `converged`。
  一串 0 天然满足。窗口 `window_size=20`（`:26`）→ 第 20 轮即判 converged。
- 停止：`orchestrator.should_continue():724-725` `if status == "converged": return False`。
- 落地：`post_chat_pipeline.py:2729` `if rsi.should_continue():` 否则走 SKIPPED ——
  **此后本进程内再不迭代**（`gain_history` 纯内存，只有重启复位）。
- 实测：`should_continue()` 首次 False 出现在第 **20** 轮；80 轮内 status 集合仅
  `{insufficient_data, converged}`。
- 这正是 `tests/unit/evolution/test_rsi_ratchet_effectiveness.py` 文档写的"根因 2 零活动虚假收敛"回潮。

## 交付内容

1. 状态集扩为 `{converged, converging, oscillating, diverging, insufficient_data, measurement_blind}`；
   `converged` 的成立**额外要求**本轮窗口内 `evidenced_cases > 0`（来自 007）。
2. 喂数门收紧：仅在"本轮确有可测增益证据"时 `record_iteration`；
   blind 轮次改记 `blind_streak`，不进 gain_history。
3. `should_continue()` 三态化：
   - `converged`（有证据）→ 转**降频巡检**而非停止；
   - `measurement_blind` / `insufficient_data` → 继续，但同样降频（避免每轮空烧 `to_thread`）；
   - 其余 → 全频。
4. 降频落点在 `post_chat_pipeline.py:2729-2780`：由二分支（跑/跳）改为"跑 / 降频跑 / 跳"，
   SKIPPED 分支的 message 必须写明**是哪一个判据、依据什么证据**（不得再写 `rsi_orchestrator not available`
   之外的模糊措辞）。
5. 摘要面（`result_summary.py`，`chat_pipeline.py:2557` 与 `negative_screen.py:348` 两个消费方）
   补 `state` 与 `evidenced_cases`，使"停滞原因"进响应面。

## 执行结果（2026-09-19）

### 交付内容落地

1. **六态成词表**：`convergence_analyzer.py` 新增 `CONVERGENCE_STATES` 与 `STATE_*` 常量，
   分析器只发这六种结论；判据侧与响应面按同一张表分派。
2. **喂数门收紧**（`orchestrator.py` 步骤 5）：门从 `applied_count > 0 or gain != 0.0`
   换成 `attempted`，并以 `evidenced=gain_evidenced` 传入。
   **与工单原文的偏离**：原文写"blind 轮次改记 `blind_streak`，不进 gain_history"。
   实测两条出路里"什么都不记"更糟——窗口空 → 分析器报 `insufficient_data`（"再等等"），
   而真症结是"再多样本也量不出来，该去修测量"。故改为
   **`record_iteration(evidenced=False)` 记成本与失明痕迹、不记增益**：
   `gain_history` 保持纯净（每条都是一次真测量，`test_unevidenced_record_fills_cost_but_not_gain_history` 锁住），
   `cost_history` 收下这次真实烧掉的评测成本，`measurement_blind` 抢在样本量门槛之前判。
3. **`should_continue()` 语义不变（走本单预告的出路 B）**，派发层改读
   `iteration_cadence() -> IterationCadence(mode, basis, evidence)`：
   `converged` / `measurement_blind` → `backoff`，其余 → `run`。
   三档里"降频跑/跳"由 `post_chat_pipeline._RSI_BACKOFF_EVERY_TURNS = 20` 决定，
   SKIPPED 措辞与 `data` 带出 `basis`/`evidence`/`turn`/`backoff_every`。
   `IterationCadence` 之所以不是裸字符串：本单第 4 条要求"说得出是哪个判据、依据什么证据"，
   字符串只到 `backoff` 就断了。
4. **必需性按阶段声明**（`deployment_controller._REQUIRED_EVIDENCE`）：
   0→1 不要求；1→2 只要求"无回滚天数"；2→3 起 `roi` 与 `convergence_status` 转为必需
   —— 按"走到这一步之前该读数有没有可能存在"填表，拆掉循环依赖而不放低门槛。
   **硬否决与必需性分离**，并把收敛判据从黑名单换成白名单
   （`_PROMOTABLE_CONVERGENCE`）：`oscillating` 此前是"没被列举为否决 ⇒ 可晋升"，
   与 003 要消灭的兜底同病，现判 `failed`。
5. **摘要两字段**：`RSI_SUMMARY_FIELDS` 扩为六项，新增 `measure_state`
   （`measured` / `measurement_blind` / `not_attempted` / `unknown`）与 `evidenced_cases`；
   推送面（`negative_screen.push_rsi_result`）加"度量证据"一行，
   并删掉它自带的那份字段默认值清单（第二套字段解释）。
   **命名裁决**：工单原文叫 `state`，与本模块已有的 `status`（收敛六态）撞名——
   验收"取值落在六态集合内"由 `status` + `CONVERGENCE_STATES` 满足，
   度量侧新字段定名 `measure_state`，不再造同义词。
