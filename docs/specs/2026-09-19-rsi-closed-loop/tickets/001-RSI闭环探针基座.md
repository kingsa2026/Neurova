# 001 · RSI 闭环探针基座

**Blocked by**: 无

## 目标

建一套"不碰私有字段就能驱动并断言 RSI 全流程"的测试基座，并落两条**当前必红**的基线用例，
使 004-016 的验收有可信靶心。

## 为什么它是第一张

现有测试用两种写法把缺陷洗成绿色，不先收口则后续每张工单的"绿"都不作数：

- `tests/unit/evolution/test_rsi_ratchet_effectiveness.py:51` 直接
  `orch.deployment_controller._current_phase = initial_phase`，绕过了正要修的晋升判据。
- `tests/unit/skills/test_improvement_persistence.py:47-52` 的 `_FakeRegistry` 令 `id == name`，
  掩盖了 `skill_system.py:505`（键=name）与 `skill_contract.py:88-92`（身份=skill_id）的双键域缺陷。

## 涉及层

- [x] 逻辑层：新增 `tests/unit/evolution/rsi/conftest.py` 探针工厂
- [x] 测试：两条基线用例（红）
- [x] 数据层：无（探针不落盘，全走 tmp_path）

## 交付内容

1. `rsi_probe` fixture 工厂：
   - 入参 `governance_settings` dict → 写 tmp 文件并经 `NEUROVA_GOVERNANCE_SETTINGS` 生效
     （`neurova/security/governance_settings.py:28` 已支持该 env 覆盖），phase **只能**从这条路径进来。
   - 四系统真值桩：`sleep` / `experience` 用真实 `SleepConsolidation()` / `ExperienceFeedback()`
     （实测其默认即 setpoint，零候选，用于验证 `unevidenced` 分支）；
     `tool_memory` 用真实 `ToolMemoryIntegration` 参数面但注入内存桩，`muscle_memory_threshold=0.85`
     以复现"当前唯一真实梯度"（`agent_core.py:234`）。
   - 提供 `run(n)` 返回 `n` 次 `run_iteration()` 结果列表与终态 phase。
2. `fake_skill` fixture：`skill_id != name`，供 013/014 复用。
3. 迁移 `test_rsi_ratchet_effectiveness.py` 的私赋点到工厂（本单内完成，不留第二套写法）。
4. 基线用例 A `test_sixty_iterations_no_deadlock`：默认 `rsi_phase=0`，跑 60 轮，
   断言 `phase > 1 or applied_total > 0`。当前必红（实测 phase 停 1、applied 累计 0）。
5. 基线用例 B `test_should_not_arrest_at_twenty`：`rsi_phase=2`，跑 25 轮，
   断言 `should_continue()` 全程 True 或转入降频而非永久 False。当前必红（实测第 20 轮翻 False）。

## 验收标准

- 全仓 grep 无 `deployment_controller._current_phase =` 出现在测试中。
  **范围澄清（实现期确定）**：只收口 RSI 部署阶段这一处；
  `tests/unit/core/test_auto_sleep_settings_path.py` 等 5 个文件命中的是睡眠周期 phase，
  与被测对象无关，不在本单范围。
- `pytest tests/unit/evolution/rsi/ -v` 结果：fixture 收集成功、A 与 B **恰好 2 红**、其余绿。
  红的必须是 A/B 本身而非装配错误（贴 `pytest -rA` 原文）。
- 探针工厂文件头写明禁令注释：新增 RSI 测试不得直接赋私有阶段字段。
- `fake_skill` 不得是"没人断言的死 fixture"：须有一条自证用例证明它真的 `id != name`
  且 `resolve_skill_identity` 取的是 skill_id（实现期补入，见下）。
