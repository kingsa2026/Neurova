# 006 · ROI 判据真值化

**Blocked by**: 003

## 目标

让阶段晋升的 ROI 守卫**真的在看数**，或把它删干净。现状是幻影：读了个永不存在的键，
兜底成 0，于是守卫永不触发。

## 证据（审计实测）

- 读点：`orchestrator.py:261-264`
  `float((convergence.get("metrics") or {}).get("roi", 0.0) or 0.0)`
- 写点：**无**。`convergence_analyzer.analyze_convergence()` 返回的 metrics 实测键集合恰为
  `['mean_gain','std_dev','trend_slope']`（`convergence_analyzer.py:131-135`）。
- 消费点：`deployment_controller.evaluate_phase_transition:100-103` 的 `if roi < 0` —— 0 不小于 0，
  故这条守卫**在有负 ROI 时也照样放行**。
- 讽刺的是算法早已写好：`convergence_analyzer.compute_roi():138-151` 生产**零调用方**。

实测佐证：40 轮迭代、累计 160 次参数应用后，`metrics keys` 里仍无 `roi`。

## 涉及层

- [x] 逻辑层：`rsi/convergence_analyzer.py`、`rsi/deployment_controller.py`
- [x] 测试：`tests/unit/evolution/rsi/`

## 交付内容（主路径 = 补真值）

1. `analyze_convergence()` 的 `metrics` 增 `"roi": self.compute_roi()`，
   使 `compute_roi()` 从死方法变为唯一供值点。
2. `roi` 缺失（历史为空）时按 `GateVerdict(unevidenced)` 语义处理：
   `deployment_controller` 不得把"无 ROI 证据"当作"ROI 非负"放行 ——
   在返回的 verdict 里带 `reason="roi unevidenced"`，且该理由在 012 的观测面可见。
3. 若论证后判定 ROI 概念对 RSI 无意义（成本恒为 `orchestrator.py:238` 的固定 `cost=1.0`，
   实为"平均增益"复读），则**整条 roi 守卫连同 `compute_roi()` 一并删除**，
   并在 ADR 0016 或新 ADR 里写明删除理由。
   **不接受的第三态**：保留读点、保留兜底、守卫继续空转。

### 撞出的更重事实：`roi < 0` 按构造不可达

原计划"补个供值"就能让守卫生效 —— **不成立**。`run_iteration` 的 gain<0 分支把
`applied_count` 与 `gain` **双双归零之后**，才由 `:237-239` 的
`if applied_count > 0 or gain != 0.0` 决定要不要喂收敛历史。
于是有害调整的负增益永不进入 `gain_history` → `total_gain >= 0` 恒成立 →
`compute_roi()` 非负 → **`roi < 0` 这条晋升守卫在棘轮正常工作的前提下不可达**。

这不是"再补一次供值"能修的，它取决于"该往收敛历史里喂什么"，而那归工单 008。
所以本单**只锁事实不假装修好**：
`test_harmful_adjustment_never_reaches_negative_roi_under_current_feeding`
断言当前不可达性，断言消息里写明 —— 一旦 008 改喂数策略使负增益可进历史，
该用例即红，提示改判为"roi<0 可达"并撤销本单留下的不可达说明。

留给 008 裁决的两个方向（本单不越权）：
- 把有害尝试的实测负增益记进历史（roi 可负，但改变收敛状态语义）；
- 或承认棘轮已消化危害，把守卫改成"roi 长期为 0（只烧成本不产出）即不晋升"。

### 一处实现期时序自纠

初版在**第 2 步**（分析收敛）读 roi，但增益要到第 5 步才 `record_iteration`
→ 首轮永远读空，指标与守卫同时拿不到值
（`test_dashboard_roi_metric_is_recorded_so_alerts_can_fire` 实测到 0 而非 0.3）。
改为在喂数之后取读数，守卫与指标共用同一时刻同一值。
连带把 `test_negative_roi_rejects_promotion_through_the_real_read`
从"patch `analyze_convergence` 返回假 roi"改成"喂真实 `gain_history`" —— 路径更真、断言更硬。
