# 014 · 技能身份键统一（宽重构 · 扩展-收缩）

**Blocked by**: 013

## 目标

注册表的**字典键域**与进化侧的**身份域**成为同一个值，
使 `apply_improvement` / `rebuild_skill` / `set_skill_enabled` 在 `id != name` 时真的命中。

本单是**宽重构**（爆炸半径横跨 8 个取键点 + 全部建键点），
按 to-tickets 的宽重构例外走"扩展 → 迁移 → 收缩"，不伪装成垂直切片。

## 证据（本单已逐行核实）

- 建键：`skill_system.py:505` `self._skills[skill.name] = skill` —— 键 = **name**
- 查键：`:595`、`:605`、`:610`、`:632`、`:778` —— 全按 `skill_name`
- 身份解析：`skills/skill_contract.py:88-92` 次序 **skill_id → id → name → fallback**
- 注册边界写入的恰是 `skill_id`：`skill_contract.py:108 setattr(skill,"skill_id",…)`（永不覆写）、
  `skill_system.py:504 canonicalize_skill_identity`、`_carry_manifest_identity :580-585`
- 按 identity 取技能的 8 处：`agent_core.py:1370`、`skill_experience.py:195/280/358`、
  `skill_improver.py:523/664`、`post_chat_pipeline.py:2513`、`collaborate/workflow/scheduler.py:396`
- 实测：`register_skill(id='skill_ab12…', name='read_write_skill_…')` 后
  `get_skill(identity)` 返回 **None** → 上述 8 处取键全灭。
- 与 ADR 0011 的关系：0011 已判 `skill_system.py` 的 SkillRegistry 为唯一实现（类 A），
  本单不推翻它，只补它没管的那一层 —— **键值域**。结论落 **ADR 0017**。

## 涉及层

- [x] 逻辑层：`skill_system.py`、`skills/skill_contract.py` + 8 个取键点
- [x] 文档层：ADR 0017（选哪个键为准、被否方案、迁移期契约）
- [x] 测试：`tests/unit/skills/`、`tests/unit/evolution/`

## 阶段一 · 扩展（不破坏任何东西）

1. `SkillRegistry` 内新增别名索引 `_alias_index: Dict[str, Skill]`，
   同时以 `skill.name` 与 `resolve_skill_identity(skill)` 为键指向同一对象；
   主字典 `self._skills` 暂不变（现有按 name 的行为零变化）。
2. `get_skill()` 查找次序：主字典 → 别名索引；返回对象同一。
3. 新增用例：`id != name` 时两种键都能取到（此刻即绿，作为迁移期安全网）。

## 阶段二 · 迁移（每批一个提交，全程保持绿）

| 批次 | 迁移点 | 数量 |
|---|---|---|
| M1 | `skill_improver.py:523/664`（改进回写） | 2 |
| M2 | `skill_experience.py:195/280/358`（经验生效/重建/禁用） | 3 |
| M3 | `agent_core.py:1370`、`post_chat_pipeline.py:2513`、`scheduler.py:396` | 3 |

每批验收：该批 3 处调用点在 `id != name` 用例下返回 True / 非 None（当前恒 False / None）。

## 阶段三 · 收缩

1. 主字典键改为 identity（`skill.name` 不再是键域），删 `_alias_index`（已无必要）。
2. 全仓 grep `self._skills[` 与 `_skills.get(`，逐个确认已走 identity。
3. `SkillRegistry.execute_skill(name, ...)` 的对外入参语义在 ADR 0017 里钉死：
   **接受任一历史形态，内部单次归一**，不在各调用方重复 resolve（避免第 9 处 resolve）。

## 验收标准

- 红绿灯终点用例（001 的 `fake_skill`，`id != name`）：
  `apply_improvement(proposal, registry)` 返回 True。**当前必红。**
- 同一用例覆盖 `rebuild_skill` / `set_skill_enabled` / `_apply_to_skill` 三处非 False。
- 反掩盖断言：`_FakeRegistry`（`tests/unit/skills/test_improvement_persistence.py:47-52`）
  改为 `id != name`；若改后某用例转为红，说明它此前靠假注册表洗绿，**必须修到绿**
  （不许放宽断言或跳过）。
- `docs/adr/0017-*.md` 存在，含"被否决方案"段（至少交代：让 name 成为唯一身份
  —— 会被否，因为 manifest 侧身份是 skill_id 且 0011 已定 `canonicalize_skill_identity` 永不覆写）。
- 全量回归：`pytest tests/unit/skills/ tests/unit/evolution/ -v` 全绿。

## 净 LOC

收缩阶段应回吐扩展期的索引开销；本单允许小幅为正，017 结总账。

## 执行结果（2026-09-20 落地）

### 与票面设计的偏差（一处，已记 ADR 0017）

阶段三原案"主字典键改为 identity、删 `_alias_index`"**未按票面执行**，改为
**身份索引 + 单点归一**：主字典仍按 `skill.name` 建键，新增
`_identity_index: Dict[str, Skill]`（`skill_system.py:487`）指向同一对象，
归一只发生在 `_lookup()`（`:608-617`）一处。

理由是落地时查到的硬约束：`skills` 只读视图的**键就是喂给 LLM 的工具名**
（`context/orchestrator.py:2006`、`tool_executor.py:2605` 两处迭代拿键当工具名）。
翻转主键要么改名（模型侧工具面漂移、历史会话里的调用名失效），要么在视图
property 里再反查 name（把归一成本摊给每个消费者）。冗余一份指针换到同一个
"两键同对象"不变量，代价更小。被否方案与理由全文见
[ADR 0017](../../../01-architecture/adr/0017-skill-registry-key-domain.md)。

### 迁移点：票面 8 处与实际的 2 处

逐点复核后发现票面列的"8 个 identity 取键点"**本来就在调 `registry.get_skill()`**
（`agent_core.py:1373`、`skill_experience.py:194/279/357`、`skill_improver.py:523/664`、
`post_chat_pipeline.py:2175/2581`），只有 `scheduler.py:396` 走 `execute_skill`。
真正坏的不是这 8 个调用方，而是 `get_skill` 自己；它们全在**同一个已经错了的口径**上。
所以收缩阶段要清的是**绕过该口径的字典直取**，全仓 grep 实得 2 处：

| 迁移点 | 修复前 | 修复后 |
|---|---|---|
| `agent/chat_pipeline.py:873` | `registry.skills.get(skill_name)` | `registry.get_skill(skill_name)` |
| `tool_executor.py:931` | `self._skill_registry.skills.get(skill_name)` | `self._skill_registry.get_skill(skill_name)` |

`tool_executor` 那处是**执行链的门口**：`execute_skill` 已经归一了，但存在性检查
按 name 直取，身份键在门口就被判"不存在"，后面那条正确的路根本走不到 ——
票面 M1-M3 三批之外的一处。

配套：`get_skill` 补进 `SkillRegistryProtocol`（`:449`）。协议此前只声明 `skills`
视图，没有"定位单个技能"这一口 —— 调用方字典直取不是偷懒，是**接口没给别的口**。
类 B 已退役（ADR 0011），旧注释里"get_skill 可能是协程"的歧义不再成立。
两处直取由 AST 锁钉死（新增绕过点即红）。

### 反掩盖：假注册表确实洗过绿

`tests/unit/skills/test_improvement_persistence.py` 的 `_FakeRegistry`（按 name 建键、
只认 name）删除，改真实 `SkillRegistry` + `id != name` 技能 → **2 例转红**：

- `test_apply_syncs_to_disk` / `test_apply_without_service_still_works`：
  改进落在假注册表的 name 键上，真注册表下取不到对象。修到绿（未放宽任何断言，
  版本仍断 `1.0.1`、回滚仍断 `1.0.0`）。

同时暴露 3 个测试文件的**替身缺陷**（同一根因：MagicMock 对未声明方法返回自动子对象，
恒真）：`test_skill_funnel_p0_1.py::test_execute_skill_records_selection_without_apply`
（"查无此技能"静默变成"查到了"，applied 由 False 翻 True）、
`test_p2_items.py::TestB3/B4`、`test_improvement_items_g2g3.py::TestB3RequiresBins`。
补法统一为**显式钉 `get_skill` 这个口**，断言原文未动。

### 契约翻面（2 例，写明不删）

`test_skill_registry.py::test_get_skill_uses_name_not_id` 与
`test_skills_registry.py::test_has_skill_uses_name` 原断言
`get_skill(id) is None` / `has_skill(id) is False` —— 钉的正是本单要消灭的旧契约。
已翻向新契约（改名 + 注释写明翻面理由），并各自补 `has_skill("absent") is False`
保住"未知键仍取空"这一侧。
