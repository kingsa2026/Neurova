# 004 · 有害调整回滚留痕 + 无回滚天数真实起算

**Blocked by**: 001, 003

## 目标

让"发生过一次回滚"和"多少天没回滚"成为**有证据的事实**，从而拆开臂一的三角死锁。
完成后第一次能观察到 `phase` 从 1 往 2 走（或明确报告 `unevidenced`）。

## 死锁本相（审计实测）

```
can_auto_execute("low") 需 phase≥2      deployment_controller.py:47
phase 1→2 需 days_without_rollback≥7    deployment_controller.py:111
days_without_rollback 空历史返回 0.0    orchestrator.py:176-184
   ↑                                            │
   └── 回滚历史只由 execute_rollback 写入 ────────┘
       而 run_iteration 的 gain<0 分支走 _restore_optimizable()（:228）
       直接改内存，从不记历史 → 要回滚先应用，要应用先晋升，要晋升先回滚
```

`orchestrator.py:84` 的 `_started_at` 注释自称"无回滚记录时 days_without_rollback 的起算点"，
但实测**零消费方**（死字段）—— 这条注释描述的正是本单要实现的语义。

## 涉及层

- [x] 逻辑层：`rsi/orchestrator.py`、`rsi/rollback_manager.py`
- [x] 数据层：`rsi_installed_at` 与回滚历史落盘（复用 `persistence.py` 的 attach/load/save 协议）
- [x] 接口层：`api/endpoints/governance.py` 回滚历史可读（012 前保持最小）
- [x] 测试：`tests/unit/evolution/rsi/` + `tests/integration/evolution/`

## 交付内容

1. `run_iteration` 的 gain<0 分支（`orchestrator.py:226-230`）改为：
   `snapshot_id = rollback_manager.create_snapshot(_snapshot_optimizable())` →
   `_restore_optimizable(snapshot)` → `rollback_manager.execute_rollback(snapshot_id)`。
   快照创建失败时不得静默继续（按 D5，记账与动作不分家）。
2. `_compute_days_without_rollback()`：空历史时返回 `(now - installed_at).days`，
   `installed_at` 首次写盘、跨重启读回；有历史时保持"距最近一次回滚"。
   彻底删除"无数据返回 0"的写法，无 `installed_at` 且无法取得时返回 `GateVerdict(unevidenced)`。
3. 回滚历史挂持久化：并入 `closed_loop.py:712 bootstrap_evolution_persistence`
   （现状该函数只挂五件，rollback 历史纯内存）。

## 执行结果（2026-09-19 本单落地记录）

| 交付项 | 落点 |
|---|---|
| 1 回滚留痕 | `orchestrator.run_iteration` 的 gain<0 分支：`create_snapshot(应用前快照)` → `_restore_optimizable` → `execute_rollback`；留痕失败打 `logger.error`，**不允许"回滚已执行但判据看不见"** |
| 2 天数起算 | `RSIRollbackManager` 唯一持有 `installed_at` 与历史，新增 `days_since_last_rollback() -> Optional[float]`；空历史从装配时刻起算，无起算点返回 None |
| 2b 编排器不再伪装读数 | `_compute_days_without_rollback()` 改为委托；**取不到就不把 `days_without_rollback` 键交给判据** → 落 `unevidenced` |
| 3 持久化 | 复用 `persistence.PersistedStateMixin`（原子写 + 未挂载零 IO）；首次构造即 `save()` 钉住装配时刻 |
| 附带 | 晋升结论进 `run_iteration` 返回值：`phase_verdict = {state, reason, evidence}`，`if verdict:` 的旧调用写法不变 |

**三处与原计划的偏差（均有理由）**

1. **`_started_at` 被删除而非接上消费方**。原计划"让死字段活过来"，
   但它与持久化天然冲突（进程内时间戳重启即重置）。改为把时间线整个交给
   可持久化的 `rollback_manager.installed_at`，`_started_at` 与其
   `from datetime import datetime` 导入一并删除 —— 001 写的验收项
   "`_started_at` 有生产消费方"由"该字段不再存在"满足。
2. **挂载点从 `bootstrap_evolution_persistence` 移到 `RSIOrchestrator.__init__`**。
   bootstrap 早于 per-agent 构造，覆盖不到后来注入的实例；而 `agent_core.py`
   受尺寸棘轮锁死（正好卡在 2159 基线），加一行即红。
   路径按既有 `NEUROVA_RSI_RECEIPTS` 先例走 env 门控，
   并由 `start_server.py:77-78` 注入 `NEUROVA_EVOLUTION_ROLLBACK`，
   否则生产拿不到持久化 —— 这条不接就等于本单第 3 项没做。
3. **回滚留痕改为即时落盘，不走 10s 节流**。实测节流会把窗口内的回滚丢掉，
   而"证据静默丢失"正是本单要消灭的对象；回滚低频（仅 gain<0 时），开销可忽略。

其文档串把"从首次运行起算"的语义**甩给了 metrics 记录**，而 metrics 里那个键

83 个测试文件（其中 12 个以 `test_rsi_*` 命名）包围下存活的原因。
