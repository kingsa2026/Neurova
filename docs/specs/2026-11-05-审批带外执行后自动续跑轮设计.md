# 审批带外执行后自动续跑轮设计（候选 C3 批次 1）

> 出处：`docs/08-research/kweaver_vs_neurova_ontology_knowledge_base_comparison_2026-11-05.md`
> C3「工具级断点/快照恢复」摸底收窄。状态：批次 1 实施中。

## 1. 现状状态机（代码级，2026-11-05 实测）

治理判 ASK 后（`tool_executor._awaitApprovalVerdict:1700`）三条路：

1. **预算内等待**：`asyncio.wait_for(waiter, budget)` 进程内阻塞；人工批准经
   `approval_relay` 跨线程唤醒，**原轮完整管线执行**（钩子/超时/审计一条不缺）。
2. **超时让出**：`approval_timeout` 回给模型（"已暂缓"），审批单留库；
   人工稍后批准 → `hasApprovalWaiter=False` → 批准端点**带外重放**
   （`governance.py:316`，skip_governance），结果经 `_deliverApprovalOutcome`
   → `tool_coordinator.recordApprovalOutcome` → `_pending_hints` 晚到队列。
3. **进程重启**（等待中死掉）：审批单持久化在 SQLite，重启后批准同路 2——
   **工具执行与结果投递已闭环**。

## 2. 真缺口（收窄结论）

带外重放后，工具终态**只进 `_pending_hints`，下一轮才被读到**
（`tool_coordinator.py:394` 原注释自认："结果比轮次晚到，而下一轮才是它能被
读到的时刻"）。没有人再发消息，结果就沉在队列里——**用户点了批准，却拿不到
任何主动汇报**。这不是 dolphin 式帧树缺口，而是「晚到终态无人续读」缺口。

## 3. 方案（批次 1，本档范围）

带外重放完成后**自动拉起一轮续跑**，形态复用 `build_mode/resume.py`（§12.4）
的服务端拉起：identity 单通道（§6-163）→ `agent.chat` 原管线（落盘/广播照走）。

- 接线点：`governance.py` 带外重放分支（`hasApprovalWaiter` 早退之后），
  投递成功后 `startApprovalContinuation(...)` 后台任务；
- 续跑提示词点名审批号/工具/成败与错误摘要，要求模型继续原任务并如实汇报；
- 晚到 hint（结构性数据）与本提示词（触发意图）互补，不互替。

## 4. 明确不做（范围裁定）

1. **不做 dolphin 式帧级快照/任意断点恢复**：审批域的恢复诉求已被
   「带外重放 + 续跑轮」闭环覆盖（重启场景：审批单在库 → 批准 → 重放 → 续跑），
   帧树机器属投机面（修复教义第 1 条）；轮级挂起/续跑已有 run ledger
   `parkTurn/resume_payload`。
2. 续跑轮走正常 `agent_run_ledger` 准入，不绕闸；会话单活闸照常生效。
3. 不改 `approval_wait_seconds` 默认（0＝不阻塞的现网口径不动）。

## 5. 开关与默认值

`governance_settings.DEFAULTS["approval_continuation_enabled"] = False`
（工单 015 口径：默认值＝现网语义，行为变更显式开启）；
env `NEUROVA_APPROVAL_CONTINUATION` 显式 0/1 最优先。

## 6. 红灯判据（tests/unit/security/test_approvalContinuation.py）

- 红批 1：带外重放完成后端点不拉起续跑（endpoint wiring 断言）；
- 红批 2：续跑模块缺位（ModuleNotFoundError）；
- 绿批：开关默认关（口径判据）、续跑调用 `agent.chat` 携带结构化提示词
  （工具名/成败/审批号）、agent 缺席/无会话归属如实报不启动、开关关时跳过。
