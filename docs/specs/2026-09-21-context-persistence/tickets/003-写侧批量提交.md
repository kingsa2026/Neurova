# 003 写侧批量提交（写放大）

**Blocked by**: 001

## 目标

把归档写入从"每行一次 connect + commit + close"改为"一次归档调用一次事务"。

## 现状（实测，基线脚本 §2，10 万行存量库 / 24 条一轮）

| 形态 | 每轮耗时 |
|---|---|
| 每行独立连接 + 提交（现状 `record()` 同形） | 24.0 ms/轮 |
| 常驻连接 + 每轮一次事务 + trigram FTS 影子写 | 2.2 ms/轮 |
| 常驻连接 + 每轮一次事务 + 不建 FTS | 0.33 ms/轮 |

## 涉及层

- [x] 数据层：`EvictionLedgerDB` 持一个常驻连接（WAL + `synchronous=NORMAL` +
      `busy_timeout` + `isolation_level=None` 显式事务），`record` 不再 connect/close。
- [x] 逻辑层：`beginBatch()` / `commitBatch()` / `rollbackBatch()` 提供"批量记录 +
      一次提交"入口；事务边界 = 一次归档调用（池侧 `archiveBatch()` 上下文管理器），
      **返回前必须已提交**（规格 D8：不做异步/后台缓冲刷盘）。
- [x] 生命周期：`close()` 随池关闭释放（`agent_shutdown` 的关闭清单纳入
      `context_orchestrator.context_pool`）；连接不可用时降级路径显式（不静默丢写）。
- [x] 测试：`tests/unit/context/test_ledger_write_batching.py`
- [x] live-verify：`tests/manual/context_ledger_batching_90.py`

## 验收标准

- **A2**：24 条/轮的归档耗时 ≤ 现状形状的 **1/3**（同机同存量规模 A/B）。
- 事务语义**定为整批回滚**：一次归档调用内任一条写失败 → 整批回滚 + 整批计入
  `failed` + 点名原因（不部分提交，也不谎报 `written`）。
- 提交后立即可被另一连接读到（WAL 下读己之写跨连接可见）——防"提交了但别人看不见"。
- 并发：两个写方并发归档不互相长期阻塞（`busy_timeout` + 实例锁生效），总行数正确。
- 批外单条写入仍立即提交（A1 的跨重启语义依赖"写完即可见"，语义不回归）。

## 实施结果

- 红灯 → 绿灯：`10 failed` → `12 passed`（先写断言 A2 与事务语义的失败用例）。
- live-verify（判据 A2 实测）：1 万行存量库、24 条/轮、20 轮取中位——
  改前形状（每行独立 connect+commit+close）**233–238 ms/轮** vs 本批实现
  **1.03–1.07 ms/轮**，差 **220–233×**（A2 只要求 ≤ 1/3）。
  另经真 `Agent` → 真 `build_context` 归档段核对：`written=3 / failed=0 / batches=1 /
  db_rows=3`，且另一进程读到同样 3 条（跨进程可见）。
- **事务语义定死为整批回滚**（两选一已在实现里定死并断言）：批内失败 → `rollbackBatch()`
  + 本批条数整批计入 `failed` + `last_error` 点名异常类型与消息；
  内存归档不受影响（教义：归档主流程不可被台账故障打断）。
- 读路径一并收敛到常驻连接（`search` / `count` / `gc` 走 `_lock`），
  `gc` 的删除与 FTS 对齐收进同一显式事务（改前是隐式事务 + 末尾提交，语义不退化）。
- 并发现实：常驻连接不可并发使用，故实例内串行（`RLock`）+ `busy_timeout=10s`；
  跨实例并发写已由用例锁住（3 个实例 × 5 批 × 4 条，总行数 60 正确、无报错）。

## 补充（A2 判据口径修订 · CI 红修复）

- A2 的读数**两侧预热后取 3 轮中位**：原用例把首次归档（含 token 估算器懒加载，
  实测 227–331 ms）计入分子 ⇒ 分子恒为现状形状的 1.2 倍，CI 上必然判红。
  修订后实测 135–427×（阈值 3×，裕量 45× 以上）。
- 同契约补一条**结构面**判据 `TestRoundHasOneTransactionBoundary`：一轮归档内
  新建连接 0 次、`BEGIN` 1 次、`COMMIT` 1 次——与机器速度无关，替代"只信比值"。
- 明细见规格 §8.1「003 补充记录（A2 判据口径 · CI 红修复）」。

## 不做

- 不做 GC 的保留策略触发点改造（007）。
- 不引入连接池（规格 D7 与 ADR 0014：动态路径不进池）。
- 不做异步/后台缓冲刷盘（规格 D8 明确否掉）。
