# 001 跨重启召回示踪弹

**Blocked by**: 无

## 目标

让"永久归档跨重启为真"这条判据第一次可被观察到：写进池的归档，在**新进程**里能取回原文。

本片只钉判据与最小通路，不做写放大优化、不换分词器、不动迁移（那些是 002-007）。

## 现状（实测，基线脚本 §1）

生产同型构造下 `resident_limit=None`、`ttl_seconds=0`：

- 写入 600 条常驻后 `cleanup_expired()` = 0、台账 DB 行数 = 0；
- 新实例 `recall_evicted` = 0 条。

即**写入口不可达 + 无持久化**，判据 A1 当前必然红。

## 涉及层

- [ ] 数据层：`ContextPool` 在**归档写入路径**上写穿台账，而不是只在"驱逐"时写。
      这是本片的根因改动：现状 `_archive_evicted` 只在驱逐时被调用，生产构造下驱逐不可达。
- [ ] 逻辑层：归档条目在 `add_context` 成功落常驻后同步写台账；写失败**显式上报**
      （`get_retention_stats()` 里可见），不静默。
- [ ] 读层：`recall_evicted` 从"内存 + 持久"双源合并（现状已有该结构，本片让持久源真的有数据）。
- [ ] 测试：`tests/unit/context/test_context_persistence_restart.py`

## 验收标准

- **A1**：写 → 丢弃实例 → 新实例同库 → `recall_evicted(query)` 取回原文，条数与内容逐字相等。
- 写失败路径：注入必然失败的台账，断言 `get_retention_stats()` 上报失败，且日志点名原因
  （不得 `except: pass`）。
- **红灯实证**：先写断言现状的失败测试并贴出红灯输出，再最小实现转绿。

## 不做

- 不做 `draw` 的 DB 直查（规格 §4 非目标）。
- 不做批量提交优化（003）。
- 不改 `resident_limit` 默认值。
