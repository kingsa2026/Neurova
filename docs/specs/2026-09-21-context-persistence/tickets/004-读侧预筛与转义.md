# 004 读侧预筛与转义

**Blocked by**: 002

## 目标

让 `recall_evicted` 的查询在中文语料上**真的走得动**，且用户输入不被当成 LIKE 通配模式。

## 现状（实测，基线脚本 §4/§4b/§8）

- `unicode61` 分词器对中文等于无索引：`上下文压缩` / `窗口预算` / `上下文` 命中 **0**
  （LIKE 真值 4934 / 4921 / 16526）。
- LIKE 分支直接拼 `f"%{query}%"`：库内 3 行时查询 `%` 命中 **3 行**、`_` 命中 **3 行**。

## 涉及层

- [ ] 逻辑层：查询长度 <3 → 走 LIKE 分支（trigram 对 <3 无索引能力，强上会**假阴性**）；
      ≥3 → MATCH。
- [ ] 逻辑层：LIKE 分支加 `ESCAPE '\'`，转义 `\` `%` `_` 三字符。
- [ ] 逻辑层：候选集上限——MATCH 命中超阈值时降级为"最近 N 条 + 候选内子串过滤"，
      不得整库拉回（阈值初值待校准，规格 U2）。
- [ ] 测试：`tests/unit/context/test_ledger_read_prefilter.py`

## 验收标准

- **A3**：中文查询的 MATCH 命中集合 == LIKE 真值集合（对拍断言，逐条比对而非只比条数）。
- **A4**：长度 <3 的查询走 LIKE 且 `%`/`_` 不越权——构造含 `%` `_` 的库内文本，
  断言命中集合与真值相等（实测：加 ESCAPE 后 `%` 命中 1 行，不加命中 3 行）。
- 英文查询不回归：`The context window` 两路一致（实测 16667 = 16667）。
- 超阈降级路径可断言（构造高命中查询，断言走降级分支且结果仍满足子串约束）。

## 注意

本片只改**查询侧**；FTS 分词器换成 trigram 在 006（同批落地，避免重建两次索引）。

- 不做启动加载（005）。
