# 002 版本域与 v1 迁移

**Blocked by**: 001

## 目标

把 `context_ledger` 库纳入 `core/db_migration.py` 的版本域纪律，并落 v1 schema 变更。

现状 `eviction_ledger_db.py` 只有 `CREATE TABLE IF NOT EXISTS`，**没有 `user_version`**，
与 `AGENTS.md` §3 直接冲突。持久层一旦真跑起来，无版本纪律 = 后续每次改 schema 都是裸改。

## 涉及层

- [x] 数据层：`register_migration(1, _migrateToV1, domain="context_ledger")`，建库路径改为
      `migrate(conn, "context_ledger")`；**不新建平行迁移体系**。
- [x] v1 内容（规格 D12 表 + §8 定案）：
      - 加 `content_digest` 列 + 回填（旧行按内容重算，`executemany` 批量）；
      - `uniq_digest(user_id, agent_id, content_digest)` 唯一索引；
      - `idx_scope_id(user_id, agent_id, id)`——实测 `(user_id,agent_id,session_id)`
        顺序对热集查询是负优化（37 ms vs 0.9 ms），故用 `id` 收尾（U4 定案）；
      - `chat_scope` 列（**U1 定案甲案**：独立列为主 + 读侧解析 metadata 作兼容兜底）；
      - `created_at` 列（U3 定案：加，`freshness` 打分与排序都要它）。
- [x] v1 前置（规格未列，实施期新增）：**合并同内容重复行**（保留最早一条 + 同批清掉
      对应 FTS 影子行 + 点名条数）——唯一索引在旧库带重复行时会让迁移直接失败。
- [x] U1 兼容兜底（甲案的配套，缺了就是"只做一半"）：读侧对
      **无该列 / 列值为 NULL** 的旧行解析 `metadata` 的等价判据（`resolveArchivedScope`）；
      `created_at` 同理回退 `evicted_at`（`resolveArchivedCreatedAt`）。两路判据同源
      `collaboration/memory_scope.scope_from_metadata`，
      **不新写第二份规则**（工单 008 的作用域闸口直接吃这两路）。
- [x] 未注册域要**报错不静默**：`migrate()` 对未注册域本就 `ValueError`，断言它生效。
- [x] 测试：`tests/unit/context/test_context_ledger_migration.py`
- [x] live-verify：`tests/manual/context_ledger_migration_90.py`（真 v0 库经生产构造面迁移）

## 验收标准

- **A6**：v0 库迁到 v1 后重跑 `migrate()` 返回空（幂等）；伪造高版本库抛 `SchemaVersionError`。
- 迁移每条独立事务；中途失败回滚且上抛（不留半迁移状态）。
- 旧代码打开新库可写可读自己写的行（规格 D12"允许回滚"，不做硬拦）——断言不抛错；
  旧代码写下的 NULL digest 行与既有行同内容时，召回侧按内容指纹去重（仍只出一条）。
- v1 迁移耗时量级：5 万行真库 **0.48–0.49 s**（三次连跑，按真内容指纹回填；规格
  D12 表的 0.19 s 来自基线脚本的常量回填，形状不可比，读数以规格 §8.1 偏离记录为准）。
  分阶段：加列 0.022 s / 回填 0.25 s / 合并重复行 0.09 s / 两索引 0.09 s，不引入长事务。
- U1 兜底路径断言：伪造一行 `chat_scope` 为 NULL 的旧行（内容与 `metadata.chat_scope`
  一致），断言读侧判据与"有列"路径**同源且同结果**（两路 `scope_from_metadata`）。

## 实施结果

- 红灯 → 绿灯：`15 failed` → `17 passed`（先写断言 A6 与 U1 兜底的失败用例并实证红）。
- `content_digest` 由 `contentDigest(content)` 单点计算：写入路径与迁移回填共用同一
  函数，不新造第二份指纹口径。
- 召回路径回填：`recall_evicted` 的行 → `ContextInput` 补 `chat_scope` 与归档时刻
  （此前只回 `turn_id/session_id/evicted_at`，作用域与时间都丢）。

## 不做

- 不做 FTS 分词器替换（006）。
- 不做 GC 策略（007）。
- 不做召回作用域闸口的放行/拦截逻辑与「session 优先 + 跨 session 兜底」策略（008）。
  本片只把判据准备好（列 + 兜底函数 + 召回回填）。
