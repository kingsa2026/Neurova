# 002 · 工具记录只有一个形状：包装事件不再进取证源

**Blocked by**: 001

## 目标

`_collect_tool_messages()` 的产物从此**只有一种形状**（扁平记录），P-b 探针转绿。
这是 003 咽喉收编的前置：不先对齐形状，收编会把脏记录一起焊进咽喉。

## 根因与落点

原生链的工具记录有**两个生产者**：

| 生产者 | 形状 | 后果 |
|---|---|---|
| `agent/loops/base.py:196-204`（tool_call）、`:338-347`（tool_result） | 扁平，带 `tool_name` / 顶层 `success` | 契约正确，保留 |
| `agent/chat_pipeline.py:2255-2257` + `:2279` | 包装 `{"type":"tool_call"/"tool_result","data":…}` 并写进**同一列表** | `turn_state.py:58-62` 的 `all(r.get("success") is True)` 恒 False；`post_chat_pipeline.py:1611` 读出 `unknown` |

## 涉及层

- [ ] 逻辑层：`chat_pipeline.py:2279` **停止**把 `native_tool_events` 并入取证源。
      SSE 转发（`emitter(etype, _e2_data)`，`:2262-2276`）继续用包装事件——它是传输壳，不是取证记录。
- [ ] 逻辑层：删 `api/endpoints/console.py:612-618` 那段"两种形状并存"的展示层跳过分支
      （consumer-only 守卫，根因修掉后即死码，**必须同批删净**）。
- [ ] 逻辑层（防再生）：`agent/turn_state.py:resolve_tool_outcome` 与
      `neurova/evolution/objective_evidence.py:parse_turn_steps` 各加**形状契约守卫**——
      见到无 `tool_name` 的 tool_call 或无顶层 `success` 的 tool_result ⇒ `logger.warning` 出声并报条数。
      静默过滤=掩盖；直接抛=会炸主链。出声是本票要的形状，不是可选装饰。
- [ ] 测试：P-b 转绿 + 反向锁（手工并写一条包装条目 ⇒ 守卫必须 WARNING）

## 验收标准

- 流式与非流式两条通道下，P-b 探针均绿；`_collect_tool_messages()` 内零"缺 `tool_name`"条目。
- 一轮真机/近真机流式对话后，EKB **新行**的 `skill_name` 不含 `unknown`（P-c 的 `unknown` 半段转绿；
  `success` 半段留给 003/004，本票不得为凑绿而改动成败判定）。
- SSE 回归：工具事件仍能在前端时间轴显示，`taskNameActive/taskNameComplete` 展示字段不丢
  （`loops/base.py:202-203`/`:348-349` 是这些字段的唯一写入方）；SSE 去重 key 仍基于完整内容 hash，
  不得因本票改为前缀 hash。
- 净 LOC ≤ 0 实测（删两处并写/守卫 ≥ 加守卫的行数）。

## 禁区

- 不得为了"消除 unknown"在 `post_chat_pipeline.py:1611` 加 `if tool_name == "unknown": continue`
  ——那是把根因从展示面挪到采集面的第二层抹除。
- 不得让包装条目继续进列表而只在下游判形状（判据必须落在生产者一处）。
