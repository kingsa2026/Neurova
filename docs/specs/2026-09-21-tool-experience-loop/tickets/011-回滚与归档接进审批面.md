# 011 · 回滚与归档要有人按得动：把孤岛读面接进审批面（含前端）

**Blocked by**: 006

## 目标

一次垂直切片：在治理/技能管理页面上点"回滚"或"查看归档"，后端真的回滚、留下可审计痕迹、
LLM 工具面随之变化。**没有 UI 的接法不算完成**——只加端点等于再造一批"写了没人读"的接口。

## 现状（上一批工单 017 移交给本批的部分）

这些方法在顶层 `neurova/` **零生产调用方**（已排除 `tests/` 与 `NeurUI/src-tauri/**` 副本），
但其底层状态在工单 016 已被持久化：

- `evolution/skill_experience.py:392` `rollback_skill`、`:308` `get_archives`
- `evolution/skill_improver.py:656` `revert_last_improvement`
- `rsi/rollback_manager.py:119` `RSIRollbackManager.should_rollback`

实际回滚走的是 `evolution/rsi/orchestrator.py:325-337` 的内联 `gain < 0` 判据 ⇒ **两套决策口径并存**。
归档仅由 `rebuild_skill`（`skill_experience.py:341-350`）有界写入。

## 涉及层

- [ ] 逻辑层（先收口径）：`should_rollback` 与 `orchestrator.py:325-337` 的内联判据**收敛为单源**。
      两套口径不得长期并存：一个自动、一个人工，判据不同会让"人以为回滚了"与"系统认为该回滚"分叉。
- [ ] 数据层：回滚留痕只写 `config["revisions"]`（工单 016 硬约束：`improvements` 那个无人读取的键
      已删净，**不许加回来**）。
- [ ] API 层：经治理面暴露 archive/rollback；沿用统一响应解包口径（新前端代码用 `unwrap<T>()`，
      不写 `as any`）。治理面未装配时按既有约定返 503 而非 `available:false` 静默 200
      （先例：`GET /v1/governance/rsi/status`）。
- [ ] UI 层：入口挂在 `NeurUI/src/pages/ExperienceKnowledgePage.vue`（上一批工单 015 的处置面就在这里）
      或 `AgentSkillPage.vue`，**不新开页面**；归档列表 + 回滚按钮 + 二次确认 + 结果态。
- [ ] i18n：`NeurUI/src/i18n/locales/` **11 份 locale 同步**（既有同键守卫会拦漏改）。
- [ ] 设计契约：新 UI 需配套 `DESIGN.md` 条目、feature spec 与 `.spec.ts` 快照
      （`quality:required` 的 companion 规则会检查）。
- [ ] 测试：后端 hunk 级 + 前端 vitest；`agent_core.py` 侧改动受尺寸棘轮约束须抽模块。

## 验收标准

- **端到端可演示**：选一条有归档的技能点回滚 ⇒ ①`get_archives` 返回项减少/状态变化；
  ②`config["revisions"]` 多一条含操作者与时间；③**发给 LLM 的工具清单里该技能状态真的变了**
  （依赖 006 的停用生效，故此票排在 006 之后）。
- 两套回滚口径合一后有守卫锁：grep/AST 断言 `should_rollback` 之外不存在第二处 `gain < 0` 决策实现。
- 反向锁：归档为空时按钮不可用且后端拒绝，不得静默成功。
- 人工审批面不得引入"批准即失效"的回潮（工单 010 的 `human_approved=True` 单线穿透语义保持不变）。
- 净 LOC 为正（新端点 + 新 UI + 用例）：在票末分列后端/前端行数，
  并对照前端既有 23 条预存红（本票不得新增红；`vue-tsc` 全量 0 error 是回归基线）。

## 执行结果

- **判据单源**：`orchestrator.run_iteration` 内联的 `gain < 0` 收进 `should_rollback`
  （发散 / 负 roi / 负 gain）；AST 守卫锁住 `gain < 0` 的决策只许出现在 `rollback_manager.py`。
- **留痕**：回滚落 `config["revisions"]` 一条（trigger/operator/时间/前后版本），有界 5 条；
  已删净的 `improvements` 未复活（用例钉住）。
- **API**：`GET /governance/skills/{id}/archives`、`POST .../rollback`；未装配 **503**、
  空归档 **409**，都不静默 200。`tests/unit/api/test_skill_rollback_governance.py`：`7 passed`。
- **UI/i18n**：入口挂 `AgentSkillPage.vue` 技能卡（不新开页面），11 份 locale 同步 10 个键；
  前端用例 `skill-rollback.test.ts`（2 条）+ `AgentSkillPage.archive.test.ts`（4 条）。

未闭环（诚实登记）：票面提到的 `DESIGN.md` 条目 / feature spec / `.spec.ts` 快照
**本仓不存在该三件套的既有落点**（`*.spec.ts` 零命中，`quality:required` 在 `.cnb.yml`
与 GitHub 侧都无对应 job），按「不新增准则类文档、不建第二套快照体系」的纪律，
以前端 vitest 用例 + `locale-consistency` 守卫承接同等约束；
浏览器级 live（起后端 + `npm run dev` 点按钮）未做，属需人配合的动作。

**用户裁定（按现状承接）**：三件套在本仓无既有落点（新造即等于建第二套快照体系，违反
「不新增准则类文档」纪律），浏览器级 live 需常驻后端。用户在 Issue #80 裁定
「按现状承接」，故两项**退出未闭环清单**，本批不补做。裁定本体与覆盖范围见
[票集索引](000-索引.md) 的「用户裁定（按现状承接）」节。
