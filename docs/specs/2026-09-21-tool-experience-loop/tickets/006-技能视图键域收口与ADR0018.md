# 006 · 技能停用与质量熔断要真的少掉一个工具（视图键域收口 + 本域 ADR）

**Blocked by**: 004

## 目标

在管理面/自动维护里停用一条自动技能，**LLM 的工具面必须真的少掉它**；
质量熔断对自动技能必须能真的咬合。审计 L-06 / L-06b。

## 根因（三闸恒开绿灯）

`skills/skill_visibility.py:144-157` 以 registry 键（= `skill.name`）建条目且**硬编码 `"enabled": True`**；
`:173-182` 以 manifest 键（= `skill_id`，`skill_service.py:886-892` 的 `iter_skills()` 产 skill_id）建条目并按
enabled 过滤。而 schema 装配拿 **name** 去问视图（`context/orchestrator.py:2004-2014`）⇒
自动技能 `name ≠ skill_id`（`evolution/skill_encapsulation.py:452-465` 明写"名字不是身份"），
于是永远命中①条目：
1. `SkillView.quality_for`（`:74-86`）读①⇒无 `usage`⇒ None ⇒ `skill_injection.quality_blocked(None)` 放行（`:237-243`）；
2. manifest 的 `enabled=False` 只挡②；
3. `SkillRegistry.set_skill_enabled`（`skill_system.py:604-616`）只改 `skill.status`，
   而 schema 段无 `status` 判据；runtime `Skill` 无 `enabled` 属性（`skill_system.py:81-88`），
   `skill_injection.py:141`/`:268` 读的 `getattr(s,"enabled",True)` 是默认值。
4. `trust_for` 的 provisional 过滤（`skill_visibility.py:148`）同被旁路。

## 涉及层

- [ ] 数据层：`build_turn_view` 的①条目必须按 **identity 反查** manifest 的 `enabled`/`usage`
      （经 `entry["manifest"]["name"]` 或等价的既有字段）。**禁止新建第三份 name↔identity 映射**
      （工单 015 教训：映射必须单源）。
- [ ] 逻辑层：`SkillView` 的 `invocable` / `quality_for` / `trust_for` 三个取数口统一到一次反查，
      不得各查各的。
- [ ] 逻辑层（L-06b）：`skill_system.py:508` 的 `self._skills[skill.name] = skill` 同名静默覆盖 ⇒
      先加**告警守卫**（计数并可观测），**不在本票硬拒**。现网 `data/agents/default/skills/manifest.json`
      有 8 条不同 `synth_*` 共用 name=`general_tool`（历史生成器遗留，现行命名已带 `pattern_id` 后缀），
      当场硬拒会让存量库装配失败。迁移方案另票。
- [ ] 逻辑层：自动维护臂 `evolution/skill_experience.py:634-643`（默认关）的开关打开后，
      效果必须可观测（`run_skill_experience_maintenance` 已在 `post_chat_pipeline.py:2635`/`:2646` 接线，
      此前是"记账通、效果断"）。
- [x] 文档：新记一份本域 ADR —— 记录"查询键=name、记账键=identity"
      的取舍与被否方案（视图按 skill_id 索引）。**不回改 ADR 0017**（0017 的键域统一方向没错，
      只是没覆盖视图域）。**落地路径**：`docs/01-architecture/adr/0019-skill-view-key-domain.md`
      （票面原按当时的平铺目录与编号写作 `docs/adr/0018-<slug>`；实际入库时平铺目录
      `docs/adr/` 已整目录退役、收口到编号分层，0018 号已被记忆分类词汇表占用，
      故本域 ADR 取 0019 号）。
- [ ] 测试：探针"停用一条 name≠id 的自动技能 ⇒ `invocable(name)` 必须 False ⇒ schema 少一个工具"；
      反向锁"停用 name==id 的手工技能"同样生效（防只修一半）。

## 验收标准

- 停用生效判据是**发给 LLM 的工具清单少了那一项**（断言 `tools_for_llm`，不是断言 manifest 字段变了）。
- `quality_for` 对有 usage 的自动技能返回非 None，且 `applications≥2 且零完成` 时该技能本轮不进 schema。
- name 冲突告警在现网存量上可复算（预期计数 = 8，来自上面那份 manifest）；硬拒未引入、存量装配不炸。
- `git show HEAD:` 单独核一遍定义与调用都在库内（本仓踩过"调用方已提交、定义未提交"）。
- 净 LOC 小正：列明去向（反查 + 守卫 + ADR）。
