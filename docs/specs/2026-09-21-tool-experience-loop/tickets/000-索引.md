## 第二轮补做（006 / 005 残留 + 011 整票）

前一轮合并（PR #87）交付了 001–010 的主干，但三轮收口各有未尽的断点。第二轮逐条补齐：

### 006 残留：两条判停闸仍在恒开绿灯

前一轮只把 **manifest 的 `enabled`** 反查进视图，另两条判停落点仍在原地：

1. `SkillRegistry.set_skill_enabled` 写的是 `skill.status`（`SkillStatus.INACTIVE`），
   而① registry 底座条目没带上这份状态 ⇒ 停用一条 `name == skill_id` 的手工技能，
   `invocable(name)` 仍为 True。
2. `SkillService.archive_skill` 写的是 `usage["state"]="archived"`，视图判据同样不读它
   ⇒ 归档完技能照样留在 schema 里（给 LLM 一个必然失败的工具）。

收口：`build_turn_view` 的底座条目补 `status`（`_runtime_status` 取枚举 `value`），
`VisibleSkill.enabled` 加生命周期归档判据（`stale` 是闲置标记，不拦）。
`usage.state` 的读取路径与 `enabled`/`status` 同在一份 entry —— 三个取数口仍是一次反查。

同名冲突复算：新增 `scripts/diagnostics/skill_name_collisions.py`，
把"我记得有 8 条 `synth_*` 共用 `general_tool`"变成可重跑读数
（8 条不同身份共用一名 → 计数 7：先到 1 条留得住，其余 7 条被静默顶替）。

### 005 残留：两处"静默零"

1. `collaboration/neurflow/{adapters,node_registry}.py` 都写
   `from neurova.execution_engine.tool_engine import get_tool_engine` ——
   该模块**没有**这个函数，ImportError 被吞成 `sync_tools` 恒 0 /
   `_sync_tools_from_engine` 恒 `return 0`，工具节点目录永远空着，
   而 0 与"真的没有工具"在观测面上分不开。
   收口：引擎单源改指 `api/endpoints/tool_layers.get_tool_engine()`
   （MCP 工具注册落的就是它）；`node_registry` 的重复 dict 版转换删除，
   委托 `adapters.sync_tools`；`tool_to_node` 兼容 `ToolDefinition` 数据类
   （此前 `tool['name']` 在数据类上直接抛 TypeError）。
   守卫：`test_no_phantom_get_tool_engine_import`。
2. `/tool-layers/tools/execute` 把 `ToolEngine` 当**入口**用 ——
   它其实是咽喉的内层一档（`tool_executor._execute_tool_core` 调它），
   直连即绕过票据、`on_tool_executed`、治理预检与 hooks。
   收口：有 agent/执行器时走 `agent.tool_executor.execute`，成败判据用咽喉的
   `_result_is_success`（单源）；无 agent 的评测/脚本路径保留引擎直调（反向锁钉住）。

## 批次级判据

票面正文（`001`–`011`）是**逐票**的收工判据；本节是**整批**的判据：每张票必须
遵守的全局约束、不可调换的硬次序、以及整批收工的取证入口。三者此前同样只存在于
Issue #80 的附件里，索引原只有一节「全局约束**遵守情况**」——那是实现方的自陈报告，
不是约束本体；读者拿不到「约束写了哪几条」，也就无从复核各票是否在同一契约下完成。
本节正文按附件原文录入，**遵守情况**在各票「执行结果」格与规格文档第 8 节。

### 硬次序（不可调换）

**主干顺序**：`001 → 002 → 003 → 004 → {005, 006, 007, 009, 010} → 008/011`

- `002` 必须先于 `003`。形状不对齐就收编咽喉，等于把 `unknown` 那类脏记录一起焊进咽喉，
  第二次动咽喉的代价远大于第一次。
- `007` 必须先于 `008`。先止住「脏参数自动执行 → 永久失败票」的灌毒，再谈指纹重构，
  否则重构期还在往证据库里续毒。

### 全局约束

1. **先红后绿**：先写必红用例，再改实现；`001` 的探针就是本批的红基线。
   修复类默认**净 LOC ≤ 0**，为正须在票末「执行结果」列明超出行数的去向。
2. **禁止 consumer-only 守卫**：不得在调用方/展示层加 try/except、默认值兜底来「消除报错」。
   已存在的两处此类守卫必须随根因修复一起收掉，不留半截。
3. **解释器**：一切 pytest/python 用项目自带解释器（Windows 下为 `.venv/Scripts/python.exe`，
   POSIX 下为 `.venv/bin/python`）；全局 python 会伪造出大片「缺包/DLL」假红。
4. **`agent_core.py` 尺寸棘轮**：基线 2159 行、净增即红、history 单调不升
   （`tests/unit/agent/test_agent_core_size_ratchet.py`）⇒ 装配改动**必须抽独立模块**。
5. **用例必须经生产构造点取件**：测试内手工传 kwarg 覆盖的通路一律视为**无效覆盖**；
   禁止 `MagicMock` 冒充工具消息，禁止用 `Mock(return_value=[])` 顶替工具记录。
6. **写路径纪律**：任何落盘路径可注入 + 根 `tests/conftest.py` 双层隔离；
   **严禁对 `data/` 下生产库做写验证**（只允许只读或复制到 `tmp_path`）。
7. **grep 限定顶层 `neurova/`**：`NeurUI/src-tauri/` 下有构建期旧副本，仓库根 grep 会假命中。
8. **新增测试文件须登记 `scripts/ci/protected_tests.txt`**，且先逐文件单跑全绿再登记。
9. **提交纪律**：他人有在途改动的热区文件可改**不可整文件提交**，必须 hunk 切分；
   提交后核对用 `git show HEAD:<file>` 而不是看磁盘。
10. **票号撞名**：本批 001–011 与上一批（经验质量门控）001–017、RSI 批 001–018 编号重叠。
    票内引用他批工单必须带路径形态（如 `docs/specs/2026-09-19-experience-quality-gate/tickets/009-*.md`），
    裸编号视为歧义。
11. **动前端必须配套**（本批只有 011 触发）：`NeurUI/src/i18n/locales/` 11 份 locale 同步 +
    设计契约 + 快照；`vue-tsc` 全量 0 error 是回归基线，不得新增前端红。
