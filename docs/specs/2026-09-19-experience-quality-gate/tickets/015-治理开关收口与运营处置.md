### 2. `experience_records` 人工处置通路

新列 `operator_disposition TEXT`（NULL=未处置），取值 `endorsed | demoted | suppressed`，
`EKB.set_operator_disposition(ids, disposition)` 是唯一写入口。**开先例的理由**（写在
docstring 里）：`adoption_outcome` 那一格由 006 的回写通路独占，记的是"这条被执行后
客观成没成"；人的判断写进同一格＝把审核洗成执行证据，007 的排序与 008 的
`adoption_success_rate` 会一起吃进假账。所以处置与证据分列，而不是新增第二套机制。

判据真的咬合（复用 007 的两个接缝，实测数值，同一查询 "PDF 报告 导出"，相关性 0.6）：

| 动作 | 检索 `similarity_score` | 注入优先级 | 行数 | 快照 |
|---|---|---|---|---|
| 处置前 | success 0.75 / 无回写 0.70 / failure **0.35** | 78 / 70 / **55** | 3 | decisions=2, rate=0.5 |
| failure 行降权 | 0.35 → **−0.10**（跌到末位，低于全部证据档） | 55 → **45** | 3 | 不变 |
| success 行隐藏 | 从结果里出局（列表只剩 2 条） | — | **仍 3**（未删） | 不变 |
| 全部恢复 | 回到 **0.35 / 0.75**（逐位相同，无暗记） | 回到 55 / 78 | 3 | 不变 |
| unevidenced 行审核通过 | 分数不变 | **65**（它的证据档，不是 78） | 3 | decisions **2→2**、rate **0.5→0.5**、`adoption_outcome` 仍 `unevidenced` |

- 降权罚分 `DEMOTION_PENALTY = 0.45` 的实测依据：证据档跨度 +0.15（success）到
  −0.25（failure），罚分不大于跨度时"被降权的成功条"仍压在"客观失败条"上面
  （首轮就是红在 `assert 0.45 < 0.35`）——降权等于没降。
- 隐藏只在**检索侧**出局（`find_similar_experiences` 里 `continue`），注入侧不重复设守卫：
  证据没带到消费方才是根因，故 `chat_pipeline._retrieve_ekb_experience` 随
  `adoption_outcome` 一起带 `operator_disposition`（`test_ekb_retrieval_wiring` 用真实
  EKB 实例锁这条传动轴：库里降权 → 注入优先级读到 45）。
- 反向锁三条：审核不得改证据列/读数/分数；任何处置态（含恢复）全程不增删行；
  未知处置态 `ValueError`（API 侧 `Literal` 先拦，`test_unknown_disposition_is_a_validation_error`）。
- 端点：`PUT /v1/experience/{id}/disposition`（`disposition` 三态或 `null`）；
  404 给不存在的行，400 给非法 id。硬删仍是原 `DELETE`，本票不混同。
- 排序口径（007 登记给本票）：`get_experience_records` 由纯 `ORDER BY id DESC` 改为
  **待处置优先、组内写入序**（待处置＝未处置且 `adoption_outcome IN (failure,unevidenced)`
  或 `evidence_state='unevidenced'`）。用例刻意让待处置那条是较早的一行，
  否则断言测的是插入序而不是处置生效（首轮即红在 `assert [2, 1] == [1, 2]`）。
