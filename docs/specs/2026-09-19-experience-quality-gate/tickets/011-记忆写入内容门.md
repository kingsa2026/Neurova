## 验收标准

- 同一句归一化后相同的输入写 5 次 ⇒ 库里 1 行（或"1 行 + 计数 +4"的合并语义，
  二者择一并在 docstring 写明）。
- 反向锁：语义不同但长度相近的两条输入不得被误合并（正例断言 2 行）。
- 空/纯空白输入不得坍缩进同一个桶（对照 `pattern_crystallizer.py:467-468` 的空键问题）。

## 执行结果（已完成）

- 一把键两个写入面共用：新增 `neurova/core/content_identity.py`——
  `normalized_key`（自 `neurova/memory/pending_memory.py` 迁入，折叠口径不变，
  `lower()` 改 `casefold()`）+ `normalized_payload_key`（收集结构化载荷的字符串
  叶子后归一化）。`pending_memory` 改为从 core 导入，全仓只有这一处折叠实现。
- 记忆面 `MemoryManager.remember`：门键 = 作用域三元组 + 归一化内容 +
  读取侧据以区分行的分类维度（category / memory_type / perspective / origin）。
  懒建索引（含从持久层载入的行 ⇒ 跨重启生效）+ 命中前懒校验自愈（目标行被删/
  遗忘/归档则重新开放该键）+ `update_memory` 改内容时 O(1) 跟随（旧键让开、新键接上）。
  显式 `id=` 是身份寻址写入（M-25 自定义 id / 恢复路径），不过门。
  合并语义择一＝**首条为准 + 刷新 `updated_at`**（不新增行、不记计数，理由写在 docstring）。
- EKB `add_experience_record`：身份键由"context/result 全字段相同 JSON"升级为
  `(agent_id, skill_name, success, content_key)`——`result` 退出身份键。生产实测
  `data/experience_knowledge.db` 同一 context 重复 7 行（id 16/17/73/74/75/87/88），
  逐行差异全在 `result.reply_excerpt`（每轮都是新的 LLM 回复），把回复算进身份
  等于宣布"同一句永不重复"。`success` 留在键内：同问一成一败必须并存（证伪回路读）。
  合并语义择一＝**1 行 + `seen_count` 计数**，且 result/timestamp last-write-wins
  （首条是 `[LLM Error]` 回复不得被永久钉死）。
- 数据层：新增 `_migrate_schema()`（幂等补 `content_key`/`seen_count` 列 + 四元组复合
  索引 + 只扫 `content_key IS NULL` 行回填一次）。`''` 表示"算不出内容身份"，
  `NULL` 只表示"尚未回填"，两者语义分开，回填不会每次启动重扫。
- 空键不坍缩（两面对齐）：归一后为空 ⇒ 不进门、各自成行（对照
  `pattern_crystallizer.py` 的空键吞没问题）。
