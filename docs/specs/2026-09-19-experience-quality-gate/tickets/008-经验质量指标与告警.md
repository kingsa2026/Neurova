## 验收标准

- 一条经验被采纳且该轮失败 ⇒ 平均采纳后成功率指标下降（读数必须能动）。
- `unevidenced` 占比可告警：构造全为无证据条目的库 ⇒ 触发告警。
- 规范指标必须有写入方（RSI 工单 006/012 同口径：定义了没人写 = 缺陷）。
- 反向锁：删除的聚合方法必须连单测一起删；接线的必须被 API 或 dashboard 真读。

## 执行结果（已完成）

指标面（净 +172）：
- `EKB.quality_snapshot()` 是经验族读数的**唯一算式来源**：`rows` /
  `unevidenced_ratio` / `hit_rate` / `adoption_decisions` / `adoption_success_rate` /
  `adoption_unevidenced`。两个"空"的方向刻意不同：空库 `unevidenced_ratio=0.0`
  配 `rows=0` 是"没数据可判"，`adoption_success_rate=None` 是"分母为零"——
  把 None 兜成 0.0 就是把"没测到"读成"全失败"。
- 形成侧第三态升成一等列 `evidence_state`（`_migrate_schema` 加列 + 存量行按
  002 的 `tags` 标记回填），`add_experience_record(evidence=...)` 写入；
  `post_chat_pipeline` 改传 `evidence=tool_success`，`tags=["unevidenced"]` 的
  字符串 hack 退役（002 的那条用例随之改写为断言列 + 断言 hack 不再存在）。
  合并路径（011）里 `evidence_state` 只升不降：同键后来带来客观回执 ⇒ 升级，
  反向不得把已确证的行改回无证据。
- 指标名进 `RSIMetrics`（5 个 `experience_*`），阈值进同一张
  `ALERT_THRESHOLDS`：`unevidenced_ratio ≥ 0.5` 且 `rows > 0` ⇒ WARNING；
  `adoption_success_rate < 0.5` 且 `decisions ≥ 2` ⇒ WARNING。
  最小决策数门槛是必需的——一次成败是噪声不是趋势。
- 写入方：`RSIOrchestrator._refresh_experience_metrics()` 在每轮迭代第 6 步搬运
  快照（只搬运不重算，算式一处）。库不可用时记 0 并告警，**不留旧值**——
  留旧值会被读成"质量没变化"。
- 读取方：`get_dashboard_data()["experience"]` + `RSIDashboard.get_overview()`
  的经验视图（只有指标没有视图 = 写了没人读，与本批在治的"定义了没人写"同形）。
- 反向锁（读数能动）：`test_adoption_moves_the_success_rate` 先采纳一条成功 ⇒ 1.0，
  再采纳一条失败 ⇒ 0.5，断言两次快照不同。
