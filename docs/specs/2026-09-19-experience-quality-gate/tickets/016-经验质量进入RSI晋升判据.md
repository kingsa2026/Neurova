# 016 · 经验质量读数进入阶段晋升判据

**Blocked by**: 008, 009

## 目标

有了可测指标（008）与可信基准（009），`crystallize_min_*` 的调参才有收敛语义；
否则 RSI 在调一个读数不明的旋钮。

## 涉及层

- [x] 逻辑层：经验质量读数进入 `rsi/deployment_controller.py` 的 `_REQUIRED_EVIDENCE`
  "按阶段声明必需性"形态（无读数即 `unevidenced`）
- [x] 逻辑层：`rsi/convergence_analyzer.py` 侧的供值点与"取不到就摘键"规则
- [x] 观测层：判据结论带 `basis`/`evidence`（沿用 `IterationCadence` 的措辞纪律）
- [x] 测试：三态判据用例 + 反向锁

## 验收标准

- 无经验质量读数 ⇒ 对应阶段晋升判 `unevidenced`，不得按通过处理
  （当前必红：该维度根本不存在）。
- 读数持续为负 ⇒ 硬否决晋升；读数缺失 ⇒ 只落 `unevidenced`（两者必须是不同态）。
- 反向锁：不得为此发明第二套三态表达 —— 一律复用 `gate_verdict.GateVerdict`（D5）。

### 1. 各阶段必证证据清单（`deployment_controller._REQUIRED_EVIDENCE`）

| phase | 晋升边 | 必证证据 | 无回滚天数门槛 |
|---|---|---|---|
| 0 | 观察 → 手动 | （无） | 0 |
| 1 | 手动 → 半自动 | `days_without_rollback` | 7 |
| 2 | 半自动 → 有条件自动 | `days_without_rollback`、`roi`、`convergence_status`、**`experience_quality`（本单新增）** | 7 |
| 3 | 有条件自动 → 全自动 | 同 phase 2 四项 | 30 |

phase 0/1 刻意不要求：那两档不自动执行任何东西，为它锁死晋升链就是 008 拆过的循环依赖；
`test_phase_one_to_two_still_requires_rollback_days` 钉着的现有契约也不得因本单变红。
由 `test_phases_below_semi_auto_are_not_blocked_by_it` 反向钉住（不要求 ≠ 不否决，见下）。

供值链（判据面零重算，票面"取不到就摘键"的落点）：
`EKB.quality_snapshot()` →（`RSIOrchestrator._refresh_experience_metrics()` 每轮搬运）
→ `RSIMetrics` 规范指标 → **`RSIMetrics.experience_quality_readout()`（本单新增的唯一供值口）**
→ `run_iteration` 第 9 步写入 `phase_metrics["experience_quality"]` → 判据。
整个读数不摘键（与 `roi`/`days` 不同）：键在而字段为 `None` 才区分得出"库是空的"与
"有库但没人采纳过"，这两种无据的运维动作相反（前者要先有采纳回写，后者要先让经验被注入过）。

三条语义铁门：
- `adoption_success_rate=None`（分母为零）在指标面是 float、只能存 0.0，供值口按 008 的
  最小决策数把它**还原**成 `None` ⇒ `unevidenced`。直接吃 0.0 就是把"没测到"读成
  "照经验做全都失败"。
- `rows=0` 时 `unevidenced_ratio=0.0` 是"没数据可判"⇒ `unevidenced`，不读成"质量完美"。
- 有读数且低于门槛 ⇒ **硬否决**（`failed`），与"此阶段是否要求该读数"无关
  （与 `diverging`、负 `roi`、天数未达标同族）。

阈值不新增、也不另立第二份：判据与 008 的告警共用 `RSIMetrics.ALERT_THRESHOLDS`
的既有两键（`experience_adoption_success_rate_warning`=0.5、
`experience_adoption_min_decisions`=2），且在**决策时刻**读而非构造期快照（015 的教训）。
不新增 governance 键的理由：为同一个量再配一份阈值就是两份数，正是本票要防的漂移；
"无据把晋升卡住"的逃生阀已经存在——阶段本身可由治理设置 `rsi_phase` 人工写入
（`create_deployment_controller_with_settings`），再加一个"跳过经验质量判据"的开关
等于把必需性表做成可关的，那是 004/015 一路在收口的东西。
`unevidenced_ratio` 也刻意**没有**做成晋升门槛：它是"证据覆盖面"的量（008 的告警位），
拿它否决会把"覆盖面不足"与"质量差"压成同一个动作，且需要一个新数。

### 3. 三态实测例（实现后，phase 2，其余三道读数固定为满足）

```
无据(空库)     state=unevidenced bool=False reason=experience_quality 缺失：经验库没有条目，
                                        质量读数无从判断（空库读数为 0 不等于质量完美）
无据(零采纳)    state=unevidenced bool=False reason=experience_quality 缺失：5 条经验的采纳决策
                                        仅 0 次，样本不足以下质量结论
质差          state=failed      bool=False reason=经验采纳后成功率 0.20 低于晋升门槛 0.50，
                                        照经验做在帮倒忙（采纳决策 5 次）
质好          state=passed      bool=True  reason=phase 2 晋升判据全部有证据且满足
```

`bool()` 只在 passed 为真 ⇒ 无据既不被当成通过，也不与被否决混淆（前两行 state 相同、
与第三行不同态）。端到端一对：同一条 22 轮链路，EKB 有 3 条采纳成功回写 ⇒ `phase==3`，
空库 ⇒ `phase==2` 且 `phase_verdict.reason` 点名 `experience_quality`。
