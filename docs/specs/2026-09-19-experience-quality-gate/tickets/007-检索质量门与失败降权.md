# 007 · 检索按质量截断，失败经验不得与成功经验同权重

**Blocked by**: 006

## 目标

让"质量"真的参与被注入的决策。今天的门是布尔的，且唯一的质量位在相似度里只占 10%
—— 而它在 002 之前恒为 1，等于没有门。

## 涉及层

- [x] 逻辑层：`experience_knowledge_base.py:436` 相关性门
  `if keyword_score > 0 or topic_score > 0` ⇒ 最低分数阈值
  （`:432` 的 `0.6/0.3/0.1` 权重与 `similarity_score` 现在算完没人读）
- [x] 逻辑层：排序纳入 006 的采纳后证据与命中次数（`:336` 现为写入序 `ORDER BY id DESC`）
- [x] 注入层：`chat_pipeline.py:1839-1846`（失败仅加 `✗` 前缀）与
  `context/orchestrator.py:645-653`（priority 硬编码 70/80，与条目质量无关）
- [x] 测试：检索接缝的入参出参断言

## 验收标准

- 同 query 下，采纳后证据为负的条目必须排在证据为正者之后或被截断（当前必红）。
- 单 token 重叠不得入选：构造只共一个虚词的查询 ⇒ 命中 0 条。
- 反向锁：阈值不得高到"永远查不到经验"——保留一条"高质量条目仍被注入"的正例。
- `unevidenced` 条目（D1）可见但降权：既不消失，也不与确证条目同权。

## 净 LOC

预期接近 0（门的表达式与排序键替换）。

## 执行结果（已完成）

- 门从布尔改成带阈值的分数门：`relevance = 0.6*keyword + 0.3*topic`，
  `relevance < min_relevance`（默认 0.15）直接出局。**门只看相关性**，质量分不得替
  无关条目买路（旧形态 `keyword_score > 0 or topic_score > 0` 让"只共一个 2-gram"
  的查询也算命中；P2-B4 收口时只堵了分词，没堵这个洞）。
  阈值取 0.15 的实测依据：真实相关查询 relevance=0.6，单实词片重叠 relevance=0.06，
  两成重叠 0.12 —— 0.15 落在"沾边"与"相关"之间，且 `min_relevance` 是形参（可拨）。
- 采纳后证据进排序：`success +0.15 / NULL→形成侧 success ±0.1|−0.05 / unevidenced +0.03 /
  failure −0.25`。D1：全部降权而非剔除——"照这条做砸了"仍要能被查到。
- 注入侧优先级不再硬编码：`dedupe_experience_sources` 按 `adoption_outcome`
  给 78/70/65/55，证据缺席回落基线 70（没测到既不升权也不凭空降权）；
  结晶产物 80 基准不动（其生命周期归 017）。
  `chat_pipeline._retrieve_ekb_experience` 随之把 `adoption_outcome`/`similarity_score`
  带进 `ctx.experience_items`——证据没带到消费方，优先级就永远只会读成基线。
- `✗` 前缀保留（那是给人看的标记），但它不再是唯一处置：同一条现在还会排在后面、
  以更低优先级进池。
- 登记（本票不改）：`get_experience_records` 仍是写入序 `ORDER BY id DESC`。
  它是运营页的浏览序（015 的处置面），把"最新"改成"按证据"会让新入库条目沉到底、
  运营看不见——排序口径归 015 一并定。
- 测试：`tests/unit/skills/test_ekb_retrieval_quality_gate.py`（8 条：单 token 重叠出局 /
  真实相关仍命中（反向锁）/ 阈值可拨（旋钮微分）/ A>D>C>B 的证据序 /
  failure 不被抹掉 / 分数与顺序自洽）+
  `tests/unit/context/test_experience_injection_priority.py`（6 条：三档优先级关系、
  缺字段回落基线、结晶 80 不动、去重仍保结晶副本）。
- 净 LOC：生产 +44（EKB 分数与门 +27、orchestrator 优先级 +14、chat_pipeline 带证据 +3）。
