# 005 · 候选不得自喂成功票，也不得绕过裁决入库

**Blocked by**: 004

## 目标

两件事同属"候选生命周期"这一条路径，合一张做：① 结晶成功这一动作不得冒充任务成功；
② LLM 裁决闸缺席时不得直写、超龄不得自动放行（D3）。

## 涉及层

- [x] 逻辑层：`pattern_crystallizer.py:305-311` 的 `record_experience(..., True, ...)`
  改为独立事件（不进入任何 `success_rate` 分子）
- [x] 逻辑层：`:264-271` judge 缺席 ⇒ 留队 + 计数，不再 `_store_candidate`
- [x] 逻辑层：`:332-341` `_prune_expired_pending` 的"超龄自动放行" ⇒ 改降置信/丢弃并计数
- [x] 逻辑层：`:329-330` 时间戳解析失败返回 `0.0` ⇒ 落"无证据"，
  不得既不过期也永不被裁决
- [x] 观测层：闸缺席计数与超龄丢弃数可查（供 008 消费）
- [x] 测试：单元

## 验收标准

- 连续结晶 N 次 ⇒ 任何关联的 `success_rate` 不因结晶本身上升。
- 无 judge ⇒ 零入库且缺席计数可见（当前必红：首批候选必直写）。
- 超龄候选 ⇒ 不得出现在库里，丢弃数可查。
- 反向锁（D3 翻案预案）：若改"直写但标 unevidenced"，该条目必须被 007 降权，
  不得以"已入库"混过观察面 —— 两版都要有对应断言。
- 队列上限（`:266` `del self._pending[:-20]` 静默丢最旧）必须计数可见，不得静默丢。

## 执行结果（已完成）

- 自喂票断掉：`_store_candidate` 原来调 `facade.record_experience(..., True, ...)`
  ——候选入库即给自己投一张成功票，`success_rate` 恒 1。改为
  `facade.notify_pattern_crystallized(...)`，`closed_loop.on_pattern_crystallized`
  只触发 RSI 节流路径，不产生任何票。
- 绕过裁决断掉（D3）：闸开但 judge 缺席时不再直写，一律入队等裁决
  （`_enqueue_candidate` / `_enforce_pending_bound`）。
- 超龄处置改向：`_prune_expired_pending` 原来"超 48h 自动放行"＝绕过裁决入库，
  现改为丢弃 + `pending_dropped` 计数；`_max_pending = 20` 上界，溢出计入同一读数
  ——留队不再无界，且"被丢了"看得见。
- `_candidate_age_hours` 对不可解析时间戳返回 None（当作"计时不可信"参与丢弃判定），
  不再按 0 小时算年轻。
- 受影响旧契约重写（不删）：`test_improvement_items_g2g3.py`、
  `test_crystallization_llm_gate.py`、`test_loop_review_residuals.py`、
  `test_experience_loop_fractures.py` —— 两条 e2e 现在显式
  `crystallizer.confirm_pending([...])`，并注："规则预筛通过 ≠ 入库，
  候选还要过 LLM 可复用性裁决"。
- 断言可判别性：005 之后 `engine.stored == []` 不再能区分"被拦"与"在排队"，
  改用 `_candidate_blocked` / `_passed_prescreen`（读 `list_pending()`）。
