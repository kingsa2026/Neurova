## 通用纪律（每张工单适用）

1. **红绿灯先行**：先写断言缺陷的失败测试，红 → 绿 → 重构。测试落
   `tests/unit/evolution/experience/`、`tests/integration/`；不得放 `tests/` 根目录。
2. **禁止 consumer-only guard**：不得在调用方/展示层加判空、吞异常、兜底默认来消除报错。
3. **放大视角**：每张票点名的契约错位须 grep 同契约全部消费方一并修，或在本索引登记。
4. **禁止的测试写法**（就是本轮缺陷的藏身形态，违反即判未完成）：
   - 不许用 `MagicMock` 冒充工具消息或闭环系统 —— `MagicMock().get("success", True)` 恒真，
     这正是 G1 藏身三个月的原因。工具消息必须用 `agent/loops/base.py` 的真实记录字典形态。
   - 不许在测试内手工传阈值/手工传 `agent_id` 绕过生产装配点（对照反思链 B 的教训：
     绿灯覆盖契约却漏掉布线）。004 必须证明"从参数事实源改起"才生效。
   - 不许写恒真断言（`outcome in {success,failure,partial}` 这类，
     `test_experience_feedback.py:57,66,75` 现状）。每条验收都要给一个会让判据变红的反例。
   - 不许"库里能查到一行"代替"判据咬合"。
5. **净 LOC ≤ 0 默认**（004-017 允许为正，须列明超出去向；测试代码不计入）。
6. **写验证一律走临时 EKB 库**（`NEUROVA_EKB_DB` 覆盖，
   `experience_knowledge_base.py:43-46`）。`data/experience_knowledge.db` 是生产运行数据，
   只允许只读复核。
7. **CI 清单登记时机**：`scripts/ci/protected_tests.txt` 只收"逐文件单跑确定全绿"的文件；
   含刻意红灯的测试文件在转绿前不得进清单。009 的门禁脚本自身不进清单。
8. **提交**：`agent_core.py` 尺寸棘轮（基线 2159 行，净增即红，history 单调）继续有效；
   新增装配逻辑一律落独立模块。本仓提交用 `git commit --only -- <paths>`，
   工作树含并发工作流的在途改动，严禁 `git add -A`。
