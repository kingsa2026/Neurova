# 014 · min_confidence 是闸，不是提示

**Blocked by**: 001

## 目标

`nl_synthesizer.py:250-258` 在置信度低于阈值时只 `warnings.append`，随后无条件
`stage = COMPLETED` + `success = True`；调用方 `chat_pipeline.py:1088-1090` 只看
`success` 与 `stage` ⇒ 这道门不存在。

## 涉及层

- [x] 逻辑层：低置信 ⇒ 不得 `COMPLETED`/`success=True`，改落显式失败或"待人工"
- [x] 逻辑层：调用方判据同步收紧（`chat_pipeline.py:1088-1090`）
- [x] 观测层：低置信被拦计数进 008 指标（指标面未就绪前先落日志）
- [x] 测试：单元

## 验收标准

- 置信度低于 `min_confidence`（`:138` 默认 0.3）⇒ 产物不得进注册路径（当前必红）。
- 反向锁：略高于阈值的产物仍须通过（不得靠抬阈值交差）。
- `warnings` 保留为信息位，但不得是唯一处置。

## 净 LOC

预期接近 0。

## 执行结果（已完成）

- 闸有后果：低置信不再只 `warnings.append` 后无条件 `COMPLETED` + `success=True`。
  新增 `SynthesisStage.PENDING_REVIEW`，拦下时 `success=False` +
  `error_message="置信度 x.xx 低于阈值 y.yy，转人工复核"`，产物仍挂在
  `synthesized_tool` 上（拦 ≠ 丢，人工复核要能看到它），`warnings` 降为信息位。
- 闸可触发（第二处根因，不做就仍是半截活）：默认阈值 0.3 落在估器可达区间之下——
  `estimate_confidence` 对任何非空描述都有 ≈0.45 下界（分类 general 也给 5 分、
  序列只要非空就满 25 分），实测样本 0.45 / 0.5 / 0.65 / 0.7，配 0.3 时低置信分支
  永不触发。默认值抬到 0.5 并写明是"让门可达"而非"收紧口径"。
- 可观测：`low_confidence_rejections` 计数（008 指标面就绪前的落点）+ WARNING 日志。
- 调用方判据同步收紧（`chat_pipeline._check_nl_synthesis`）：产物存在但
  `success and stage is COMPLETED` 不成立 ⇒ 不注册且 INFO 留痕。
  这同时补掉旧实现的一个静默洞：`success=True` 而 stage 非 COMPLETED 时原先什么都不发生、
  也什么都不说。
- 测试：`tests/unit/evolution/test_nl_confidence_gate.py`（5 条：低置信不落 COMPLETED
  且 success=False / 产物仍在 / 反向锁——0.65 的清晰描述照常放行且 `warnings==[]` /
  旋钮微分：阈值调到实测置信度之下同一描述必须放行，证明门吃参数不是硬编码 /
  消费者负例配正例对照：过闸产物确实进入 `_register_synthesized_tool`）。
  先红证据：首轮 `test_low_confidence_product_is_not_completed` 红在前提断言
  （"0.45 并不低于默认阈值 0.3"），正是可触发性的缺口。
- 登记给度量面（008/009 家族）：`estimate_confidence` 的"序列只要非空即满 25 分"
  是置信度虚高的根因（"帮我处理 xyzzy frobnicate widget" 能拿 0.9），属"质量本身
  无可测定义"一条，本票不改打分公式——一次性把注册率打没不是修复。
- 净 LOC：生产 +24（闸分支 15、消费者守卫 9）；无可删旧分支（原实现只有一句
  `warnings.append`）。
