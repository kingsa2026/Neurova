## 判据设计（本单的核心）

**两轴分离**是本单成立的先决条件：

- **判据类**（机器算，四值）：`absent` / `no_consumer` / `self_loop` / `consumed`。
  台账照抄，不一致即报红——若三态也能人填，论证就退化成自述。
- **处置**（人填，有限枚举）：`待处置` / `已接线` / `已删除` / `收口第二份`。

判据只算 **1 跳**，刻意不做传递可达性分析：那需要类型推断与调用图，静态近似必然误判。
「1 跳可达但其消费方自身不可达」（`build_system_prompt` 被零消费的 `ContextFacade` 调用
即此形态）写在**依据**里逐条论证——这正是审计要求「单独论证」的落点。

## 验收标准

- 20 个登记符号各有台账条目，判据类与机器算出的值一致，依据非空。
- 反向控制：`draw` / `archiveBatch` 必须报 `consumed` 且永远「待处置」。
- 守卫单跑在数秒量级（不得撞 pytest-timeout 的 30s 墙钟）。
- 负向控制三项各实证转红：篡改判据列 / 反向控制项被赋处置 / 依据留空。

### 实施期确立的两条判据细则

1. **孤立 `import` 不算消费**。`from x import Y` 只是把名字带进文件；若该文件再无 Y 的
   调用/读取，那是**再导出**（`context_pool.py` 把 `ContextPoolUtils` 提进 `__all__` 即此形态）。
   判据：同文件内除 `import` 外还有其它形态引用，该 import 才算消费点。
2. **`absent` 说的是「无定义」，不是「零引用」**。`get_context_pool` 有 import 与调用
   （引用数 2），但符号本身不存在——正是 P2-1 的形态。若把「有引用」当成「符号存在」，
   P2-1 会永远被判成可达。守卫里有一条用例专门钉这个区分。
