# Agent × Ontology 知识库检索与推荐精准度全面升级方案（统一版）

> 定位：本文整合检索精准度分析（三桥）、方案推荐场景、假发推荐场景、**餐饮智能客服场景**四份分析，给出**一份**覆盖全部已识别场景的统一改进方案。
> 事实源：`neurova/agent/chat_pipeline.py`、`knowledge_retriever_adapter.py`、`hybrid.py`、`derivation_citation.py`、`context/injector.py`、`foundation/knowledge_facts.py`、本体栈升级计划（B1–B14 已落格 v29–v34）。
> 前序分析（并入本文后退役）：`2026-11-06-ontology-retrieval-precision-plan.md`、`2026-11-06-ontology-scenario-trace-planB.md`、`2026-11-06-ontology-scenario-temporal-preference.md`、`2026-11-07-ontology-intelligent-recommendation-unified.md`。

## §0 一页结论

**Agent 检索本体知识库"能找到"但"找不准、不会推、不知为何推"。**

根因不在本体语义栈本身——B8–B14 落格后，写面已完备（类型层级/关系特征/条件类/qualifier schema/双时态/推导账本/形状校验）。根因在**从用户问题到 LLM 上下文之间缺了六层能力**，导致本体的语义能力只在写入时生效（校验/物化），读取时仍然是"纯文本相似度 + 扁平列表 + 无时间信号 + 无偏好约束推理"。

**六层缺失 → 六层改进 → 四个场景全部覆盖。**

| 层 | 缺什么 | 解决什么 | 核心改动 |
|---|---|---|---|
| L-A 语义桥 | 用户语言→本体术语的映射 | 别名/异写/条件类/类型层级对查询词零影响 | 开闸默认关＋新增查询扩展模块 |
| L-B 检索策略 | 数值比较/多跳遍历/最新偏好 | "400M 的方案""最新的购买""关联的客户"走不通 | 数值过滤＋关系遍历＋latest-per-subject |
| L-C 时间维度 | 无时间衰减/无时序排序/无时间透传 | 过期偏好与当前偏好同分并列 | recency 权重＋payload 时间戳＋时间线注入 |
| L-D 注入结构 | LLM 收到扁平文本不是结构化视图 | 推导标注/类型层级/qualifier/双时态在管道里丢失 | 上下文构建器按本体结构组织 |
| L-E 反馈环 | 用户纠正不回流到检索 | 检索 miss 持续 miss | 纠正→候选→审批→命中闭环 |
| **L-F 约束推理与推荐** | **偏好约束不提取＋产品属性不结构化＋无约束过滤排序** | **"海鲜过敏推了含海鲜的""价格偏高推了更贵的"** | **偏好提取＋产品目录＋约束过滤＋排序＋理由** |

### §1.2 S4 场景详述

**数据**：
- 套餐A：含海鲜，¥400，中式
- 套餐B：无海鲜，¥400
- 套餐C：无海鲜，¥300

**客户历史**：
- 8月10日：购买套餐A
- 8月15日：**差评**——"A套餐中有海鲜，自己海鲜过敏，而且套餐A价格偏高"

**问题**：9月1日客户再次光顾，Agent 该推荐什么？

**正确答案：套餐C**（¥300，无海鲜）——同时满足两个约束：
1. 硬约束（健康安全）：海鲜过敏 → 排除含海鲜的套餐A
2. 软偏好（预算）：价格偏高 → 套餐C（¥300）优于套餐B（¥400）

### §3.4 L1 数据结构化（写入面）

**目标**：产品/客户/反馈全部结构化为可查询的本体事实。

| # | 改进 | 数据形状 | 落点 | 红灯判据 |
|---|---|---|---|---|
| D-1a | **产品属性结构化** | `(套餐A, has_seafood, "true")`、`(套餐A, price, "400")` | 抽取 prompt 扩展＋B8 候选 | 产品属性在库可按谓词查 |
| D-1b | **产品关系结构化** | `(套餐B, derived_from, 套餐A)` | B8 候选面审批 | 继承关系在库 |
| D-1c | **客户购买记录** | `(客户X, purchased, 套餐A)` + valid_from | 对话/订单抽取 | 购买事实在库 |
| D-1d | **客户偏好约束（从反馈学习）** | `(客户X, has_dietary_restriction, "no_seafood")` + valid_from | **新模块** `preference_extractor.py` | 差评文本→约束事实落库 |

### §3.5 L-F 约束推理与推荐（新增层，解决 RC-5/RC-6）

**目标**：给定客户偏好约束（从反馈中学到的），在产品目录中过滤兼容产品、按偏好排序、输出带理由的推荐。

#### §3.5.1 偏好约束提取（RC-5a）

| # | 改进 | 说明 |
|---|---|---|
| F-1 | **反馈→偏好提取**（新模块 `preference_extractor.py`）：LLM 分析反馈文本→识别两类信号→映射为本体关系事实 | "海鲜过敏"→硬约束 `has_seafood ≠ true`；"价格偏高"→软偏好 `price < 400` |
| F-2 | **偏好事实落库**：约束作为结构化事实经咽喉落库，带 valid_from（偏好有时效性） | `(客户X, has_dietary_restriction, "no_seafood")` valid_from=差评日期 |
| F-3 | **偏好画像构建**：按客户聚合全部偏好约束→`CustomerPreferenceProfile` | 硬约束（违反即排除）＋软偏好（违反降权） |

#### §3.5.2 产品目录结构化（RC-5b）

| # | 改进 | 说明 |
|---|---|---|
| F-4 | **产品属性事实**：产品/套餐的属性（has_seafood/price/cuisine_type）作为结构化事实经咽喉落库 | `(套餐A, has_seafood, "true")`、`(套餐C, price, "300")` |
| F-5 | **产品目录读取**：按类型（Plan）取全部产品实例＋属性 | `activeFactsForPredicate` 已有 |

#### §3.5.3 约束推理与推荐（RC-6a/RC-6b）

| # | 改进 | 说明 |
|---|---|---|
| F-6 | **硬约束过滤**：偏好画像的硬约束→逐产品检查属性事实→违反即排除 | `has_seafood=true` 违反 `no_seafood` → 排除套餐A |
| F-7 | **软偏好排序**：软偏好→打分排序（价格低者得分高） | `price_sensitivity=high` → 套餐C(¥300) > 套餐B(¥400) |
| F-8 | **推荐理由生成**：每条推荐附 `rationale`（满足了哪些约束/违反了哪些软偏好） | "无海鲜匹配过敏限制＋价格最低" |

**落点**：`neurova/knowledge/ontology/recommender.py`（新模块）＋`preference_extractor.py`（新模块）。

**核心数据结构**：

```python
@dataclass
class CustomerPreferenceProfile:
    customerId: str
    hardConstraints: List[Constraint]    # 违反即排除
    softPreferences: List[Constraint]    # 违反降权
    validFrom: str

@dataclass
class Constraint:
    attribute: str       # 本体关系术语
    operator: str        # == != > < >= <=
    value: str
    priority: str        # hard / soft

@dataclass
class ProductRecommendation:
    productId: str
    score: float
    rank: int
    matchedConstraints: List[str]
    violatedSoftPreferences: List[str]
    rationale: str
```

### §4.4 S4 餐饮智能客服（偏好学习＋约束过滤＋排序）——核心新增

> 套餐A（海鲜¥400）/B（无海鲜¥400）/C（无海鲜¥300）；客户 8/10 买A → 8/15 差评（海鲜过敏＋价格偏高）→ 9/1 再光顾。

| 维度 | 改进前 | 改进后 | 驱动层 |
|---|---|---|---|
| 推荐套餐 | ⭐ 可能推 A（**含海鲜！客户过敏！**） | ⭐⭐⭐⭐⭐ C（约束过滤确定性排除 A，价格排序 C > B） | L-F F-6/F-7 |

| 排除说明 | 无 | ⭐⭐⭐⭐ "套餐A含海鲜，不建议" | L-F F-6 |
| 偏好学习 | ⭐ 差评只是文本 | ⭐⭐⭐⭐⭐ 差评→约束事实落库→下次自动过滤 | L1 D-1d＋L-F F-1/F-2 |

**改进前后回答对比**：

改进前：
> "我们有套餐A、B、C可供选择……"（**可能推荐A——含海鲜，客户过敏！**）

改进后：
> "根据您之前的反馈，推荐**套餐C**（¥300，无海鲜）。
> 推荐理由：您之前反馈对海鲜过敏，套餐C不含海鲜；同时价格300元低于您之前反馈偏高的400元。
> 套餐B（¥400，无海鲜）也可选，但价格较高。**套餐A含海鲜，不建议。**"
