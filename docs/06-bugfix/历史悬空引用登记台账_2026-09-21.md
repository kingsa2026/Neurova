## 一、根因

归档层里的失效引用**不是「没人写文档」**，而是**「写了但被删掉」**：

清理批次 `663faa5d`（第三方借鉴痕迹清除波）与 `5f94b93d`（文档目录重排）在改写历史文档时，
把带具体目标的引用**直接删空**——`docs/INDEX.md` 变成 `` ` ` ``，`docs/architecture/OVERVIEW.md`
连文字一起删掉。这正是 `AGENTS.md` 修复教义第 2 条禁止的**「用抹除代替修复」**：
报错表面没了，信息本体也没了，且没有任何记录说明被删掉了什么。

因此本单的判据是**「能不能指认被删掉的东西去哪了」**。能指认 → 该还原就还原；
不能指认（目标确实已废弃）→ 以显式文本交代去处，不得继续留空。

  "生成 → 计数变化 → 再生成"的自引用死循环。

## 二、判定口径

扫描器对每条引用给出**四类判定之一**，不允许留空、留「待定」：

| 判定 | 含义 | 处置 |
|------|------|------|
| **迁移可达** | 目标已不在原位，但在仓库内**唯一命中**（同后缀路径或全仓唯一同名） | 路径过期，非内容缺失。按命中路径还原即可，零信息风险 |
| **同名歧义** | 全仓存在**多个同名候选**（典型：`docs/X.md` 与 `docs/<领域>/X.md` 并存） | 须按上下文人工裁定指向哪一个；**不得随机选取**——选错等于制造新错误 |
| **源已删除** | 全仓**零命中** | 目标确实不存在。须交代去向（合并进哪篇 / 随哪批退役），改成纯文本，不留空标签 |
| **空标签悬空** | `[文字]()` 空目标 / 空反引号 | 「用清空代替修复」的产物。须从 git 历史回收**前像**，逐条判定前像可达性（见第四节） |

判定由 `scripts/scan_docs_refs.py::resolveTarget` 统一产出；守卫只做「重算 + 比对」，
不复制判据——**一份口径，不在台账与守门之间造第二份**。

## 五、其余三类的处置要点

### 迁移可达（66 条，零信息风险，可批量还原）

目标都在，只是路径过期。典型：

- `neurova/agent/tool_executor.py` → `neurova/tool_executor.py`（模块上提）
- `memory_layer/muscle_memory.py` → `neurova/cognitive_layers/memory_layer/muscle_memory.py`
- `tests/unit/test_crystallized_experience_manager.py` → `tests/unit/agent/...`（测试按模块归档）
- `api/agents.ts` → `NeurUI/src/stores/agents.ts`（前端目录重排）

这一类的批量还原**不属于本单**：归档层文档的正文陈述的是**当时**的代码结构，
把路径改成今天的形态会让「历史记录」与「历史事实」不一致。故本类仅登记，
**在需要引用归档结论时才按命中路径还原**。

### 同名歧义（97 条，须人工裁定）

`docs/` 下存在大量「扁平文件 + 领域子目录同名」的并存形态
（`docs/PRODUCT_GUIDE.md` 与 `docs/03-user-guide/PRODUCT_GUIDE.md`），
所以仅凭文件名**无法**判定该指向哪一个。**不得随机选取**——选错就是制造新错误。

裁定时以 `docs/INDEX.md` 的领域归属表为准（它是文档体系唯一导航事实源）；
若两处内容确实重复，应先按修复教义第 6 条**收口为一份**再定引用。

### 源已删除（45 条）

目标全仓零命中。多为随批次退役的设计稿与临时脚本，例如
`UI开发计划.md` / `TokenConsumptionChart.vue`（UI 方案演进中作废的组件清单）、
`test_jwt_fix.py` / `fix_jwt_import.py`（一次性验证脚本，按「临时脚本即用即删」纪律已清理）。

**Issue #74 新增 5 条**：`memory_layer/{schema,semantic_edge_filter,coreference_resolver,

不是把洞改写成已修复。

## 六、销账流程

1. 修完一项 → 源文件里不再悬空；
2. 重跑 `python scripts/scan_docs_refs.py --markdown` 刷新第三节表格；
3. 若改动涉及空标签，同步更新第四节前像表；
4. 守卫 `tests/unit/test_legacy_ref_ledger_guard.py` 会重算比对——**改台账不代替改事实**，
   源文件里的洞还在却把台账记成已修复，会直接红。

> 本表为**登记台账**：`迁移可达` / `同名歧义` / `源已删除` 三类的量在数千级，
> 不承诺在某个时间点清零——它们多数是**历史归档的正常形态**（旧路径、同名并存），
> 清零本身会破坏可追溯性。承诺的是**没有一条被静默遗留**：每条都有判定、
> 有处置口径、有常驻守卫。
>
> **唯一例外是 `空标签悬空`**：它不是"路径过期"，而是**引用被删成了空白**，
> 属修复教义第 2 条明令禁止的形态，没有"保留原样"的余地。故这一类已全仓归零
> （见第一节「本单实现层」），并由基线棘轮防回潮——台账不再只登记，而是**修完**。
