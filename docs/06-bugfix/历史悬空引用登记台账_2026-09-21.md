## 一、根因

归档层里的失效引用**不是「没人写文档」**，而是**「写了但被删掉」**：

清理批次 `663faa5d`（第三方借鉴痕迹清除波）与 `5f94b93d`（文档目录重排）在改写历史文档时，
把带具体目标的引用**直接删空**——`docs/INDEX.md` 变成 `` ` ` ``，`docs/architecture/OVERVIEW.md`
连文字一起删掉。这正是 `AGENTS.md` 修复教义第 2 条禁止的**「用抹除代替修复」**：
报错表面没了，信息本体也没了，且没有任何记录说明被删掉了什么。

因此本单的判据是**「能不能指认被删掉的东西去哪了」**。能指认 → 该还原就还原；
不能指认（目标确实已废弃）→ 以显式文本交代去处，不得继续留空。

### 本单实现层：抹除形态已全仓归零

登记台账不代替修事实。除登记之外，本单把**抹除形态**（第 2 条明确禁止的形态）
按引入批次的前像**全仓修完**：

- 全仓实测 **372 处 / 123 文件**（`docs/` 366 + `README.md` 1 + `audit-reports/final-report.md` 5）；
- 内联引用按"骨架一致 + 逐位填回内容"还原 **352 处**，链接目标还原 **15 处**；
- 前像已退役或从未入库的 **3 处**改显式文本并注明去向，不还原为死链；
- 修后全仓抹除形态 **0 处**，由本台账的常驻守卫
  （`tests/unit/test_legacy_ref_ledger_guard.py` 的棘轮用例 + `tests/unit/docsErasureBaseline.txt`）
  防回潮——只降不升。

入档扫描口径随之收紧（同一份 `scripts/scan_docs_refs.py`，非第二套判据）：

- **台账的定位改为内容锚点，不再是源文档行号**。行号是「扫描那一刻这份文档的属性」，
  而台账是入库的生成物：归档层被后续批次改过分节（`e6fec939` 退役闭环链时即改过），
  行号整片平移，台账与扫描器逐格失配——CI 构建 `cnb-1f0-1k5uonjt2-003` 的
  「期望行数 218，实际行数 228」正是这个形态，被引用的路径一条没变，变的只是它们
  落在第几行。现在「位置」列取 `本行·<行正文+引用原文的摘要>`，于是**补一节不再动
  台账，改掉一条引用照样会动**；上游文档合并（`docs/05-reports/` 追一篇审计）也会
  让台账漂移，那是真漂移，该重新生成。判据 `tests/unit/ci/test_scanDocsRefsLedgerAnchors.py`
  把两头都钉住：行号平移 → 机器区逐字节不变；引用变化 → 机器区必变。

- 行内代码按 CommonMark 反引号 run 配对判定——`` `行内码` `` 这类
  "内容里含反引号"的合法写法**不再误报**为空引用（此前误报 2 处，且会成批出现）；
  真正被删空的引用（孤立 run）照样报出，不漏报；
- 引用块内嵌的代码围栏（`> ```python`）与顶格围栏同样剥除，
  不再把围栏本身读成空引用；
- 台账类文档（把空引用当**数据**逐条列举者）在扫描时排除，避免
  "生成 → 计数变化 → 再生成"的自引用死循环。

## 二、判定口径

扫描器对每条引用给出**四类判定之一**，不允许留空、留「待定」：

| 判定 | 含义 | 处置 |
|------|------|------|
| **迁移可达** | 目标已不在原位，但在仓库内**唯一命中**（同后缀路径或全仓唯一同名） | 路径过期，非内容缺失。按命中路径还原即可，零信息风险 |
| **同名歧义** | 全仓存在**多个同名候选**（典型：`docs/X.md` 与 `docs/<领域>/X.md` 并存） | 须按上下文人工裁定指向哪一个；**不得随机选取**——选错等于制造新错误 |
| **源已删除** | 全仓**零命中** | 目标确实不存在。须交代去向（合并进哪篇 / 随哪批退役），改成纯文本，不留空标签 |
| **空标签悬空** | `[文字]()` 空目标 / 空反引号 | 「用清空代替修复」的产物。须从 git 历史回收**前像**，逐条判定前像可达性（见第四节） |

判定由 `scripts/scan_docs_refs.py::resolveTarget` 统一产出；守卫只做「重算 + 比对」，
不复制判据——**一份口径，不在台账与守门之间造第二份**。

## 六、同名多份裁定（96 条逐条）

### 6.1 根因：目录重排被另一批次批量撤销

96 条 `同名歧义` 的源头**不是归档文档自己写错**，而是两批次互相抵消：

- 批次 `fd7ea92c`（文档目录分类重排）把 **358** 篇文档 `git mv` 进编号分层
  `docs/01-architecture/ … docs/11-legacy/`，旧路径在分层里成为唯一命中；
- 批次 `3b5d7e80`（一次与文档无关的功能提交，却**夹带 306 个 docs 文件**）把旧
  路径**原样还原**回来，同时又保留了分层里那份。

于是同一个 basename 在 `docs/` 根或 `docs/<旧目录>/` 与编号分层**各存一份**：
264 对里 **231 对逐字节相同**（纯冗余），**33 对内容分叉**（真出现两个版本，
各自还带着不同批次的增量）。后果不是"文档不好看"，而是**归档文档的引用失去唯一裁定**：
扫描器面对同一 basename 给出两个候选，只能标 `同名歧义`，人工无从判断该指哪一份。

### 6.2 裁定口径

**编号分层（`docs/<NN-领域>/`）是文档重排后的留存层**，非编号层的同 basename 文件
是回潮副本。故：

- **裁定目标** = 该 basename 在编号分层的唯一命中；
- 副本与保留侧**逐字节相同** → 纯冗余，删副本即消歧，零信息风险；
- 副本**另有真增量**（内容分叉的 33 对） → 先把增量并入保留侧，再删副本；
- 代码同名引用（`sleep.py` 等 11 条）→ 同 basename 在代码树天然多份，
  按每条归档文档的**上下文**逐条裁定，不套用"编号分层唯一命中"。

**排除项是具体路径，不是 basename**（判据里逐条写明理由，见
`scripts/scan_docs_refs.py::LAYER_OWNED_PATHS`）：`docs/README.md`（Neutesting 说明，
与 `docs/0-index/README.md` 不是同一篇）、`docs/INDEX.md`（现行导航事实源，
见 6.4.1）、两份目录级 `README.md`。按 basename 一刀切会放过
`docs/dev_progress/README.md` 这类**真副本**——本单第一版判据就踩过这个坑，
故收紧为路径白名单。

裁定由 `scripts/scan_docs_refs.py::adjudicatedRows` 统一产出，台账与守卫都从这里取数，
**一份口径，不在台账与守门之间造第二份**。

### 6.2.1 本单实现层：回潮副本已归零

裁定不代替修事实。除逐条登记之外，本单把**回潮副本**（第 6.1 节那 268 份非编号层副本）
按修复教义第 6 条**收口为一份**：

- **删除 271 份副本**（含 `docs/adr/` 整目录、`docs/architecture/` 41 份、
  `docs/dev_progress/` 74 份、`docs/memory/` 11 份、`docs/` 根 124 份等），
  每份都先确认编号分层存在同一篇；
- **33 对内容分叉的先并增量再删**——其中真正的实质增量 2 处已并入保留侧：
  `docs/01-architecture/09-context-processing.md` 补回归档侧独有的 §10.2
  「ContextPool 运行态指标（Issue #65）」；`docs/11-legacy/源码图谱.md` 按
  `07e793d6` 的代码实况修正 `cognitive_layers` 计数与已删死码清单。
  其余 31 处的差异全是**陈旧文本**（品牌名未换、版本号未更新、旧路径未改），
  保留侧本就是现行版本，无需并入。
- **56 个文件里的 135 处引用改指编号分层**（把 `dev_progress/` 段换成

## 八、归档层按「是否影响当下导航」再筛一轮（Ref: #68）

前三节（一至七）把归档层 1800 余条悬空引用**一视同仁**登记为「历史留痕，不就地改写」。
理由成立——归档正文陈述的是**当时**的代码结构与路径，改成今天的形态反而让历史记录
与历史事实不符。但这条口径有一个副作用：它把两类性质完全不同的东西混在了一起。

- 绝大多数条目所在的文档，**今天没有任何读者走得到**（不在导航图里）。改它等于改写历史；
- 少数条目所在的文档，**当下打开就能走到**（导航可达），其中可点击的引用**点开就 404**。
  这类不是「历史留痕」，是**当下把人带错路**。

不筛这一轮，口径只剩两个极端：全改（破坏可追溯性）或全不改（把当下的坏导航
当成历史正当形态）。本节把「是否影响当下导航」变成**可复算的判据**。

     与活跃层同一条纪律，不适用「归档层不就地改写」的豁免。
   - **乙·指路条目**：载体是**专职指路**的文档（`INDEX.md` / `README.md` 文件名，
     或标题写明「清单 / 索引 / 图谱 / 单一事实源」）。这类文档存在的意义就是把人
     指向别处，失效条目即使写成行内码也会把人带错；但**整篇级过期不是改路径
     能解决的**——故登记 + 单独立项。
   - **丙·行内码路径陈述**：导航可达的归档正文里写着的路径（`x/y.py`）今天不在了。
     读者把这个名字复制走同样落空，与甲类同属「当下把人带错路」，只是不可点击。
     处置是**登记不就地改写**（归档正文陈述的是当时的代码结构）——那是处置，不是
     豁免理由。

形态只决定**处置**，不决定入不入筛：把「入筛」再拆一条自造的豁免理由，曾让八百余条
导航可达载体里的失效行内码被记成「不构成当下导航问题」，摘要据此算出「本类已归零」。

**入账门槛（行内码先要「在表达仓库内位置」，才谈可达性）**：`scanFile` 此前把任意被反引号
包住、后缀又落在 `PATH_SUFFIXES` 里的字符串一律登记。`PATH_SUFFIXES` 含 `js` / `ts` / `json`，
于是**变量名、模块名、被提及的第三方脚本名**（平台侧校验器 `validate.js` 即一例）都被登记成
悬空引用，判定「源已删除」，台账数字随任一篇正文的举例漂移。判据收口为
`codeSpanNamesARepoLocation`：带目录分隔符（`context/fold_resolution.py`）或**全仓同名有命中**
才算路径引用；零命中的裸文件名是**叙述性提及**，不入账。判定与可达性解析仍只此一份。

**豁免两条（理由可复算，不接受「人工看过了没事」）**：载体不在导航图内（无当下读者）／
占位或模板路径（`daily_reports/YYYY-MM-DD.md`、`neurova/xxx/yyy.py` 不是真实目标）。
第三条「描述性行内码」已退役：那是**处置**（不就地改写）被写成了**理由**（不影响当下导航），
计数与摘要结论都由此推出，属于把结论当证据。
