## P0（必然触发 / 全站级故障）

### RES-P0-1 ✅主线复核 | `neurova/llm/multi_model_client.py:907-1063` | 流式成功/中断路径永不 release 并发槽位 → 8 次成功流式后该模型永久「限流」不可用

release 全文件仅 4 处，其中 3 处在非流式路径，唯一流式 release 在 `except Exception` 分支的 finally；**成功路径（908-1061）无任何 release**：

```python
            finally:
                _silence_task.cancel()          # 成功路径只收尸看门狗
                ...
            client.increment_request(success=True)
            limiter.report_success(model_key)   # 只清 429 暂停，不清并发计数
            ...
        except Exception as e:
            ...
            finally:
                if acquired:
                    limiter.release(model_key)  # release 只存在于异常分支
        else:
            _stream_ok = True                   # 死变量，佐证控制流断裂
```

- **git 实证**：d48a5c51 原版成功路径有 `limiter.release(model_key)`；df34c204（"BUG AUDIT L-03"）注释称「成功路径的重复 release 已移除」将其删除——**误删**。except 分支与成功路径分属不同控制流，并非重复。
- **触发条件**：每次成功的流式调用 +1 计数几乎永不归还；消费方中途放弃（客户端断开 → 生成器被 aclose）时 GeneratorExit 是 BaseException，绕过 `except Exception`，同样不 release。前端全走流式。
- **后果**：`ModelRateLimiter._concurrent[model]`（默认 max_concurrent=8）单调递增，**8 次成功/中断流式后** `acquire` 恒抛 `RateLimitExceeded`，该模型对所有用户返回「模型限流」直到重启进程；中断路径连 usage 记账一并跳过。
- **修复方向**：acquire 成功后用外层 `try/finally: if acquired: limiter.release(model_key)` 包住 chat_stream 全体（含 GeneratorExit）；删除死变量 `_stream_ok`。防回归用例：连续 9 次 mock 流式后仍可调用。

### RES-P0-2 ✅主线复核全链路 | `neurova/api/endpoints/channel_config.py:220,268` + `neurova/channels/wechat_auth.py:194-218` | 保存/测试 iLink 微信渠道时同步轮询最长 300 秒跑在事件循环上，全后端冻结

- 而丢弃消息的路径只清数组：`switchSession → store.clearMessages()`（useChat.ts:170，✅主线复核 `messages.value = []` 无 revoke）、切 Agent（ChatPage:2277）、`reset()`、`removeRoundFrom`——被丢弃的消息在卸载时已不在 `messages.value` 里，其 blob 永远收不回。
