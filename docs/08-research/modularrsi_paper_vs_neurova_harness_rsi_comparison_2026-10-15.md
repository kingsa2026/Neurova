## 0. 结论摘要

- **一句话画像**：论文的真实贡献不是"分数涨了 4.86pp"，而是**把演化对象摆到 harness 上，再用三条
  纪律证明涨的不是题感**——演化任务与评测基准**任务源不相交**、同一任务**成败对照**、
  五个 harness 模块**各自独立演化后再合并**（联合演化那一档消融是**掉的**）。
- **对照出的本仓主画像**：本仓在**判据与治理**这一侧不弱于论文（留出/真留出双集与"永不参与判定"
  的防自适应污染纪律 `eval/dataset.py:48-51`、三态判据、负债反向闸、五阶段门禁、人工评审主 gate）；
  **真正的空在演化对象的覆盖面**——`rsi/integration_manager.py:33-67` 的五族参数全是记忆/情感/
  上下文预算，**agent 循环与停止判定的门限一格都不在表里**（全目录 grep `max_rounds|doomLoop|
  maxContinuations|GoalGate` 零命中）。论文单项收益最大的恰是那一侧（Agent Loop +2.99pp、
  Observation Management 省约 35% 步数）。
- **最值得学的 3 条（M-A/M-C/M-D）**：① 把循环与停止门限纳入可演化面（**配置级，不改代码**，
  前置是本仓 003 的负债账本）；② 评测结果按**被测基座模型**分键——本仓 `neurova/evolution/` 内
  `model_name|model_id` **零命中**，而模型是管理员运行时可换的，这是风险面不是对齐项；
  ③ `EvalExample.difficulty/category` 两个字段**只写不读**，论文恰好给了"难度中心化采样决定
  泛化幅度"的外部论据。
- **明确不学 4 条**（§5）：让 agent 编辑自身循环代码（本仓 `propose_pr_patch` 显式 `not_supported`，
  `rsi/self_improvement_proposer.py:11, 503`）、同任务多轮 rollout 的演化预算、无人监督准入、
  以跨模型迁移成功替代人工评审。
- **与前作的重叠只有一处**：成败对照缺失（本文 §3.3 只补"三分支证据生成"这一形态增量，
  立项出处仍是前作 §4 P1-B）。
- **本轮拍板态（2026-10-15，全文见 §7.1）**：落笔范围＝**只提交文档，不立票面**；
  M-A＝**只挂配置键不入棘轮表**；M-C＝**只出读数不判**；M-D＝**退役 `difficulty`/`category` 字段**；
  M-B／M-E 未拍板（M-E 须晚于 M-B，且分类枚举不得并存第三套）。
  **裁定只定档位，不授权动码**——实施须另批点单后按修复教义独立立项。

## 1. 论文机制（事实层，全部标「论文自述，未复核」）

| 机制 | 论文表述（要点） |
|---|---|
| 演化对象 | 冻结基座 M，只演化包裹它的 Harness H（prompts、控制流、工具接口、记忆/上下文管理） |
| 模块分解 | H 拆五块：Agent Loop、Tool Use、Observation Management、Context Management、Task Completion Detection；**各块从初始 H 独立演化**，末了做跨模块合并 |
| 证据生成 | 任务执行后**多次 rollout**，三分支：全成功→找冗余低效；有成有败→对照两者的决策差异；全失败→翻历史成功样本或分析循环/报错 |
| 结论形态 | 每条发现结构化为三元组（出问题的函数 / 证据 / 修改方案），并**跨任务聚合**成"反复出现的行为缺陷" |
| 三道验证 | Program Check（语法与接口）、Diff Review（**拒绝任务特定常量与局部启发式**）、Execution Validation（重跑任务） |
| 数据口径 | 演化池 2,000 条外部可执行任务，与下游评测基准不相交；评测在 Terminal-Bench 2.0 与 SWE-Bench Verified 上做 |
| 论文自述数字 | TB2.0 准确率 47.57%→52.43%（+4.86pp），其中 Agent Loop 贡献 +2.99pp，Observation Management 使步数降约 35%；SWE-Bench 76.45%；pass@3 65.17%；跨域迁移 TB-evolved→SWE +2.40pp、SWE-evolved→TB +1.83pp；跨基座迁移 GLM 档 59.55→61.80、MiniMax 档 41.57→44.94、DeepSeek 档 47.57→52.43 |
| 消融 | **模块化演化优于联合演化**，"全模块联合演化"一档掉分；**中等难度为中心的演化数据**带来 +6.6pp，纯难/纯易只 +0.6pp |
| 自承局限 | 共同演化的稳定性、演化数据的最优构造、更多轮次与数据下的可扩展性、不同基座对 harness 演化的影响差异；另有一处**对照步骤本身没有独立消融** |

## 2. 公平性前提：两侧演化的不是同一层东西

| | Neurova RSI | ModularRSI |
|---|---|---|
| 演化对象 | 运行参数（五族）+ 技能正文 + 工具权重——**不改本仓代码** | **改 harness 自身的 Python 实现**（循环控制流、观测处理、完成判定） |
| 反馈源 | 分层票据：服务端票据 > 本轮客观回执 > 自述/关键词，三态可空 | 同任务多次 rollout 的成败对照 + 验证器分数 |
| 准入 | 人工评审主 gate + 五阶段门禁 + 负债反向闸 + 留出/真留出双集 | 三道程序化验证 + 跨基准/跨模型迁移读数 |
| 执行面 | 进程内，不执行外部代码 | 可执行任务池，真跑终端/仓库 |
| 自动化程度 | 默认 `rsi_phase=0`、文本臂默认关（前作 §3.7 已记，不重复立项） | 批式离线演化，无人监督 |

公共交集仍只有一条：**不动权重，靠外部机制的自我修订获得持续提升**。因此本文**不比分数**，
只比"同一类机制在两侧分别落到哪一层、判据谁更咬合"。可迁移部分收敛在 §4。

## 3. 逐维对照（本仓侧全部实测）

### 3.1 可演化面的覆盖面（差异最大的一条）

**本仓**：`rsi/integration_manager.py:33-67` 的 `OPTIMIZABLE_PARAMETERS` 五族＝
sleep(2)／emotion(2)／experience(3)／tool_memory(4)／context(4)，后一族是 2026-09 才补进来的
token 预算与保留窗口（其注释自陈"此前上下文链的自动决策参数对棘轮完全不可见"）。
而 agent 循环侧的门限机制**确实存在且已接线**：`agent/gates.py:61-99` 轮次上限与 token 预算门、
`:102-150` 死循环门、`:153-258` 目标门（含"模型自认完成但目标未达成"的假完成拦截，
`:207-233`），装配点 `agent/loops/base.py:378-385`。

**判定**：论文五模块里的四块（Agent Loop／Observation Management／Context Management／
Task Completion Detection）本仓**有实装骨架，但只有 context 那一族进了可演化面**。
缺的不是能力，是**把能力参数化并纳入棘轮**。

### 3.2 联合轮 vs 分模块轮

**本仓**：`rsi/orchestrator.py:409-434` 一轮的动作序列是——
`generate_optimizations()`（`853-868`：对**每个**参数各产 1 个最优候选）→
`apply_optimizations(optimizations)` 全量应用 → 一次 `perf_after - perf_before` →
一次 `rollback_manager.should_rollback` 对整体快照回滚。
即本仓参数臂**正是论文消融里掉分的那种"联合演化"形态**，且回滚粒度与提名粒度不一致
（提名按参数、判定与回滚按整轮）。

**判定**：论文给的是**论据**而非现成方案。本仓不能直接照搬"每族一轮"——
`rsi/parameter_activity.py:5-9` 实测 262 行真账里 11 个参数只有 7 个出现过，4 个 `never_proposed`；
把一轮拆成五轮，多数轮次会在无数据上空转，且每轮都要付一次评测成本。
落点因此是**先加归因读数，不动动作粒度**（§4 M-B）。

### 3.3 三分支证据生成（与前作 P1-B 的重叠处，只记增量）

**本仓**：四条分析路径均无"同题成败配对"（前作 §3.3/§3.4 已实测并立项为 P1-B，本文不改写其结论）：
`eval/mutator.py:73-101` 只取最低分失败样本；`meta_cognition_layer/self_model.py:439-467`
的 `_op_contrast` 是**同一工具按输入特征切组的统计对照**（带 Wilson 区间），不是同一任务的
一次成与一次败的对照；`skills/experience_knowledge_base.py:403-427` 的去重键里含 `success`，
即同问的成败两行**并存但从不互比**。

**增量只有一条**，且是本仓完全没有的第三分支：**全部成功的任务也要被审视（找冗余步骤/低效）**。
本仓文本臂的评分面里**没有任何效率项**——`eval/fitness.py` 全文件 grep
`token|step|cost|efficien|latency|轮次` **零命中**；代价记账只存在于参数臂
（`orchestrator.py:382-385` 的 `compute_roi()` 与 003 的负债闸）。
"省 35% 步数"这类改进在本仓**没有可被优化的目标函数**，不是没实现，是没进判据。

### 3.4 缺陷的结构化归因（三元组）

**本仓**：失败分类是**按错误关键词**的六桶（`evolution/skill_improver.py:44-52`
timeout／invalid_input／resource_error／dependency_failure／logic_error／unknown，
修复建议是查字典，前作 §3.3 已记），另有按机制的五算子（`self_model.py:205-210`
drift/sequence/contrast/calibration/budget）与三值能力缺口（`agent/capability_gap.py:43-47`）。
**没有一个是"这条缺陷属于哪个 harness 环节"的归因轴**；且归因只进证据面、
不改 accept/reject（前作 §3.4 实测 `history_ledger.py:181-194`）。
**判定**：论文的三元组形态（出问题的函数/证据/修改）比关键词桶更咬合，因为**它让"改对地方没有"
成为可判命题**。本仓的对应改造见 §4 M-E，且必须复用既有的 `attribution_hit_rate` 面，
不新造第二份归因账（教义第 6 条）。

### 3.5 三道验证闸的对应物

- **Program Check** ≈ 本仓 `rsi/automation_prerequisites.py` 的四条运行时可反证探针（聚合进晋升否决）
  与 NL 合成臂的字母表闸/置信闸/注入扫描（前作 §3.2 记录其接线）。
- **Diff Review（拒任务特定常量）** ≈ 本仓 `eval/leak_critic` 标记集 + 结晶入库闸
  （`eval/eval_corpus.py:107-134`，每次现读语料、不设缓存以免陈旧围栏）。
  **射程差一层**：本仓的检只防"评测题面逐字回流"，一个不在语料里的任务特定常量照样放行。
  不立项理由：泛化该检需要语义判定，易自伤（把好经验误判为泄漏），且本仓已有呈现账与
  采纳回写可事后归因——列为观察项，非缺口。
- **Execution Validation** ≈ 本仓双臂评测 + 留出/真留出 + `scripts/ci/experience_quality_gate.py`
  的冻结真语料 A/B 与自证红探针。**这一维本仓更强**（论文的重跑只在其演化集内）。

### 3.6 演化集与评测集的分离

**本仓**：`eval/dataset.py:48-77` 的 train/val/holdout/heldout 四分与注释"heldout 只做最终验收证据，
永不参与判定——防自适应污染"，`eval/config.py` 的 `holdout_ratio`，`runner.py:4` 的政策条文
（"变体在 holdout 上必须优于基线，而非在训练集选最优"）。用例出处带 `source` 三态
（`eval/dataset.py:29`，synthetic/history/golden，history 由 `eval/miner.py:215-261` 从真实会话
持久化里采）。
**判定**：**基本平手，本仓不必为此学**。论文的"任务源不相交"比本仓强的一点是它跨了两个
不同基准的题域；本仓的分隔发生在**同一份语料内部**，没有"换个题域验收"的读数。
但这条与本仓治理面重叠（前作 §3.7 已记"默认配置下双臂实际不产生自改"），本文不重复立项。

### 3.7 跨基座迁移（本仓零覆盖）

**实测**：`neurova/evolution/` 目录内 `model_name|model_id` **零命中**；
`eval/fitness.py:129` 与 `eval/mutator.py:122` 用的是**固定的 `config.judge_model /
optimizer_model`**——那是打分与生成用的模型，不是被测模型。没有任何读数按被测模型分键，
也没有换模型后的回归。

**判定**：这条不是"形态启示"，是**风险敞口**：本仓基座模型是管理员运行时可换的配置，
而技能正文与参数 setpoint 的验收证据全部产生在某一个模型之下。切模型后，
既有 accept 判定对新模型**没有任何证据**。论文的三档迁移读数正是这一格的反证方法。见 §4 M-C。

### 3.8 难度维（只写不读的断点）

**实测**：`EvalExample.difficulty`（`eval/dataset.py:27`，默认 `medium`）与 `category`（`:28`，
默认 `general`）由 `eval/synthetic.py:26, 99`（prompt 里要求 LLM 产出 difficulty）与
`eval/miner.py:198` 写入，`to_dict` 序列化（`:35-36`）；
但 `split`（`dataset.py:80-111`）与 `runner` 判定链**都不按它们筛或分组**——
在 `neurova/evolution/` 全目录 grep，这两个字段没有任何读取点
（runner 里的 `verdict.category` 是泄漏判定的另一个对象，不属此处）。
其余 `difficulty` 命中属不同概念（`core/intrinsic_motivation.py` 的 0-1 浮点、
`collaboration/neurflow/templates/*` 的模板标签、`api/endpoints/benchmark.py` 的静态题面）。

**判定**：这是 AGENTS.md §2「只写不读」断点条款自己禁的形状；论文消融（+6.6pp vs +0.6pp）
把它从洁癖升格为**有外部论据的实际问题**。两条合法出口见 §4 M-D 的三态票。

## 4. 值得习得点（M 前缀，不占前作号位）

> 落地纪律同前作：以下是**形态启示**，不是实现搬运；命名一律本仓自有词汇。

### M-A（P1）把循环与停止门限纳入可演化面——配置级，不改代码

- **对方形态**：Agent Loop 与 Task Completion Detection 是演化收益最大的两块。
- **本仓现状**：机制在（`agent/gates.py:61-258`），装配点在（`agent/loops/base.py:378-385`），
  可演化面没有（§3.1）。更硬的一处：`loops/base.py:379` 的 `DoomLoopGate()` **连配置键都不挂**，
  三个阈值全吃构造默认值（`gates.py:105-115`：`window_size=4`／`similarity_threshold=0.95`／
  `max_interrupts=2`），而同文件 `:368` 的注释自陈忌讳"上限再次不受任何配置键管辖"。
- **习得动作（次序固定）**：① 先把 `DoomLoopGate` 三阈值挂上配置键（这一步与 RSI 无关，
  是补齐管辖）；② 再评估入表。**入表有硬前置**：`integration_manager.py:56-60` 写明
  "该参数必须已有 003 的负债/代价记账"，判据在 `parameter_identity.admits_into_table` 逐条咬合——
  绕开它即是工单 018 修过的"棘轮奖励自己编辑空对象"第三形态，且会重演前作 §6-1 的
  `context.experience_knowledge` 死旋钮（表里有 setpoint、injector 无消费点）。
- **红线**：**不碰 `propose_pr_patch`**（`self_improvement_proposer.py:11, 503` 的 `not_supported`
  是安全模型的一部分，§5）。本条只让门限可被观测与调节，不让 agent 改自己的控制流代码。
