## 0. 结论先行

SELFCOMPACT 的核心命题：**"何时压缩"是一种元认知能力——模型天生不可靠，但可以由 scaffold
用"压缩工具 + 轻量规则"在零微调、零外部监督下赋予**。论文用 6 基准 × 7 模型的实验证明：
固定间隔（token 阈值）压缩是**结构盲**的，会在推导中途、搜索中途把尚未消费的中间态压掉；
而"结构感知的触发/抑制规则 + 可主动调用的压缩工具"两者结合，性能持平或超过固定间隔总结，
token 开销只为其一小部分（对比不压缩基线：数学最高 +18.1 分、agentic search +5~9 分、
每题成本 −30~70%）。

对照本仓的结论：

- **时机范式上论文领先**：其触发/抑制条件是**任务相位**（子任务完成、轨迹收敛、推导中途、
  卡住），本仓增长门是 **token 增量**（占用下限 ∧ 增量门槛 ∧ 消息数）——增长门解决了
  "别在容量压力下被迫折"，但还没有解决"别在任务中途折"。这两层是互补而非重复。
- **无损保障上本仓结构性领先**：论文（与 billion-context 一样）是纯窗内方案，压缩=摘要
  替换原文、原文弃置；本仓折叠只动视图，原文入活水池，`recall_history` / `pool_search` /
  `covers_ref` 下钻三路可回。论文的"压缩"在本仓语境里对应的是**折叠**，且本仓形态信息保留率更优。
- **论文的"工具 + 规则"二元结构，本仓已落地大半**：`context_compress`/`context_status`
  模型工具（B1）+ 工具描述内嵌的时机软规则（"任务步骤完成时用；调试/推理中途不用"）+
  成文压缩教义（B3）+ 增长门（B5，2026-11-15 跑数据转正默认开）。
- **真正的增量启发只有两条**：① 框架触发面补**任务相位抑制**（swarm run 进行中、工具链
  未闭合、连续失败卡住时抑制折叠，推迟到边界）；② 把增长门的"当前是否处于推荐折叠时机"
  作为**判读读数**暴露给模型（`context_status` 已有基建），把元认知支架从"描述级"升到"判读级"。

六维加权打分：**SELFCOMPACT 8.0 vs Neurova 7.3**。差距集中在"触发/抑制的时机智能"这一
论文主场；无损保障、工程化落地面反超。

## 1. SELFCOMPACT 论文理解

### 1.1 问题设定

长轨迹 agent（思维链 + 工具调用）会持续积累过时内容：过时内容**锚定**后续生成（模型倾向
复述/沿用旧中间结果），并最终撑爆上下文窗口。现有 scaffold 的主流做法是**固定间隔压缩**——
到达 token 阈值就触发总结。论文指出这类触发的结构性缺陷：**不看轨迹结构**，可能在推导
进行到一半、搜索进行到一半时，把尚未完成、尚未消费的部分结果压掉，直接损伤任务完成度。

### 1.2 方法：推理时二元结构（压缩工具 + 触发/抑制规则）

SELFCOMPACT 是纯推理时方案，不训练、不改模型，由两个组件构成：

1. **压缩工具（compaction tool）**：注册为模型可调用的工具，模型主动发起，把已积累的
   上下文总结成摘要并替换原文。
2. **轻量规则（rubric）**：规定何时**触发**、何时**抑制**——
   - 触发：**子任务已完成**（a sub-task has resolved）；**轨迹正在收敛**（the trajectory
     is converging）；
   - 抑制：**推导进行中**（mid-derivation）；**模型陷入停滞**（when stuck）。

论文的关键消融结论：**两个组件缺一不可**。只给工具时，开源权重模型的使用极不均衡——
常在不合适的时机调用，或干脆不调用；只给规则则没有执行载体。二者结合才稳定生效。

### 1.3 证据面

- 6 个基准（竞赛数学 + agentic search 两族）× 7 个模型。
- 对比固定间隔总结：性能持平或更好，token 开销只是其一小部分。
- 对比不压缩基线：数学最高 **+18.1 分**，agentic search **+5~9 分**，每题成本 **−30~70%**。
- 分基准/分模型得分表、rubric 具体措辞：摘要页未载，未验证。

### 1.4 核心论断：元认知鸿沟

模型在无提示时**无法可靠判断自己的上下文何时已经"腐坏"**（rotting）——哪些内容已被消费、
哪些中间态还会被引用，模型自己说不准。但一条轻量规则即可弥合这一鸿沟。由此论文提出：
**"何时压缩"应当被当作一种由 scaffold 提供、无需训练就能赋予模型的能力**——与"给模型
一个搜索工具"同构：能力不在模型权重里，在外围脚手架里。

- Neurova 第 3 维 7.5 而非更高：工具与读数已有，但模型拿到的是"静态描述"，不是"动态判读"

  提升幅度小于数学类，部分归因于长程信息依赖）。

## 5. 可改进项（候选，均含影响面与不做的代价）

### SC-1 · 框架折叠的"任务相位抑制"（P1，时机升级）
**做什么**：给 `decideFoldTrigger` 增加抑制臂——当本会话存在**进行中的结构信号**时抑制
框架折叠，推迟到边界：swarm run 处于运行中（`SwarmManager` 活跃 run / 子任务未到终态）、
本轮工具调用链未闭合等。抑制不是永不折：硬水位兜底仍在（容量安全优先于时机最优），
相位抑制只作用于增长门的"主动折"路径。
**影响面**：`neurova/context/fold_trigger.py`（新增抑制判据入参）、`orchestrator.py`
`_apply_window_budget`（传入 run 状态）、run 状态读取走既有 `core/agent_run_ledger` /
SwarmManager 查询面（不新造第二状态源）。
**不做的代价**：多 agent 长任务里，框架折叠仍可能切在子任务中间——S6 之后 swarm 会话
有了压缩纪律，但"何时压"仍是 token 水位说了算。
**决策点**：相位信号的权威来源（run ledger vs SwarmManager 内存态）需先定，避免引入
双源；建议读 ledger（跨进程一致），SwarmManager 态仅作加速缓存。

### SC-2 · "卡住抑制"（P2，反直觉保守臂）
**做什么**：检测会话停滞信号（连续 N 次工具失败 / 重复同参调用 / 长时间无新产出），
命中时抑制折叠——卡住时模型最需要完整历史来自我修正，此时压缩等于销毁脱困线索。
**影响面**：`fold_trigger.py`（抑制判据）、停滞信号源（工具执行结果账本已有失败计数面）。
**不做的代价**：模型越挣扎、上下文越快被压掉，进入"失忆→重复失败→再失忆"循环。
**决策点**：停滞判定阈值（连续失败次数/时长）需按真机轨迹定标，先观测后启用。

### SC-3 · "推荐折叠时机"判读暴露（P1，元认知支架升级）
**做什么**：`context_status` 增加"当前是否处于推荐折叠时机"判读字段——直接复用
`decideFoldTrigger` 的判定结果与未触发原因（`below_floor` / `insufficient_growth` /
`growth_gate` / 相位抑制），把框架的时机判断透明给模型；同步把 `context_compress` 描述里
的软规则升级为与增长门一致的结构化表述（任务步骤完成 / 阶段收敛可压；推理中途、连续
受挫时勿压）。
**影响面**：`fold_trigger.py`（判定结果结构化输出）、`tool_executor.py` 的
`context_status` 实现、`builtin_tools.py` 工具描述。
**不做的代价**：模型自决压缩始终靠"猜"——工具给了、时机规则却只写在描述里，正是论文
消融实验里"只有工具"的弱形态。
**决策点**：无（纯读数增强，默认无害）。

### SC-4 · 折叠时机三臂基准（P2，实证补课）
**做什么**：在 B8 保留率探针基准（aee0d78f7，合成马拉松×三臂）上增加**时机臂对比**：
固定间隔 vs 增长门 vs 增长门+相位抑制，读数含可恢复率、视图峰值、摘要调用次数、
"中途截断次数"（折叠发生在工具调用对中间的次数）。
**影响面**：`tests/performance/` 基准套件扩展、`docs/08-research/` 结果落格。
**不做的代价**：SC-1/SC-2 的收益只能靠单测与体感背书，无法量化"时机对了省多少、
稳多少"。

### 落地次序建议
SC-3（纯读数，零风险）→ SC-1（相位抑制，需定信号源）→ SC-2（卡住抑制，需定标）→
SC-4（基准复跑贯穿）。

## 6. 不照搬清单

1. **摘要替换原文的压缩语义不采用**——本仓折叠原文入池 + 三路回读，信息保留率优于论文
   方案；论文的"压缩工具"语义对应本仓"折叠工具"，已是更优形态。
2. **rubric 措辞不搬运**——论文 rubric 面向竞赛数学与搜索任务，且属他人成果；本仓只吸收
   "触发/抑制二元 + 任务相位条件"的**形制**，条目文本按本仓任务形态（多 agent 协作、
   工具链、长陪伴会话）自写。
3. **"元认知鸿沟"结论不外推过度**——论文实验集中在两族基准；本仓多用户产品形态下，
   确定性保底折叠（硬水位）必须保留，模型自决与相位抑制只做增量通道，不能替代兜底。
4. **固定间隔压缩不引入**——论文的对照臂是它，不是可选方案；增长门已是更优的 token 侧
   触发，缺的只是相位维度。
5. **成本数字不直接引用**——−30~70% 是论文基准集上的读数；本仓收益以 SC-4 自采数据为准。

## 8. 活水池 × SELFCOMPACT 结合评估（v2 增补）

> 论文是纯窗内方案；本仓独有的活水池（`neurova/context_pool.py`，设计文档
> `docs/01-architecture/living_context_pool_design.md`）把折叠原文全量归档（SQLite WAL+FTS5
> 写穿、永不过期、跨重启可召回，信息保留率 R∞=100%），并配被动语义召回（抽屉）与主动检索
> （`pool_search`/`recall_history`/`recall_context_span`）。本节评估论文各机制放进
> "窗内折叠 + 窗外活水"形态后，哪些被增强、哪些失效、哪些要改造。

### 8.1 核心判断：池把压缩从"不可逆删除"变成"可逆降权"

论文所有时机规则的严苛性，根源在于其压缩**不可逆**——压早了就是丢，只能靠抑制条件
（mid-derivation/stuck）把错误挡在发生之前。池形态下，折叠只把内容从"常驻视图"降到
"可召回归档"，时机错误的代价从**永久丢失**降为**暂时不可见**。因此：

- 论文的抑制条件在本仓语境下从"防丢失"（生存必需）放松为"防遗忘"（体验优化）；
- 触发时机可以比论文更激进——只要"当前视图不再需要"即可折，不必等"确定永不再需要"，
  因为需要时池里还在。这是论文形态给不了的自由度：它折早了没有后悔药。

**一句话结论：池让论文的"保守压缩学"升级为"激进折叠 + 召回兜底"的双层策略——
折叠管窗口效率，池管信息安全，rubric 管两者之间的切换时机。**

### 8.2 逐机制评估

| 论文机制 | 放进活水池后 | 评估 |
|---|---|---|
| 压缩工具（摘要替换原文） | 本仓 `context_compress` 已是折叠语义：原文入池，视图留摘要 | **天然增强**。论文工具的 最大风险（不可逆丢失）在池形态下不存在；工具回执还可携带召回指引（→SC-5） |
| 触发：子任务完成/轨迹收敛 | 池形态下触发线可前移：早折的下行风险有限（可召回） | **增强**。论文必须等"确定不再需要"，本仓只需"当前不需要"；前移触发可进一步压低窗口峰值（并入 SC-4 验证） |
| 抑制：推导中途（mid-derivation） | 折了也能召回，但推导中的模型往往不知道自己缺什么——被动抽屉按 need 注入可兜一部分 | **保留但可软化**：从"硬抑制"改为"软抑制 + 边界锚点保留"（折叠时把推导链最后一条消息/当前工具调用对留在视图，其余入池） |
| 抑制：卡住（stuck） | 卡住轮历史折了仍在池里；但卡住时召回锚最弱（短输入 need 区分力低，B10 已实证），被动召回可能接不住 | **降级**：从论文的"生存必需"降为本仓的 P2 观测项——池兜底后不再致命，但 SC-2 仍值得做（作保险） |
| 元认知鸿沟（模型判不了何时压） | 池形态下多出一层：模型还要知道"压掉的去哪了、怎么找回" | **改造**：rubric 职责从单一的"何时压"扩展为"何时压 + 压后何时取"。教训在 billion-context 论文里已实证：模型不会自发使用恢复工具——所以"取"的半边必须靠被动抽屉兜底 + 回执内嵌指引，不能只靠模型自觉 |
| 成本经济（−30~70%） | 折叠省窗口（账单），池增加自持成本（存储+召回嵌入计算，B11 LRU 已缓冲） | **净收益更优**：收益面扩大（可早折、多折），风险面缩小（可召回），新增成本有界且已治理 |
| （论文没有）时机质量反馈 | 池形态独有：**"折叠后 N 轮内被召回的比率"**可作折叠时机质量的量化指标——折早了召回率会抬高 | **本仓独有优势**。论文形态测不了这项（压掉即失联）；本仓取水读数（B13）+折叠事件（CompressionEvent）已具备基建，加一个关联读数即可 |

### 8.3 对 §5 候选的修订

- **SC-1（任务相位抑制）维持 P1，形态软化**：不做成一刀切硬抑制，改为"相位信号命中时，
  折叠只取区间尾部、保留推导边界锚点（最后一条消息/当前工具调用对）在视图，其余照常入池"。
  影响面不变（`fold_trigger.py` + `orchestrator.py`，run 状态读 `agent_run_ledger` 防双源）。
- **SC-2（卡住抑制）从 P2 观测项继续保留，但紧迫性下调**：池兜底后卡住轮压缩不再是
  不可逆损失；是否落地以 SC-4 基准里"卡住轮召回失败率"数据为准。
- **SC-3（推荐时机判读）维持 P1 不变**：池形态下模型更需要知道"该不该折 + 折了去哪找"，
  判读暴露的价值不降反升。
- **SC-4（三臂基准）扩为四臂**：固定间隔 / 增长门 / 增长门+相位抑制（软） /
  **增长门+前移触发（池形态激进臂）**——最后一臂验证"池兜底下触发线前移"的收益与召回
  失败率，读数新增"折叠后 N 轮召回率"与"中途截断次数"。
- **新增 SC-5（P1，折叠回执带召回指引）**：`context_compress` 执行成功的回执中附带
  结构化提示——被折区间的池引用（covers_ref/消息 hash 段）与找回路径
  （`recall_history` 精确直取 / `pool_search` 语义检索 / `recall_context_span` 下钻），
  把"压后去哪找"写进模型刚看到的位置（元认知支架的第二半）。影响面：
  `tool_executor.py` 的 context_compress 实现、回执文案；不做的代价：模型折叠后遇需求
  只会整会话粗捞或干脆遗忘，池的回读面利用率上不去。
- **新增 SC-6（P2，折叠后召回率读数）**：把 CompressionEvent（折叠时点、区间 hash 集）
  与抽屉命中账本（B13 八计数）关联，产出"折叠后 N 轮内区间被召回比率"——这是池形态
  独有的折叠时机质量指标，论文形态无法构造。作为 SC-1/SC-4 的验收读数。影响面：
  `fold_trigger.py`/`orchestrator.py` 折叠事件、`semantic_drawer.py` 命中埋点、
  `budget_report.py` 聚合；不做的代价：折叠时机好不好永远只有间接证据（窗口峰值），
  "折早了"无法被数据发现。

### 8.4 结合形态下的边界与不照搬（对 §6 的补充）

1. **池不豁免时机纪律**：召回不是免费的——被动注入受 0.65 门槛与预算约束，主动检索依赖
   模型自觉。"折了反正能召回"若成为默认心态，窗口是省了，但每轮召回的嵌入计算与
   上下文噪音会反向吃掉收益。折叠仍应优先落在任务边界。
2. **早折前移必须有界**：SC-4 的激进臂只做实验臂，不作为默认——前移多少取决于召回
   失败率曲线，无数据不转正（与 B5 增长门"先灰度后转正"同一纪律）。
3. **召回锚弱化场景要认账**：短输入轮（"继续""不对"）的 need 信号弱，池兜底在这些轮次
   最不可靠——这恰是 SC-2 卡住抑制仍有价值的场景，两者互补而非替代。
4. **论文数字不可迁移**：−30~70% 与 +18.1 分均在纯窗内形态取得；池形态下的本仓收益
   以 SC-4/SC-6 自采数据为准。

## 9. 元认知能力 × 压缩时机（v3 增补，2026-11-18）

> 论文的"元认知鸿沟"论断是：模型判不了自己上下文何时腐坏，需要 scaffold 用**静态规则**
> 补位。本仓有一套论文没有假设的东西——**系统级动态元认知回路**
> （`neurova/cognitive_layers/meta_cognition_layer/`）。本节基于本会话代码核对重估：
> 当"何时压缩"的信号源从静态 rubric 换成本仓元认知信号，前两节的结论要怎么改。

### 9.1 本仓元认知能力实态（代码核对）

| 组件 | 位置 | 能力 |
|---|---|---|
| 自我模型反思 | `self_model.py` `SelfModelEngine.reflect`（L224） | 五算子反思（contrast/sequence/calibration/budget 等，`OPERATORS` 单点），把累积事件编译成**教训（lesson）**；逐字可核闸防幻觉（拒收的教训进读数面）；per-operator 隔离防单算子崩全轮 |
| 反思触发 | `self_model.py` `reflect_due`（L212） | 轮次门（每 10 轮）∨ **事件量门**（台账未编译事件 ≥ 阈值，持久判定重启不丢），600s 节流——与压缩增长门同构："攒了新证据才动作" |
| 元认知台账 | `ledger.py` `MetaLedger` | SQLite 持久：原始事件、教训、反思历史、状态快照、**工具成功率**（`tool_success_rates`）、未编译事件数 |
| 工具自省 | `self_model.py` `check_tool_advisory`（L388） | 查询某工具当前活跃的 avoid_tool 教训（带 expires_at）——**现成的"连续受挫"信号源** |
| 教训生命周期 | `growth_log.py` `GrowthLogManager` | PENDING → APPLIED → VALIDATED（带置信度），治理闭环 |
| 教训再注入 | `context/injector.py` `_select_growth_reflections` + `context/orchestrator.py`（L51/L70 消费 `ReflectionLogStatus`） | 已验证教训按置信 top2 优先注入上下文信封（≤3 条），**注入即 pending→applied**，痕迹挂 turn ContextVar 供效力裁决——"自我观察 → 反思 → 教训 → 回到模型面前"完整闭环 |

（索引文档 `docs/0-index/README.md` 写的模块路径 `metacognition_layer` 与实际目录
`meta_cognition_layer` 略有出入，模块本身存在且与上下文管线有真实消费接线。）

### 9.2 与论文的对照：静态外挂规则 vs 动态自反思回路

SELFCOMPACT 的元认知是**外挂的**：scaffold 用一条写死的 rubric 提醒模型"该压了/别压"，
模型本身的能力没有变化。本仓的元认知是**内生的**：系统持续记录自己的行为事件，周期性
编译成教训，教训再以系统提醒形态回到上下文影响后续行为——这是一个会随经验自我修正的
"何时/何不该"判断来源。

对压缩时机的含义：论文 rubric 的四个条件（子任务完成/收敛/推导中/卡住）在本仓不必全靠
启发式猜——**其中两个有现成的系统信号**：

- **"卡住"** ≈ `check_tool_advisory` 的活跃 avoid_tool 教训 + `MetaLedger.tool_success_rates`
  的滑动失败率。模型在同一工具上反复失败时，元认知层早已记录在案。
- **"子任务段落完成/收敛"** ≈ 反思编译点。`reflect` 跑完意味着"一批事件已被提炼归档"，
  对应原始消息的信息密度骤降——这是比任何启发式都可靠的"可折叠"信号。

### 9.3 三方结合的重新评估（SELFCOMPACT × 活水池 × 元认知）

v2 的结论是"池把压缩变成可逆降权，因此可以激进折叠+召回兜底"。加入元认知维度后，
结论再进一步：**池解决了"压错了找得回"，元认知解决"什么时候压更准"——两者正交，
合起来把论文的"时机难题"拆成了已被本仓架构消化的两个半题。**

1. **压缩时机的信号层级重排**（从弱到强）：
   静态 token 水位（论文的对照臂）→ 增长门（本仓现行，token 增量感知）→ 静态 rubric
   （论文方案，任务相位启发式）→ **动态元认知信号（本仓可达成）**：失败率/活跃教训
   判"卡住"、反思编译点判"段落完成"、事件量门判"新增量"。论文的 rubric 是这一层级里
   的第三档；本仓有基建走到第四档。
2. **"反思后再压缩"是本仓独有的结构感知触发**：反思编译完成 = 系统级确认"这段经历已
   提炼完毕"，此刻折叠对应的旧消息，损失最小、收益最确定。论文没有等价机制——它只能
   靠模型自报告或外部启发式；本仓有真实的自我观察节律可挂靠。
3. **解耦红利**：反思证据存于 MetaLedger（独立 SQLite），**不受视图折叠影响**——折叠只
   改变模型"看得见"什么，不动系统"记得"什么。因此"折叠 × 反思"没有论文形态里"压掉
   证据→反思失据"的循环风险；反过来，反思产物（教训）以系统提醒再注入，天然抗折叠
   （教训短小且周期性重现）。
4. **对打分的修正**：§4 第 1/2 维（触发结构感知、抑制条件）评的是"现状"，维持不变；
   但可达上限显著上调——论文 9.0 的优势是"它做了"，本仓的差距是"还没接"，不是"接不了"。

### 9.4 对候选的再修订（SC 系终版）

| 项 | v2 状态 | v3 修订 | 依据 |
|---|---|---|---|
| SC-1 相位抑制 | P1，软抑制+边界锚点 | **信号源明确化**：优先读 run 生命周期（agent_run_ledger），元认知信号作第二优先级 | run 状态是"子任务进行中"的权威源 |
| SC-2 卡住抑制 | P2（池兜底后紧迫性降） | **信号源现成，实现成本大降，升回 P1-**：命中条件 = 活跃 avoid_tool 教训（check_tool_advisory）∨ 工具滑动失败率超阈（tool_success_rates） | 不必新造卡住检测器，接现成元认知读数即可 |
| SC-3 推荐时机判读 | P1，context_status 加判读 | **升格**：除增长门判定外，同时暴露元认知状态（未编译事件数、距今反思轮数、活跃教训计数）——模型获得"系统怎么看我自己"的完整读数 | 元认知支架从预算读数升到认知状态读数 |
| SC-7（新增，P1） | — | **反思节律对齐折叠**：反思编译完成后，将"已编译事件对应的更早消息"纳入下一轮折叠候选（仍过增长门与池归档，不越硬水位） | "反思后再压缩"——本仓独有的结构感知触发；折叠时机挂靠系统自我观察节律，而非启发式猜测 |
| SC-8（新增，P2） | — | **活跃教训引用保护**：compression_doctrine 的 KEEP 面增加一条——活跃 lesson（未过期、PENDING/VALIDATED）引用的原文消息折叠时豁免或降档处理 | 教训正在指导当前行为时，其证据原文被折会增加"教训与现场脱节"的风险 |

落地次序更新：**SC-3（读数，零风险）→ SC-7（反思对齐，信号现成）→ SC-5（回执指引）→
SC-1（run 相位）→ SC-2（卡住，接 advisory）→ SC-8（教训保护）→ SC-4（四臂基准贯穿）→
SC-6（召回率读数）**。SC-7 与 SC-3 同批做收益最大：前者给框架触发面换上最强信号，
后者把同一信号透明给模型自决通道。

### 9.5 边界与不照搬（对 §6/§8.4 的最终补充）

1. **元认知信号是"优先级建议"，不是"替代门"**：增长门的 token 判据仍是安全底线
   （容量优先），元认知信号只决定"在安全区间内何时动手"——顺序不可倒置。
2. **反思节律不能被折叠反馈污染**：折叠/召回统计（SC-6）与反思证据（MetaLedger 事件）
   必须是两条账——若把"被折叠"计入反思输入，反思会开始对压缩行为本身过度反应。
   台账记行为，压缩记视图，两不相扰。
3. **教训注入预算已收敛（≤3 条），不要为压缩再扩**：SC-3 的读数走 `context_status`
   工具回执（模型主动查询面），不进信封恒定注入——避免元认知信息变成新的常驻噪声。
4. **论文结论仍只作背景**：本节的信号源设计全部落在本仓既有模块上（MetaLedger/
   SelfModelEngine/growth_log/fold_trigger），论文只提供"时机应为元认知能力"的问题定义，
   不引入其实现。
