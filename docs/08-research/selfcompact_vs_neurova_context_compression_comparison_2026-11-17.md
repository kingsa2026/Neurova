# SELFCOMPACT vs Neurova 上下文压缩时机对照评测（2026-11-17）

> 对象：Apple Machine Learning Research 发布论文 **Self-Compacting Language Model Agents**（SELFCOMPACT，
> arXiv:2606.23525，NeurIPS 2026；作者 Tianjian Li、Jingyu Zhang、William Jurayj、Xi Wang、Chuanyang Jin、
> Mehrdad Farajtabar、Eric Nalisnick、Daniel Khashabi，Johns Hopkins University × Apple）。
> 证据边界：依据官方发布页与 arXiv 摘要页整理，**未逐页核对全文 PDF**；rubric 具体提示词措辞、
> 分基准/分模型得分表未获取，涉及时标注"未验证"。
> 对照面：本仓 `neurova/context/` 上下文压缩链路（增长门折叠触发、`context_compress` 模型工具、
> 成文压缩教义、活水上下文池）与 S6 压缩纪律（swarm 会话压缩）。
> 性质：外部研究对照，**研究参考、不作事实源**；不搬其实现与措辞（原创性红线），改进项待拍板后另立工单。

## 0. 结论先行

SELFCOMPACT 的核心命题：**"何时压缩"是一种元认知能力——模型天生不可靠，但可以由 scaffold
用"压缩工具 + 轻量规则"在零微调、零外部监督下赋予**。论文用 6 基准 × 7 模型的实验证明：
固定间隔（token 阈值）压缩是**结构盲**的，会在推导中途、搜索中途把尚未消费的中间态压掉；
而"结构感知的触发/抑制规则 + 可主动调用的压缩工具"两者结合，性能持平或超过固定间隔总结，
token 开销只为其一小部分（对比不压缩基线：数学最高 +18.1 分、agentic search +5~9 分、
每题成本 −30~70%）。

对照本仓的结论：

- **时机范式上论文领先**：其触发/抑制条件是**任务相位**（子任务完成、轨迹收敛、推导中途、
  卡住），本仓增长门是 **token 增量**（占用下限 ∧ 增量门槛 ∧ 消息数）——增长门解决了
  "别在容量压力下被迫折"，但还没有解决"别在任务中途折"。这两层是互补而非重复。
- **无损保障上本仓结构性领先**：论文（与 billion-context 一样）是纯窗内方案，压缩=摘要
  替换原文、原文弃置；本仓折叠只动视图，原文入活水池，`recall_history` / `pool_search` /
  `covers_ref` 下钻三路可回。论文的"压缩"在本仓语境里对应的是**折叠**，且本仓形态信息保留率更优。
- **论文的"工具 + 规则"二元结构，本仓已落地大半**：`context_compress`/`context_status`
  模型工具（B1）+ 工具描述内嵌的时机软规则（"任务步骤完成时用；调试/推理中途不用"）+
  成文压缩教义（B3）+ 增长门（B5，2026-11-15 跑数据转正默认开）。
- **真正的增量启发只有两条**：① 框架触发面补**任务相位抑制**（swarm run 进行中、工具链
  未闭合、连续失败卡住时抑制折叠，推迟到边界）；② 把增长门的"当前是否处于推荐折叠时机"
  作为**判读读数**暴露给模型（`context_status` 已有基建），把元认知支架从"描述级"升到"判读级"。

六维加权打分：**SELFCOMPACT 8.0 vs Neurova 7.3**。差距集中在"触发/抑制的时机智能"这一
论文主场；无损保障、工程化落地面反超。

## 1. SELFCOMPACT 论文理解

### 1.1 问题设定

长轨迹 agent（思维链 + 工具调用）会持续积累过时内容：过时内容**锚定**后续生成（模型倾向
复述/沿用旧中间结果），并最终撑爆上下文窗口。现有 scaffold 的主流做法是**固定间隔压缩**——
到达 token 阈值就触发总结。论文指出这类触发的结构性缺陷：**不看轨迹结构**，可能在推导
进行到一半、搜索进行到一半时，把尚未完成、尚未消费的部分结果压掉，直接损伤任务完成度。

### 1.2 方法：推理时二元结构（压缩工具 + 触发/抑制规则）

SELFCOMPACT 是纯推理时方案，不训练、不改模型，由两个组件构成：

1. **压缩工具（compaction tool）**：注册为模型可调用的工具，模型主动发起，把已积累的
   上下文总结成摘要并替换原文。
2. **轻量规则（rubric）**：规定何时**触发**、何时**抑制**——
   - 触发：**子任务已完成**（a sub-task has resolved）；**轨迹正在收敛**（the trajectory
     is converging）；
   - 抑制：**推导进行中**（mid-derivation）；**模型陷入停滞**（when stuck）。

论文的关键消融结论：**两个组件缺一不可**。只给工具时，开源权重模型的使用极不均衡——
常在不合适的时机调用，或干脆不调用；只给规则则没有执行载体。二者结合才稳定生效。

### 1.3 证据面

- 6 个基准（竞赛数学 + agentic search 两族）× 7 个模型。
- 对比固定间隔总结：性能持平或更好，token 开销只是其一小部分。
- 对比不压缩基线：数学最高 **+18.1 分**，agentic search **+5~9 分**，每题成本 **−30~70%**。
- 分基准/分模型得分表、rubric 具体措辞：摘要页未载，未验证。

### 1.4 核心论断：元认知鸿沟

模型在无提示时**无法可靠判断自己的上下文何时已经"腐坏"**（rotting）——哪些内容已被消费、
哪些中间态还会被引用，模型自己说不准。但一条轻量规则即可弥合这一鸿沟。由此论文提出：
**"何时压缩"应当被当作一种由 scaffold 提供、无需训练就能赋予模型的能力**——与"给模型
一个搜索工具"同构：能力不在模型权重里，在外围脚手架里。

### 2.1 触发面（框架侧）

### 2.2 模型参与面（工具侧）

| 工具 | 位置 | 与论文的对应 |
|---|---|---|

- 折叠完整性：`fold_integrity.py` 零丢失对账；折叠原文入活水池（`context_pool.py`）。

## 3. 逐维度对照

|---|---|---|---|---|

| 2 | 抑制条件完备性 | 双抑制：推导中途 / 卡住 | 工具描述有"推理中途不用"软规则；框架侧无抑制臂；卡住抑制完全缺位 | 抑制是论文的反直觉贡献点（卡住时更需保历史） |

| 模型参与权与元认知支架（20%） | 9.0 | 7.5 |
| 无损保障与回读（20%） | 5.0 | **9.0** |

| 成本经济（10%） | 8.5 | 7.0 |

打分说明（诚实校准）：

- 论文赢在它的主场"时机智能"——这恰是它全文唯一论题；本仓赢在"无损"与"工程落地"。
- Neurova 第 3 维 7.5 而非更高：工具与读数已有，但模型拿到的是"静态描述"，不是"动态判读"
  （模型要用 `context_status` 自己换算该不该压；论文的 rubric 由 scaffold 在恰当时机注入）。
- Neurova 第 5 维 7.0：单测与探针基准厚，但缺论文式"跨基准 × 跨模型"的横向证据；
  B8 保留率基准已具备扩展三臂时机对比的地基。
- 论文第 4 维仅 5.0：纯窗内替换在长程任务里是信息净损失（其自身实验也显示搜索类任务
  提升幅度小于数学类，部分归因于长程信息依赖）。

## 5. 可改进项（候选，均含影响面与不做的代价）

### SC-1 · 框架折叠的"任务相位抑制"（P1，时机升级）
**做什么**：给 `decideFoldTrigger` 增加抑制臂——当本会话存在**进行中的结构信号**时抑制
框架折叠，推迟到边界：swarm run 处于运行中（`SwarmManager` 活跃 run / 子任务未到终态）、
本轮工具调用链未闭合等。抑制不是永不折：硬水位兜底仍在（容量安全优先于时机最优），
相位抑制只作用于增长门的"主动折"路径。
**影响面**：`neurova/context/fold_trigger.py`（新增抑制判据入参）、`orchestrator.py`
`_apply_window_budget`（传入 run 状态）、run 状态读取走既有 `core/agent_run_ledger` /
SwarmManager 查询面（不新造第二状态源）。
**不做的代价**：多 agent 长任务里，框架折叠仍可能切在子任务中间——S6 之后 swarm 会话
有了压缩纪律，但"何时压"仍是 token 水位说了算。
**决策点**：相位信号的权威来源（run ledger vs SwarmManager 内存态）需先定，避免引入
双源；建议读 ledger（跨进程一致），SwarmManager 态仅作加速缓存。

### SC-2 · "卡住抑制"（P2，反直觉保守臂）
**做什么**：检测会话停滞信号（连续 N 次工具失败 / 重复同参调用 / 长时间无新产出），
命中时抑制折叠——卡住时模型最需要完整历史来自我修正，此时压缩等于销毁脱困线索。
**影响面**：`fold_trigger.py`（抑制判据）、停滞信号源（工具执行结果账本已有失败计数面）。
**不做的代价**：模型越挣扎、上下文越快被压掉，进入"失忆→重复失败→再失忆"循环。
**决策点**：停滞判定阈值（连续失败次数/时长）需按真机轨迹定标，先观测后启用。

### SC-3 · "推荐折叠时机"判读暴露（P1，元认知支架升级）
**做什么**：`context_status` 增加"当前是否处于推荐折叠时机"判读字段——直接复用
`decideFoldTrigger` 的判定结果与未触发原因（`below_floor` / `insufficient_growth` /
`growth_gate` / 相位抑制），把框架的时机判断透明给模型；同步把 `context_compress` 描述里
的软规则升级为与增长门一致的结构化表述（任务步骤完成 / 阶段收敛可压；推理中途、连续
受挫时勿压）。
**影响面**：`fold_trigger.py`（判定结果结构化输出）、`tool_executor.py` 的
`context_status` 实现、`builtin_tools.py` 工具描述。
**不做的代价**：模型自决压缩始终靠"猜"——工具给了、时机规则却只写在描述里，正是论文
消融实验里"只有工具"的弱形态。
**决策点**：无（纯读数增强，默认无害）。

### SC-4 · 折叠时机三臂基准（P2，实证补课）
**做什么**：在 B8 保留率探针基准（aee0d78f7，合成马拉松×三臂）上增加**时机臂对比**：
固定间隔 vs 增长门 vs 增长门+相位抑制，读数含可恢复率、视图峰值、摘要调用次数、
"中途截断次数"（折叠发生在工具调用对中间的次数）。
**影响面**：`tests/performance/` 基准套件扩展、`docs/08-research/` 结果落格。
**不做的代价**：SC-1/SC-2 的收益只能靠单测与体感背书，无法量化"时机对了省多少、
稳多少"。

### 落地次序建议
SC-3（纯读数，零风险）→ SC-1（相位抑制，需定信号源）→ SC-2（卡住抑制，需定标）→
SC-4（基准复跑贯穿）。

## 6. 不照搬清单

1. **摘要替换原文的压缩语义不采用**——本仓折叠原文入池 + 三路回读，信息保留率优于论文
   方案；论文的"压缩工具"语义对应本仓"折叠工具"，已是更优形态。
2. **rubric 措辞不搬运**——论文 rubric 面向竞赛数学与搜索任务，且属他人成果；本仓只吸收
   "触发/抑制二元 + 任务相位条件"的**形制**，条目文本按本仓任务形态（多 agent 协作、
   工具链、长陪伴会话）自写。
3. **"元认知鸿沟"结论不外推过度**——论文实验集中在两族基准；本仓多用户产品形态下，
   确定性保底折叠（硬水位）必须保留，模型自决与相位抑制只做增量通道，不能替代兜底。
4. **固定间隔压缩不引入**——论文的对照臂是它，不是可选方案；增长门已是更优的 token 侧
   触发，缺的只是相位维度。
5. **成本数字不直接引用**——−30~70% 是论文基准集上的读数；本仓收益以 SC-4 自采数据为准。
