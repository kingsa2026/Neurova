## 0. 结论摘要

- **综合评分：Neurova 4.9 / 10**（八维加权，权重与逐维依据见 §4）。口径声明见 §1.2：
  这是"按综述提出的实证 RSI 证据协议量覆盖面"，**不是**前作 RSIAgent 档"各自问题域完成质量"
  的口径，两个分数不可直接互比。
- **一句话画像**：Neurova 的**治理与证据契约骨架成熟**（三态判据、五阶段门禁、回滚留痕、
  负债反向闸、可编辑面有界），但综述用来区分"可信 RSI 主张"与"重复优化"的那套**实证机器**
  ——改进器自更新、配对探针（Eq8）、真实任务增益（Eq5）、保留/迁移（Eq6）、全成本账（Eq10）、
  密封报告集——**大多缺失或默认关闭**。
- **核心判定**：按综述 §3 的区分，本仓存在进入**任务系统 S** 的结构返回路径（技能/参数/提示文本
  持久化喂下轮），但**没有进入改进器 I 的返回路径**（`generate_optimizations` 读固定参数表，
  无"提案→下轮候选"回路），也没有证明返回路径有效的配对证据。⇒ **结构 RSI on S 成立，
  实证递归改进不成立**。用综述的话说：当前是"repeated optimization"，不是"recursive improvement"。
- **开箱实态**：默认 `rsi_phase=0` 只观察；0→1 可自动晋升，但 1→2 被 §8 前置 2 探针永久否决
  （生产装配点 `resolveEvolutionExecutor(None)` 拿到 `SimulatedAgent`，无 `agent_ref`）。
  应用参数需管理员手设 phase≥2。**治理机器守着一个默认从不应用参数的循环**——这一条
  与前作 Designer-RSI 档 §8「仅前置 2 未满足」是同一件事，本文不另立新项（见 §5.2）。
  **2026-11-10 活体复算成立**（§9.4）：首迭代自动晋升到 1 后停驻；1→2 三态读数 `failed`
  逐字点名 `realTrajectoryExecutor`；观察迭代与配置默认态逐格命中预判。
- **新增量 6 条**（S1–S6，见 §6）：配对探针、全成本账、保留/迁移轨迹、密封集默认启用、
  真实任务增益标尺升判据、反馈漂移对照。其中 S4 是"既有机制开默认"，S1/S2/S3 是新建证据机器。
- **明确不采纳 4 条**（§7）：为综述分数追外部基准、无限制自动执行、把综述协议当设计标准搬运、
  合并前作成总档。
- **提升到 9 分的路线图已成文 §10**：逐维 9 分锚点（§10.1）＋ 30 张工单四行式清单
  （做什么/落点/验收红灯判据/依赖与量级，§10.2）＋ 四波次分数轨迹 5.4→7.3→8.95→≈9.1
  （§10.3）＋ 风险止损（§10.4）与路径内不做清单（§10.5）。硬关键路径只有一条链：
  A1 前置 2 闭环 → A2/A3 I_t 对象化＋配对探针 → A4/A5 双对照＋真实升级；其余可并行。
- **哲学对齐**：综述 §7.6/§9 的 sober 结论（全球证据只支持有界增益；回归可能；执行/可信数据/
  人类专家仍是纠正源）与本仓"人工评审主防御＋golden 参考＋可执行用例＋回滚"的立场一致。
  低分不是"本仓差"，是"实证判据机器未补齐"；综述自己也承认连它引用的 SOTA 都没做到无限制 RSI。

## 1. 公平性前提与评分口径

### 1.1 对象性质：机制论文 vs 评测协议综述

前三篇前作对照的都是**提出具体机制的工作**（RSIAgent 框架、Designer-RSI 程序性记忆、
ModularRSI harness 演化），比的是"同一件事谁做得好"。本篇对象是**综述**：它不提出新机制，
而是把 404 篇工作的证据形态归纳成一套**提问框架**——"你声称递归自我改进，请拿出这三类证据
（任务增益 / 保留迁移 / 改进器变强），并按这份协议（密封集 / 全成本 / 双对照 / 轨迹）度量"。

因此本文的评分回答的问题是：**本仓现有的证据机器，覆盖综述所提协议的多少？**
这不是"本仓 RSI 好不好用"的评分（那是前作 RSIAgent 档的口径），两者分列不合并。

### 1.2 口径声明（为什么 4.9 与前作 7.9 不矛盾）

| | 前作 RSIAgent 档（2026-10-06） | 本文（2026-11-10） |
|---|---|---|
| 标尺 | 各维按"对各自问题域的完成质量"，不为对方域里不存在的需求扣分 | 综述 §7 实证 RSI 证据协议的覆盖面 |
| 问题域 | 生产常驻自调优（本仓）vs 离线基准习得（对方） | 单一对象：本仓的证据机器 vs 协议清单 |

| 不可互比原因 | 完成质量口径 | 协议里多项（配对探针/迁移轴/重复种子/资源向量）是**研究级要求**，生产平台普遍未建；综述自认其协议是提议而非既成标准 |

## 2. 论文框架（评分标尺的事实层）

### 2.1 两个工程目标与统一循环

- **Goal A**：自动设计 AI 基础设施（造新系统）；**Goal B**：修复/优化既有系统。本仓属 **B**。
- 统一循环（§3.3）：状态 X_t=(S_t, I_t)——**任务系统 S** 与**改进过程 I** 分列；反馈 E_t、
  验证 V_t、外部固定条件 C。四种更新模式：局部修订 / 记忆累积 / 参数学习 / **改进器更新**。
- 三配置描述子（§4.1）：反馈（来源＋角色：训练/提议/选择）、持久化（任务/会话/训练边界）、
  控制（可编辑面 vs 固定面）。
- 六机制族（§4.2）：参数与数据 / 记忆与技能 / 提示、程序与 harness / 反馈与评测 / 改进过程。

### 2.2 三条实证主张（§3.4）

1. **任务增益**（Eq5）：Δ_t = Q(S_t; D_test) − Q(S_0; D_test)——在**测试任务**上的质量差，
   不是内部代理分。
2. **保留 ρ ＋ 迁移 τ**（Eq6）：早先获得的能力在后续 rounds 是否保住（回放）；
   优势是否迁移到新任务/新基座/新工具接口/新反馈源。
3. **改进程序变强**（Eq8）：Γ_t(B)——**配对探针**：把 I_t 与 I_0 作用于**同一批留出起始态**，
   同预算比下游增益。这是"改进器本身在变好"的直接证据，与"任务系统变好"是不同命题。

**核心区分**：结构 RSI（存在返回路径）≠ 实证 RSI（有证据证明返回路径让后续改进更有效）。
**"重复优化 ≠ 递归改进"**——这是全文的判据 spine，也是本文 §4 维度 A 的来源。

### 2.3 评测协议（§7，Fig 7）

- **7.1 基准匹配目标**：交互基准（AgentBench/GAIA/SWE-bench/τ-bench）测任务结局；
  纵向基准（SEA-Eval/SEAGym/TRACE/LifelongAgentBench）测历史与保留；
  "重复尝试一个不变的 agent"与"学习更新后的重复尝试"量的是不同东西。
- **7.2 dev / selection / sealed-test 三分**：开发反馈指导提案；验证集选择更新；
  **密封集只在所有 run 结束后由独立审计者按预定 checkpoint 表审计，测试反馈永不回流**
  指导更新/接受/停止/选点。接受门形式化（Eq9）：验证增益≥阈值 η_t、各保护组回归≤容差 ε_j、
  累积成本≤预算 B，三者合取才接受。警告：**反复对固定验证集选择＝让搜索适应该集**；
  只藏单条标签不够，均值回流也算污染。
- **7.3 全成本账**（Eq10）：C_≤T = Σ_t (c_proposal + c_train + c_validation + c_execution)，
  **含重试、被拒候选、环境检查**；提案推理计入提案项；异质资源（GPU/API/物理实验）报**资源向量**
  不硬加；部署视野 N 任务报 C_total(N)=C_dev+N·c̄_task（摊销）。
- **7.4 隔离改进器贡献**：全循环 vs **冻结改进器对照**（允许用 I_0 更新 solver）vs
  **无持久更新对照**（只允许推理时搜索），同预算同初始化同数据访问；Eq8 配对探针与主轨迹隔离。
- **7.5 轨迹、保留、迁移**：每个预定 checkpoint 报质量 vs 累积成本、接受率、新成功与早先组回归；
  **archive-best / deployed / final 三条曲线回答不同问题**；重复 run 要变动更新生成与选择
  （不只是最终推理）；迁移轴分别变动。
- **7.6 现有证据读数**（论文转述，未复核原始文献）：DGM 20→50%（200 任务 SWE-bench Verified
  子集、80 轮，含搜索任务非全独立留出）；STOP 迁移有回归（GPT-4 配置改善、GPT-3.5/Mixtral 可退化）；
  Hyperagents 冻结迁移元代理 50 轮 → 0.630（CI 0.540–0.630，从零起步，但未隔离元代理质量与起始代理）；
  Metan token-parity 只覆盖两个提示任务；Meta-Rewarding 39.44% vs 35.49%，但 **judge-人工相关性
  的早期增益不在所有后续 rounds 持续**——"演员偏好增益"与"评测器稳定改善"是不同观测。

### 2.4 挑战（§8，本文维度 D/F/G/H 的来源）

- **8.1 外部反馈与漂移**：模型 judge 偏见＋演员-judge 共享更新可让内部奖励越来越有利而任务增益
  没有对应；要变动外部反馈源/频率/成本并设**无新反馈对照**。
- **8.2 经验选择与覆盖**：合成数据替换 regimes 可退化；旧经验与可执行技能会保存稀有成功也会保存
  陈旧假设；回放/选择性保留/刷新要在早先与漂移任务上对比。
- **8.3 交互更新与恢复**：层间干扰与回放回归；档案/回滚/ consolidation 三策略同预算对比；
  恢复时间、丢失技能、恢复后质量与最新分一起报。**稳定性是 stated horizon 上的测量属性，
  不是递归的推论**。
- **8.4 自修改下的评测完整性**：可编辑系统能改"开发分怎么来的"；实验边界应**保护测试标签、
  审计代码、记账不被可编辑态触碰**；内部 judge 可演化而独立参考保持固定。
- **8.5 发现与验证争资源**：更多提案可烧在弱候选上；过早过度验证可杀探索；记录被筛掉的有效候选
  与廉价代理放进来的回归。
- **8.6 迁移局限**：迁移 solver 与迁移 improver 是不同实验；配对探针在每个新域内固定起始态与预算。
- **8.7 失败机制**：优化/信息/行为漂移是不同状态不同时间尺度，拢成"collapse"会藏住失败位置；
  **持久化会保存漏洞**（记忆操纵/提取/投毒、对齐漂移、可执行技能把边界从信息存储扩到允许动作）；
  保留负结果、不确定性与拒因。

### 3.6 关键判定四：四集切分与密封态（主代理亲验，澄清一对易混词）

`eval/dataset.py:44-48` 的 docstring 钉死了两个集合的语义（**不是同一集**）：

- **holdout（留出集）**：接受判据的组成部分，**会被搜索过程反复比较**
  （`eval/runner.py:644-659,825-832`）。⇒ 按综述 §7.2 口径它是 **selection set**，
  不是 sealed test；"反复对固定验证集选择＝适应该集"的警告对它适用。
- **heldout（真留出报告集）**：只做最终验收证据，**永不参与判定**（防自适应污染）；
  决策后只读附带（`eval/runner.py:899-912`）；从 holdout 尾部确定性划出
  （`dataset.py:66-83 carve_heldout`）。**机制已实装**，但 `heldout_ratio` 默认 0.0 = 关闭
  （`config.py:103`；生产建议 0.15 写在 config 注释里）。
- 前作 ModularRSI 档引用的"真留出双集与永不参与判定纪律"（`dataset.py:48-51`）说的就是
  heldout 这一集——**机制存在不是本文新发现，本文的增量只是"默认关"这一实测态**（S4）。
- RSI 参数侧更彻底：每轮复用同 9 个固定合成用例，**无 held-out、无 I_t vs I_0 比较**
  （核查代理读数，`eval_harness.py` 全文）。例级回归门＋锚点地板实装在**技能文本进化**
  （`eval/runner.py:834-862`），对象是技能变体不是改进器；RSI 无多轮 retention 实装。

### 10.2 工单清单

> 每单四行：**做什么 / 落点（现状 file:line 或新建位）/ 验收红灯判据 / 依赖与量级**。
> 量级＝粗估人日（不含评审与票面往返），±50% 视波次复核实状修正。

**A 递归性本质（权重 20%，4→9 的主战场）**

**A1 · 前置 2 真闭环（默认装配接真轨迹执行器）**〔前作 Designer-RSI §8 前置 2 的号位，此处只排波次〕
- 做什么：`resolveEvolutionExecutor(None)` 的回落不再产 `SimulatedAgent`——默认装配路径改解析
  在线 agent（照抄文本进化 API 已验证的 `_textArmExecutor` auto→在线 agent 模式，
  `api/endpoints/text_evolution_api.py:368-398`），结构判定 `isRealAgentTrajectoryExecutor`
  （`eval/service.py:227-244`）自然翻真。
- 落点：`neurova/evolution/eval/service.py:207-224`（单点改回落，禁第二处旁路）。
- 红灯判据：现有探针 `probeRealTrajectoryExecutor`（`automation_prerequisites.py:92-111`）
  当场红（改前 False）；改后行为格——评测执行一步真跑 agent 回合（小预算上限 3 turns），
  台账臂来源读数 `real_agent`；**回落路径的历史病**（接真多模型客户端烧配额挂死测目录，
  `service.py:210-215` 注释）必须有反向格钉住：离线测试态仍走隔离替身。
- 依赖：无。量级：2–3。
- 效果：phase 1→2 晋升不再被前置逐字点名否决；A/B/C/E 全部判据的"下游增益"从此有真实执行面。

**A2 · 候选生成程序对象化（I_t 的可版本化载体）**
- 做什么：把"候选怎么产生"从 `generate_optimizations`（`orchestrator.py:963-1011`）内联逻辑
  抽出为 `CandidatePolicy` 策略对象（步进选择、剪枝次序、打分公式三个自由度），
  版本化落盘 `improverVersionLedger`（新台账：I 版本号、变更摘要、生效时间）；
  `I_0` 钉当前行为为冻结复刻（回归基线，不许"改着改着基线漂了"）。
- 落点：`neurova/evolution/rsi/orchestrator.py`（只改委托方向）＋新模块
  `neurova/evolution/rsi/candidate_policy.py`。
- 红灯判据：行为格——同输入下 I_0 复刻与原内联**逐值相等**（防抽取漂移）；结构格——
  `generate_optimizations` 不再含步进字面量（AST 判据）；台账格——版本落盘可读回、
  伪造版本号被拒。
- 依赖：无。量级：3–4。

**A3 · Eq8 配对探针 `ImproverPairedProbe`**
- 做什么：新建重放式探针——同一批留出起始参数态（复用 `carve_heldout` 的确定性切分纪律），
  分别交给 I_t 与 I_0 产候选，**同预算**跑下游（A1 的真轨迹臂，预算受 `planRealArmTurns`
  镜像约束），输出 Γ_t(B) 读数（后继质量差＋逐对明细）；与主轨迹完全隔离（不进 gain/回滚，
  先观测后升判据，学 yardstick 的两步走）。
- 落点：新模块 `neurova/evolution/rsi/improver_paired_probe.py`；读数挂
  `orchestrator.get_status()`（`orchestrator.py:1277`）＋治理 API＋`RsiGovernancePage`。
- 红灯判据：确定性格——合成可控结局流＋固定双版本输入，两次探针输出逐字节相等；
  三态格——样本不足报 `insufficient_data`（复用 `task_yardstick.MIN_ENTRIES` 先例）；
  接口格——I_t/I_0 版本缺失时探针报 `unevidenced` 而非空转（GateVerdict 纪律）。
- 依赖：**A1＋A2**。量级：4–6。

**A4 · 双对照臂（冻结改进器 / 无更新）**
- 做什么：探针加三臂——全循环 vs 冻结 I_0 允许更新 S vs 只允许推理时搜索不持久更新，
  同预算帽同初始化同数据访问（论文 §7.4 原型，落到本仓即 A3 的臂扩展）。
- 落点：A3 模块内扩臂；读数呈报区分三臂。
- 红灯判据：变异格——把"持久更新"摘掉后无更新臂读数不变（证明双对照真的隔离了变量）；
  预算格——三臂各自 realized cost 报出且不超帽。
- 依赖：**A3**。量级：2–3。

**A5 · I_t 的第一次真实升级（元优化闭环）**
- 做什么：让剪枝/步进策略**吃自己的失败史**（`recursive_ratchet_pruner.py:140,210-216`
  已在记，今天没人用它调策略）产 I_{t+1} 候选；升级本身走提案 gate（人工批准换版），
  换版后配对探针必须重跑并把 Γ_t 读数写进版本台账——"改进器变强"从此有据可查。
- 落点：A2 台账＋A3 探针的接缝处；不新建第三条回路。
- 红灯判据：台账格——无探针读数的换版被拒（"升级了但没证据"不许入账）；
  行为格——I_{t+1} 候选被拒史注入后，同题再提议的步进选择确实改变（对照注入前后）。
- 依赖：**A1–A4**。量级：3–5。这是"递归"名实相符的收口单。

**B 任务增益（15%，4→9）**

**B1 · 真实结局升判据**
- 做什么：`task_yardstick` 读数从仅观测（`orchestrator.py:354-364`）升为 gain 的**并列构成**
  ——gain 报告体改双读数（行为地板分 + 真实结局对齐分），冲突处置按既有 GateVerdict 三态，
  回滚判据读两者（先都进快照，不硬替换单源）。
- 前置处置（写进票面）：yardstick 自认的两条诚实边界（平稳性假设、decay_rate 快重放不可观测，
  `task_yardstick.py:16-24`）——前者加"分布漂移告警读数"，后者维持 eval_harness 专用用例守。
- 红灯判据：注入"行为分涨但真实结局对齐崩"的合成流 → 综合 gain 必须判否（反向：只涨代理分
  不再自动安全）。
- 依赖：A1（读数要真臂供料）。量级：2–3。

**B2 · Goal B 任务源接入**
- 做什么：建一个**与经验挖掘数据源不相交**的固定任务流（工具使用成功/策略合规/一致性形态，
  τ-bench 式三问；数据源登记 repo 内既有会话语料的种子与来源，防 §7.1 生成器偏好污染）。
- 落点：新 fixture 通道挂 `eval/dataset.py` 的 source 体系（sourceIssues 纪律沿用）。
- 红灯判据：任务源重叠守卫——同一 knowledge_id/session 出现在挖掘与任务流两侧即红。
- 依赖：B1。量级：3–5。

**B3 · 不确定度校准**
- 做什么：`noise_repeats` 0→≥3 起步（`eval/config.py:91`），基线重复测出 δ=z·sd 噪声带
  （`eval/calibration.py:49-69` 已有算式，只差默认开）；RSI gain 报 CI，
  晋升判据读"增益下界>阈值"而非点值。
- 红灯判据：单点噪声不得触发接受/拒绝（合成两向抖动用例）；CI 缺失时判据报 `unevidenced`。
- 依赖：无（先文本进化侧，后 RSI 侧）。量级：2。

**B4 · judge 独立校验并列**
- 做什么：文本进化 fitness（`eval/fitness.py:49-71`）的 LLM 分与 B1 真实结局分**并列呈报**
  进审批面（审批人第一次同时看到"评审说好"与"结局好不好"），相关性异常（连续 N 轮背离）
  进告警（接 `RSIMetrics` 告警面）。
- 红灯判据：合成"judge 高分×结局低分"读数 → 告警触发；两列缺一时审批面显式点名缺哪列。
- 依赖：B1。量级：1–2。

- 做什么：迭代序列启动前**预定** checkpoint 时间表落盘；事后审计只读预定时刻

**D4 · 自适应污染监测曲线**
- 做什么：选择轮次 ×（holdout 分 − heldout 分差）逐轮曲线（论文"反复选择适应该验证集"的

- 红灯判据：合成"holdout 独涨 heldout 不涨"序列 → 告警触发。
- 依赖：D1/D3。量级：1–2。

**E 成本核算（10%，3→9）**

**E1 · LLM usage 单源接进成本**
- 做什么：提案生成/judge/mutator 的 token 从**既有 usage 记账链**（身份上下文按 sender 计
  的那套事件）取数，**不新建第二套计数**（教义第 6 条）；无 usage 的确定性件记轮次/墙钟。
- 红灯判据：真臂跑一步评测后 cost 事件里出现对应 usage 读数；模拟臂不冒领真 token 计数。
- 依赖：A1。量级：2–3。
**E2 · 每轮资源向量**
- 做什么：`cost_history` 的常数 1.0（`orchestrator.py:566`）换 `costVector{turns,tokens,wall_ms}`；
  ROI 分母变真；向量不相加、逐维呈报（论文资源向量口径）。
- 红灯判据：ROI=Σgain/Σcost 逐值随向量重算（旧常数路径的回归快照比对）。
- 依赖：E1。量级：2–3。
**E3 · 被拒候选成本汇总**
- 做什么：`history_ledger` 的被拒格加 realized cost 列并在治理面聚合（"被筛掉的有效候选
  与它们的成本"——§8.5 的账）。
- 红灯判据：注入一次被拒 → 聚合列出现该行成本；被拒零成本不许静默入账（漏计费守卫）。
- 依赖：E2。量级：1。
**E4 · 质量@成本里程碑**
- 做什么：共同预算帽下的质量读数点（三臂/双版本都用同一里程碑轴），替代"只看终点分"。
- 红灯判据：里程碑点缺失时报告体点名缺哪个臂（不得空线冒充）。
- 依赖：E2/A4。量级：1–2。
**E5 · 部署摊销读数**
- 做什么：C_total(N)=C_dev+N·c̄_task，c̄_task 从 serving usage 实测取数（接现有按发送者
  记账，不新算）；先以文本进化臂起步。
- 红灯判据：c̄_task 读数可回溯到真实 serving 事件样本；无样本时 N·c̄ 报 `unevidenced`。
- 依赖：E1/E2。量级：1–2。

**F 反馈与漂移（10%，5→9）**

**F1 · 外部固定参考集并列**
- 做什么：选一档外部固定参考（golden 任务流首选，B2 同源复用），performance_score 与其
  相关性逐轮报——**setpoint 贴近度代理第一次有外部对照**。
- 红灯判据：合成"代理涨×参考平"序列 → 相关性读数如实下跌（代理不得独自粉饰）。
- 依赖：B2。量级：2。
**F2 · judge 漂移台账**
- 做什么：judge-人工相关性逐轮进台账（Meta-Rewarding 教训的在册形态），连续下滑→告警；
  人工标注样本从审批动作自然采集（approve/reject 即标签，零新成本）。
- 红灯判据：注入"相关性塌"序列 → 告警；样本不足报 `insufficient_data` 不硬算。
- 依赖：F1。量级：2。
**F3 · 无新反馈对照臂**
- 做什么：实验档（非常驻开关）——同预算内切断新增外部反馈只留内部信号跑若干轮，
  量"自play 幻觉增益"；论文 §8.1 的 no-new-feedback 形态。
- 红灯判据：该臂读数与主臂分列可查；混臂即红（读数以臂为键，单源登记）。
- 依赖：F1/F2。量级：2。
**F4 · setpoint 治理**
- 做什么：四族 setpoint 从"出厂默认值"改由外部参考校准（F1 数据反哺）或明示降权，

### 10.4 风险与止损

- **判据机器本身被优化掉（Goodhart）**：A5 之后 I_t 能产新策略，D3（heldout 零引用守卫）
  与 G4（探针防摘除）是硬前置——先有反身防护，再开元优化。顺序不许倒。
- **成本爆炸**：配对探针×三臂×真轨迹是 token 大户；预算帽沿用 `planRealArmTurns` 镜像＋
  E 波实测 realized cost 反推帽值；探针默认低频（每 N 轮一次），升常驻判据前先在观测档跑稳。
- **平稳性假设破裂**：B1 的地基假设（历史成败预测后续成败）在任务流漂移时失真——
  漂移告警读数＋yardstick 的 `insufficient_data` 三态是止损线；破裂时增益判据自动降回
  行为地板单源（不硬撑双读数）。
- **小样本自评**：9 分锚点要求"首份实证在盘"——没有真实运行数据时分数只能停在锚点未达；
  本路线图**不允许**用"实装存在"冒充"证据存在"（这正是本文给本仓打分的同一把尺）。
- **每波人工复核**：预测分不等于得分；波次收尾按 §4.2 格式逐维附证据复核定分，
  复核定数低于预测时波次不封口。
