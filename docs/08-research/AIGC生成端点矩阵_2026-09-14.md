## 2. capability_detector 现有 vs 缺口
`neurova/llm/capability_detector.py` 已内置识别：seedream/seededit/seedance/qwen-image/wanx/wan2/veo/sora/dall-e/imagen/flux/kling/janus-pro 等。
缺口（本会话实测确认应补）：
- `agnes-image` → image_generation；`agnes-video` → video_generation（当前 agnes-* 无规则，会被误判 text）。
- `gpt-image` → image_generation（现仅 dall-e，gpt-image-1 未覆盖）。
- Gemini 图像新模型 `gemini-3.1-flash-image`/`gemini-3-pro-image`（nano banana 2）→ image_generation（现仅 imagen 关键词）。

## 3. 落地决策
1. **Agnes 视频 / OpenAI Sora 视频**：不做无依据预置（Repair Doctrine：禁止虚构端点）。~~Agnes 视频待拿到官方 mode 参数或提额再补~~ → **已闭环**（同日官方仓 AgnesAI-Labs/AgnesAI-Models 实核：根本无 mode 字段，轮询走 `{root}/agnesapi?video_id=`）——已适配 `VideoProtocol.AGNES`（submit/poll/body 纯函数 + runtime host 启发表 + 预置 agnes-video-v2.0，测试 `test_generation_protocols.py::TestVideoUrlRules` 5 例 + 预置 1 例先红后绿）；参考图（i2v/keyframe）字段官方未公布参数名 → 适配器诚实报错引导走 Seedance/WAN，不虚构。Sora 无公开 API，AIGC 视频页不列 OpenAI 视频。
2. **服务商预置**：后端 `_BUILTIN_PROVIDER_DEFS` + 前端 ModelPage 种子卡，新增 agnes(国际网关)，补 dashscope/gemini/openai 的默认 AIGC 模型清单（只放已验证 ID：qwen-image、wan2.7-t2v、veo-3.1-generate-preview、doubao-seedream/seedance、agnes-image-2.1-flash、gpt-image-1、dall-e-3）。
3. **AIGC 页能力过滤**：`useAigcModels` 当前已按 capability 过滤但显示全部模型；改为**仅 connectable=true**（服务商已配 key）的模型，且图像页只出 image_generation、视频页只出 video_generation，选择器视觉对齐聊天页 `ChatComposerArea` 的级联分组 + 绿/灰点。
4. 前端选中模型需把 `provider_id` 一并传给 generation 端点（`resolve_generation_creds` 优先 provider_id 取凭据），避免 Agnes 因 host 不在启发表而拿不到 key。

## 5. 实施终态（2026-09-14，本会话）
用户决策：Agnes 双网关都预置 / 视频只预置已证实端点 / 范围全做。
- **capability_detector.py**：`_IMAGE_GEN_PAT` 补 `gpt-image|qwen-image|agnes-image`，`_VIDEO_GEN_PAT` 补 `seedance|agnes-video`（seedance 无 t2v 后缀时目录族前缀吃不到，是 AIGC 下拉不显示火山视频的根因；判定序在 `_VIDEO_UNDERSTAND_PAT` 前，生成模型不再被误标视频理解）。
- **provider_manager.py `_BUILTIN_PROVIDER_DEFS`**：新增 `agnes-intl`(apihub.agnes-ai.com/v1) + `agnes-cn`(api.agnes-ai.cn/v1)，models 含已实测图像模型（`agnes-image-2.1-flash` 等，视频未证实不放）；volcengine 追加实测 `doubao-seedream-*`/`doubao-seedance-*` 静态模型。种子「只补缺失、不覆盖用户配置」不变。
- **runtime.py**：`resolve_generation_creds` host 启发表补 openai_compat↔(openai/agnes) 兜底。
- **前端 useAigcModels.ts**：只出 `connectable!==false`（后端对未配 key 回填 false）+ 对应能力模型；标签 `服务商名 / 模型名`；auto 置顶；导出 `providerOf(id)`。ImageGen/VideoGen 页选中具名模型时透传 `provider_id`（auto 不传，走后端能力路由）→ Agnes 等未进 host 表的网关可用。
- **GEMINI 图像协议未新增**：无 Gemini key 可测，`imagen/gemini-*-image` 能力检测已就位，但生成端点不凭空预置（诚实原则）；Veo 视频协议仓库已有且端点经官方核实。
- 测试：新增 `test_aigc_capability_presets`(16)、`test_aigc_provider_presets`(5)、`useAigcModels.test`(4)；`test_model_capability_endpoints::test_filter_image_generation` 因内置新增图像模型由精确等式放宽为「包含+文本不混入」（合法演进非回归）。
