## 二、甄别后判定「非空数据页 bug」（前端不消费或本就诚实回退，无需修）

- **home/data 剩余硬编码 0 字段**（total_skills/plugin_count/sleep_count/evolution_count/memory_categories/skill_categories/agent_capabilities）：DashboardPage（`useDashboardStats.ts`）仅消费 agent_count/conversation_count/memory_count/token_consumption/llm_call_count —— 这 5 项 home.py 已精心接真实源，其余 0 字段前端不读。文件头自述「无数据源回退 0」。→ 非空页 bug，可作**遗留字段清理**候选（未做，避免无消费方的投机接线违反 Simplicity First）。
- **analytics/performance p99=0、usage avg_latency=0、stats/agents per-agent tokens=0**：已文档化「无 agent 粒度埋点源的诚实零」，非缺陷。
- 合法空返回（DB 表有写入路径、当前恰好为空）：experience_knowledge/metacognition/governance/firewall/collaboration/plans/groups/provider/model/skill/memory CRUD 等 —— 排除。

## 三、登记待办（根因清晰但需产品决策 / 缺包 / 无前端消费方，本轮未动，登记台账）

### A. 需产品决策（前后端两套数据模型发散，对齐属功能而非表面 bug）
- **firewall（FirewallPage/AgentFirewallPage）**：FE 模型 `{type:allow|deny, pattern, scope, priority, active, layer}`，BE 模型 `{rule_type:ip|path|rate_limit, action, value, enabled}` 合成自 global_rules（blocked_ips/paths/rate）。FE 无 ip/path 选择器 → POST 恒缺 `value` **422 保存从不生效**；rate_limit 规则 GET 合成 id `rate_limit_minute` 三段切分 → PUT 恒 400；POST 速率分支靠 `"minute" in name.lower()` 判断，名字无英文关键字则静默不写仍返 200。**需决定规则数据模型统一口径后重做，勿半修。**
- **growth.ts constitution 前端增删改** 调 `POST /growth/constitution`、`PUT/DELETE /growth/constitution/{id}`，后端路由是 `/growth/constitution/rules[/{id}]` → **路径错位恒 404/405**（且 BE constitution 内存 setattr 无落盘）。需连前端路径与后端持久化一并定。

### B. 依赖缺失/未接线（非补码可了，属未落地功能）
- **tasks/teams/logs-api（TaskPage/TeamPage）**：`neurova.projects` 包整体不存在（TaskBoardManager/TeamManager/WorkLogSystem 三个 import 目标缺失）→ 恒回退进程内 dict 假存储，重启即空。要么补齐 `neurova.projects`，要么端点诚实下线。
- **trace（AgentTracePage/AgentTrajectoryPage）**：端点自带进程内 `TraceManager` 全仓无写入方恒空；真实记录器是 `TrajectoryRecorder`/`ReasoningTraceManager`（另一套）→ 需接真实记录器。
- ~~**notifications 残留接线缺口**：生产 `get_notification_manager()` 从不注入 `negative_screen_config_manager` → 负一屏推送链路休眠~~ **同日修复（用户指定「修复残留」，注入点+调度桥两半）**：① 单例缺省注入 `NegativeScreenConfigManager()`（与负一屏设置页同源目录 `data/negative_screen`；构造失败降级为无推送、铃铛不受影响）；② 排查发现更深一半——`task_completed` 通知类型**全仓无生产者**（调度器 `_emit_event` 的 `_event_handlers` 零注册），注入后仍无人触发。`get_scheduler()` 创建时注册事件桥（单例守卫天然幂等）：task_completed→task_completed 通知（走负一屏推送判定）、task_failed→普通站内通知，接收人 `notify_admins`（单机兜底 default）。`test_notifications_negative_screen_bridge.py` 7 用例先红后绿（含全链集成钉：真 config manager+假 pusher→后台线程回写→跨实例落盘回读；及桥幂等/落盘断言）。
- **sandbox（SandboxPage）/image builds(AIGCPage)/media 列表/files 列表**：`_SANDBOXES`/`_builds_store`/`_media_store`/`_files_store` 内存索引，files/media 文件写盘但重启后索引不扫回磁盘 → 列表恒空。需「启动扫盘重建索引」或持久索引。
- **memory/reflection.py**：读 `agent.reflection_manager`（全仓无赋值）恒空；`/logs` 调 `MemoryManager.get_reflection_logs()` 等不存在方法 → 必进 except 分支（live 实测多端点 500）。与已修的 `metacog_manager` 同型平行假数据源。
- **sleep dreams/insights/merges/conflicts**：`run_sleep_cycle` 有写入但进程内 list 无落盘 → 重启页面空。
- **growth motivation/proactive**：`proactive_behavior_engine` 全仓无实例化 → motivation 恒默认、proactive 恒 uuid 伪造 3 条 mock。
