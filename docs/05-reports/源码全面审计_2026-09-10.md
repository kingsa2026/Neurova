## 总体判断

功能纵深是真实的：evolution/ 12 个文件（8297 行）无纯骨架，genetic_engine（种群/适应度）、pattern_miner（PrefixSpan）、closed_loop、RSI orchestrator 均为真实现——与 AGENTS.md "partially skeletal" 的旧口径不符（勘误）。

但存在三条系统性主线贯穿全库：

1. **事件循环同步 I/O**——async 路径上遍布同步 SQLite/文件/HTTP 调用（跨 5 个域均命中）
2. **"声明了但没接线"**——沙箱声明面、docker 运行时假分支、provider 健康度负载均衡死链、审批闸门零调用、真流式存在未接线
3. **单例实例状态 + 并发**——轮次身份挂单例 Agent 实例属性、provider/上下文 dict 裸读写

### P0-1 沙箱是"声明性"的，不是真实的

三处叠加构成假隔离：

| 子项 | 证据 | 说明 |
|------|------|------|
| 强制开关默认关 | `neurova/security/governance.py:65-74` | `NEUROVA_TOOL_SANDBOX_ENFORCE` 默认关，run_code/shell 的 `sandbox_required: True` 声明（builtin_tools.py:557）仅是展示面 |
| 开关打开也无效 | `neurova/security/governance.py:29` | `_ENFORCED_SANDBOX_BACKENDS = {}` 恒空 → `_platform_has_enforced_sandbox()` 恒 False → 开了就**全禁**（governance.py:425-427），而非隔离执行；exec_sandbox 侧明明有 bwrap/seatbelt/AppContainer/RestrictedToken 后端探测 |
| docker 分支假实现 | `neurova/tool_executor.py:3263-3270` | `runtime_type="docker"` 调 `RuntimeManager.create_runtime_class(...)`——该方法不存在（execution_layers/__init__.py:589-638），hasattr 守卫恒 None 静默回退裸 `LocalExecutor` = 裸 `subprocess.Popen`（继承完整 os.environ、无文件系统/网络隔离），返回值却标 docker 让调用方以为容器隔离 |

**实际状态**：run_code 默认在本机裸跑，只有内容检测命中 HIGH 才进沙箱。

**修复方向**：填充后端探测表；删除假 docker 分支改显式拒绝；enforce 默认开或 run_code 默认走 `execute_in_sandbox`。

### P0-3 Agent 单例实例属性存轮次状态，并发互踩

- **证据**：`agent_core.py:1907-1920`（`set_request_identity` 写 `self._current_user_input/_current_session_id/_current_user_id`）、`chat_pipeline.py:477-489`（每请求 `set_current_reasoning(None)` + `reset_tool_messages()`）、`agent_core.py:1895-1897`（读共享 `_tool_messages_list`）、`tool_executor.py:2097-2105`（`_recall_loop_guard` 挂实例）
- **后果**：Agent 是单例（app.py AppState.agents 共享池），两用户同时对同一 agent 发消息时请求 B 覆盖请求 A 的身份/工具消息——A 的回复可能带上 B 的身份；工具层三层隔离、事件广播、产物归属全依赖这些字段。管道已有 ContextVar 先例（request_user_id，chat_pipeline.py:365-370），这套轮次态没迁
- **修复方向**：`_current_*` 与 `_tool_messages_list` 全迁 ContextVar（与 set_request_user_id 同模式），guard 按 session_id 分桶

### P0-4 /attachment 端点无鉴权

- **证据**：`neurova/api/endpoints/chat.py:422-423`，无 `Depends(get_current_user)`（同文件 103/197/300/366 行均有）；接受任意 `file_path`
- **现状**：TODO stub 只回显；一旦实现附件落盘即成未授权文件读写面
- **修复方向**：补鉴权 + `_user_can_access_agent`；stub 期 404/501 更稳

### P0-5 假流式：公开 /chat/stream 恒走全量降级

- **证据**：`chat.py:244-264`（注释自认"Agent 类现无 chat_stream 方法——恒走此分支"）；`agent_core.py:1720-1725` 的 `chat_stream` 也是先 `await self.chat(...)` 拿完整回复再切块；真流式路径 `_call_loop_stream`（chat_pipeline.py:1729）存在未接线
- **后果**：首 token 延迟 = 全响应时长；长回复期间连接无心跳（console.py 的 /console/chat 有 15s ping，此端点没有），代理/网关易掐断；前端主聊天全走这条路
- **修复方向**：chat_stream 传 stream=True 走 _call_loop_stream 增量 yield，post-chat 后置到 done 事件前

### P0-6 LLM 流式路径绕过限流器与熔断器

- **证据**：`multi_model_client.py:744-878`——`chat()` 经 `_chat_single_attempt` 做 `get_shared_limiter().acquire()` + retry/circuit-breaker（:611-627），`chat_stream()` 直接调 `client.client.chat_stream_async(...)` 全无
- **后果**：前端主流量全走流式 → per-model QPM/并发上限/429 暂停在主路径上是空的
- **修复方向**：chat_stream 包相同 limiter acquire/release + 熔断检查，流内 429 走 report_429

### P0-7 记忆 persist.db 无 WAL + 每轮写放大

- **证据**：`manager.py:282,340,414,445,495` + `mem_core.py:86`——每条记忆一次完整 connect→INSERT→commit→close，默认 DELETE journal 每次 commit 都 fsync；同项目 dependency_graph.py:111-112 等已用 `WAL + synchronous=NORMAL`，唯独写入最频繁的核心库没有。每轮对话 ≥12 次独立事务：remember×2（post_chat_pipeline.py:664-676）+ recall 对 top-10 逐条 touch→_persist_memory（manager.py:883-887）+ 依赖图逐 entity/edge（dependency_graph.py:188-234）
- **修复方向**：常驻连接（check_same_thread=False + 锁）+ WAL/NORMAL；touch 改批量事务或延迟落盘队列

### P0-8 记忆全表驻内存

- **证据**：`manager.py:342-346` 启动 `SELECT * FROM memories WHERE agent_id=?` 全量 json.loads + fromisoformat 驻留 `self._memories`；代码注释自证已出现 232 万行的库（manager.py:319）；所有读路径（_scoped_memories，manager.py:561-569）在全量 dict 上线性过滤
- **修复方向**：SQL 分页/索引查询替代全量驻留，或按三级隔离分区缓存

### P0-9 前端流式渲染 O(n²)

- **证据**：`ChatPage.vue:1463`（`msg.content += ...` 每 chunk 直写响应式）+ `:210`（`v-html="renderRichContent(msg.content)"`）——对流式中的消息**全文**重跑 renderMarkdown（marked+DOMPurify+语法高亮，utils/markdown.ts 无 memo），长回复解析量随长度平方增长，同时带动窗口内 60 条消息的列表 diff
- **修复方向**：chunk 进非响应式缓冲，rAF（30-50ms）节流刷入；非流式消息按内容 hash 缓存渲染结果
