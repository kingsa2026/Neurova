## 3. 为什么"零产出一轮"没有人接着跑

收尾接力的判据（ADR 0022）是平台在**收尾时刻**注入的两条事实：

```
$CNB_PIPELINE_STATUS = error
$CNB_BUILD_FAILED_STAGE_NAME 命中 npc-go
```

零产出收官是 `success`，两条都不成立 ⇒ 收尾 Stage 每次 `skipped`。
五条构建逐条如此（`轮数触顶接力…: 160ms (skipped)`）。

于是本轮改而未提交的改动（工作树不跨轮保存）随容器一起丢，
Issue 上只留一条构建号 —— 用户读到的就是「空转」。

## 4. 根因与修法（修在产生非法状态的那一处）

分成两个事实，缺一不成立：

| # | 事实 | 可核读数 |
|---|------|----------|
| 1 | 推理吃满单轮输出预算 ⇒ 该轮零正文零工具调用 | 五条构建末轮 `out=32000` 且 `reasoning_tokens=32000`、正文 0 字符 |
| 2 | 零产出收官是 `success` ⇒ 收尾判据不成立 ⇒ 无人接手 | 五条构建收尾 Stage 一律 `skipped` |

仓库侧能改的只有三处：`.cnb.yml` 的运行参数、`.cnb/settings.yml` 的角色人设、
`scripts/ci` 的门禁脚本。其中**唯一进 Agent 上下文**的通道是角色 `prompt`
（`npc:go.options` 不认 `prompt` 键，评论触发时提示词一律由角色自带）。

已在人设里的「时间预算硬约束」只覆盖**墙钟**（sleep 轮询 / 单条命令超时 /
宽匹配 `pkill`），上一版对单轮输出预算**只字未提**。于是 Agent 按"等我全部
想清楚再一次性交代"的方式工作，一次长推理就把整轮预算烧掉，连交代的机会都没有。

修法：**在六个在册角色的 prompt 上补一段「单轮输出预算纪律」条款**，
把两条事实与动作约束写进唯一必达通道（条款正文逐字一致）：

- 点名单轮输出预算与推理共享、推理吃满即当轮终止（附五条构建的实测读数）；
- 点名零产出一轮**不会触发接力**（收尾判据读哪两个变量、为什么两条都不成立）；
- 给出动作：**先落盘，后继续** —— 每完成一个可独立成立的片段就
  commit / push / 回帖，再开下一段。

## 5. 判据（红 → 绿实测）

新守卫 `tests/unit/ci/test_npc_turn_output_budget_discipline.py` 钉四件事：

- **A 条款在册**：每个在册角色的 prompt 都必须含该条款；
- **B 覆盖四条事实**：单轮输出预算 / 推理 / 零产出 / 不会触发接力；
- **C 有动作不只有现象**：必须给出可执行的「先落盘」；
- **D 条款正文逐字一致**：防「改一处漏一处」的静默漂移。

## 7. 未闭环（点名，不静默）

1. **共享正文的手抄形态未收口**：六份 prompt 是手抄的。改为 YAML 锚点要求平台
   YAML 解析支持且行为等价，本仓**无法在本地自证**（改错会让全部 NPC 配置期失效），
   故本轮不动配置，只登记在此。漂移风险由守卫的 D 条（逐字比对）拦住。
2. **32k 的出处不可核**：平台文档只写「`maxTokens` 取值范围 48k ~ 1m」，
   未声明单轮输出上界；实测 `out` 恒为 32000。故条款按**实测读数**写，
   不写死"平台上限是 32000"这一因果断言（平台换模型即失效）。
3. **端到端确认需要下一轮真实会话**：本轮只能自证「指令面已覆盖死因」，
   不能自证「下一轮 Agent 一定不再吃满预算」—— 那是 Agent 的运行时行为，
   属指令面修法的固有边界。
4. **`@CodeBuddy` 系统 NPC 不受本修影响**：它走平台默认配置，不读本仓人设
   （同源结论见 `docs/05-reports/npc续跑角色连续性_2026-09-26.md` §1.2）。
   要吃到本条款必须用本仓角色（`@kingsa2026/neurova(DSCoder-*)`）。
