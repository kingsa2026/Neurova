## 1. 用户看到的现象与真实死因

Issue #256 附的构建链接指到 `cnb-5bc-1k3e046c7`。该构建**不是门禁**：

```
流水线: cnb-5bc-1k3e046c7-001 (status: error)
失败 Stage: s
错误信息: 任务执行失败，返回码：125
日志: docker: Error response from daemon: Invalid container name (x),
      only [a-zA-Z0-9][a-zA-Z0-9_.-] are allowed
```

`docker run -d --name x …` 这一行、以及 `x` 这个容器名，在**本仓 `main` 的
任何一个提交里都不存在**（`git log --all` 全量对象扫描的读数）——它是
`cnbcool/default-npc:latest` 镜像自带 entrypoint 的探测动作，被一个**掺坏的环境变量**
连累。真正要判读的不是这一行，而是 `--name` 的**实参**。

## 2. 根因：载体层 env 的自引用，把值掺成字面量

`.cnb.yml` 的接力链上有三处 `env` 映射，此前键集合**不成对**：

```yaml
# issue.comment@npc 的收尾接力（只供自己那一侧）
env:
  handoffIssueIid: $CNB_ISSUE_IID
# pull_request.comment@npc 的收尾接力（同样只供自己那一侧）
env:
  handoffPrIid: $CNB_PULL_REQUEST_IID
# 接力落点 api_trigger_npc_handoff 的载体层（两个键都声明）
env:
  handoffIssueIid: $handoffIssueIid   # ← 自引用：上一跳根本没传这个键
  handoffPrIid: $handoffPrIid         # ← 同理
```

平台对「无值变量」**不报错、不告警**（平台「环境变量」篇：`$name` 无值时替换为空串），
而配置里写了 `$handoffPrIid` 这种**同名自引用**时，替换的输入恰好是它自己。
于是：

1. 该跳把它写成字面量（实测 18 字符：`$handoffPrIid-1k3ddqln6`）；
2. 下一跳的 carries 再读它、再写一次，**沿链越掺越长**（35 → 84 字符）：

```
+84 characters ... "...$handoffPrIid-1k3ddqln6$handoffPrIid"
```

3. 这个值进入 `cnb:trigger` 的目标流水线名/构建参数，报错落在**与它无关**的地方
   （镜像 entrypoint 的 `docker run --name` 收到了一个含 `$` 的名字）。

## 3. 修法（教义第 1 条：修在生产非法状态的那一处）

非法状态的生产点**不是**报错那一格，而是"声明了 `$同名变量`、却没有任何一跳
向它赋值"这种写法本身。故修法是让键集合**对齐**：

- 接力落点（载体）**删掉自引用的 `env` 层**：真值由触发方经
  `cnb:trigger.options.env` 直接注入（平台「环境变量」篇：子流水线的 env 由触发方给出）；
- 三个触发方（两条评论事件 + 载体自身的续链跳）把两个键**都显式供上**，
  不适用的一侧给空串 —— 空串是有界的，不会掺坏目标流水线名。

判据落在"被触发方承诺会读的键"与"每一跳供上的键"的**集合关系**上，不落在
注释或取值形态上。载体层的承诺面取「它自己声明的键」∪「上游 `options.env` 里
对它 `$handoff*` 的直接引用」——后者是必要的：载体层不声明 `env` 时，
承诺面只能从引用读出。

## 6. 未闭环（点名，不静默）

- 本批不轮询 CI（时间预算纪律）。载体层的 `env` 是可选读取面，删掉它不影响
  `npc:go` 读 `$handoffIssueIid` —— 该变量仍由触发方的 `options.env` 直接注入；
  下一轮接力一旦跑起来，上游 `+N characters` 的掺值警告应当消失。
- 若平台对"空串 env 值"另有语义（例如视为未设置），接力轮会读到空串而非缺失，
  行为与现状等价（缺失同样是空）；由 `cnb:trigger` 的
  `options.env` 逐键枚举保证**不出现缺键**，这才是本条判据要守住的东西。
