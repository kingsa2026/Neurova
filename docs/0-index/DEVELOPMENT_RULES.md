# Neurova 开发准则（Development Rules）

> 版本: v1.0.0 · 生效日期: 2026-09-21 · 状态: **强制**
> 本文是 Neurova 全仓**唯一**的协作红线事实源。所有人类协作者与 NPC 角色
> （见 `.cnb/settings.yml`）执行任务时一律以本文为准；规则变更只改本文 +
> `.cnb/settings.yml` 人设两处，二者由
> `tests/unit/test_devRulesConfigGuard.py` 常驻校验，不允许只改一侧。

---

## 1. 交流语言：中文

- 面向用户的回复、Issue / PR 评论、提交信息正文、文档正文**一律使用中文**。
- 代码标识符、命令、路径、第三方 API 字段名保持原文，不做翻译。
- 面向国际化的产品文案仍按 `docs/i18n/` 的 11 语言对齐纪律执行，
  不因本准则放宽。

## 2. 开发模式：TDD 红绿灯

严格按「红 → 绿 → 重构」三段推进，禁止先写实现后补测试：

1. **红灯**：先写会失败的测试（新功能先写期望行为，修 Bug 先写复现用例），
   本地跑出**确定的失败**，并记录失败信息与失败原因。
2. **绿灯**：写**最小**实现使测试通过，不夹带无关改动。
3. **重构**：在绿灯保护下清理结构、命名与重复，重构后测试必须仍绿。
4. **验证**：涉及共享文件（`chat_pipeline` / `tool_executor` / `mem_core` 等）时，
   用 `git stash` 做 A/B，证明失败集合修复前后逐行相同——**预存失败不算回归，
   新增失败才算**。

交付说明里必须写清：红灯阶段失败了几条、绿灯后通过几条、依据是什么。

## 3. Bug 修复：放大视角，修根因

- 先定位**根因**，再看补丁；只修表象、吞掉异常、加宽 `try/except`、
  注释掉断言、放宽校验一律视为未修复。
- **放大视角**：同一病根要查全仓所有调用方与同源写法，一次性收口，
  不留「同类问题下次再爆」。示例：值域重复定义要收敛为一份权威枚举，
  而不是在每个调用点各打一个补丁。
- **不得抹除或规避表面报错**：报错是证据，先解释它为何出现，再让它在
  根因消除后自然消失。
- 修复要有可复现证据：复现步骤 / 用例名 / 修复前后的读数对比。

## 4. 增加功能与升级改造：全局视角，不断点，成闭环

- **先看全链路**：数据从哪来、经谁处理、到哪去、谁消费，缺一环即为断点。
- **不留断点**：写出但无人读的字段、注册但无消费者的模块、只写不读的配置、
  只读不写的指标，均属断点，必须接线或删除。
- **形成闭环**：写入 → 读取 → 反馈 → 再写入 的回路要闭合；观测面要有读数，
  读不到就等于不存在。
- 升级改造同理：老路径的退役与新路径的接线必须同批完成，不做「先上新的、
  旧的以后再说」。

## 5. 原创性与自主性

- **严禁**在代码注释、技术文档、提交信息中引用、模仿或对齐任何第三方项目：
  不写「参考 XX 项目」「对齐 XX 实现」「与 XX 保持一致」之类表述，
  不搬运其命名、结构与措辞。
- 所有产出必须基于当前项目的**独立设计与实现**，可追溯到本仓自身的
  需求、约束与取舍。
- 外部依赖只作为**功能依赖**登记（版本、许可、用途），不引入其设计标准；
  研究参考类文档仅作背景，**不可作事实源**。

## 6. 命名风格：Neurova 技术美学

命名是本项目的对外表达方式，必须统一、精确、有领域感。

| 对象 | 规则 | 示例 |
|------|------|------|
| 变量、函数、方法 | **camelCase** | `resolveMemoryAnchor()`、`memoryTemperature` |
| 类、模块、类型 | **PascalCase** | `MemoryRecallEngine`、`ContextPoolIndex` |
| 常量 | 全大写下划线（沿用既有工程惯例） | `MAX_RECALL_DEPTH` |
| 测试用例函数 | `test` + camelCase 段落 | `testClassifyMemoryClosesLoop` |

- 命名要**简洁、语义清晰**，体现功能意图与业务领域。
- **禁用**通用或模糊词汇：`data`、`info`、`temp`、`handler`、`manager`、
  `util`、`helper`、`process` 等，除非叠加领域限定
  （如 `memoryTemperature`、`skillRegistryStore`）。
- 新增测试用例名用驼峰时，pytest 收集由 `pyproject.toml` 的
  `python_functions = ["test_*", "test[A-Z]*"]` 放开（守卫自身除外，
  由 `tests/unit/core/test_pytest_collection_hygiene.py` 反向锁住）。

## 7. 规则文档与测试目录的归属

- **规则文档统一存放于 `docs/`**，本文件即唯一入口；仓库根目录不再新增
  准则 / 规范 / 约定类文档。新增准则在 `docs/0-index/README.md` 登记。
- **测试用例统一存放于本仓唯一测试根 `tests/`**，并**按功能模块分子目录**
  组织：
  - `tests/unit/<module>/` — 单元测试
  - `tests/integration/` — 跨模块 / 真实 IO 集成
  - `tests/e2e/` — 端到端；`tests/performance/` — 基准
  - `tests/fixtures/` — 共享数据；`tests/runners/` — 运行器

  > 需求口径中的「TEST 文件夹」即本仓唯一测试根 `tests/`。整目录更名属全仓
  > 路径迁移（影响 `pyproject.toml`、CI、`scripts/ci/*`、大量守卫与文档），
  > 须单独立项、分批迁移并同步全部引用；**不得**另建第二个测试根造成双源。

## 8. 提交规约

- Conventional Commits：`feat(scope): ...` / `fix(scope): ...` /
  `refactor(scope): ...` / `docs: ...` / `chore: ...`，**正文用中文**。
- 单任务单提交；提交正文说明动机与根因，不写「改了什么」的流水账。
- 只 `git add` 本任务文件，**不要** `git add -A`（工作树常含并行会话的改动）。

---

## 无准则例外

本文无「紧急可绕过」条款。确需偏离时，必须在 PR 描述中显式说明偏离点、
原因与补偿措施，并同步更新本文——规则与行为不一致时，以**改规则**为准，
不以「默认这么做」为准。
