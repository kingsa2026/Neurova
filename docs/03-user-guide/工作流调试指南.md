## 〇、功能总览

NeurFlow 工作流已具备 **断点调试 + 单步控制 + Mock 输出** 三件套，把画布从"只能跑"升级为"可调试"。借鉴 [smart-flow](https://github.com/MrXujiang/smart-flow) 的"工作流 IDE"差异化能力。

| 能力 | 状态 | 入口 |
|---|---|---|
| **断点** | ✅ 已支持 | 节点右键 → Toggle Breakpoint |
| **单步** | ✅ 已支持 | 调试面板 Step In/Over/Out |
| **Mock 输出** | ✅ 已支持 | 节点属性面板 → Mock 标签页 |
| **变量监控** | ✅ 已支持 | 调试面板实时刷新 |
| **流式调试 API** | ✅ 已支持 | `execute_debug()` async generator |
| **画布集成** | ⏳ 集成中 | 独立 PR |

## 一、后端 API（4 个端点）

所有调试端点注册在 `/neurflow` 命名空间，由 `neurova/api/endpoints/neurflow_api.py` 提供。

### 1.1 设置断点

```http
POST /neurflow/executions/{execution_id}/breakpoint
Content-Type: application/json

{
  "breakpoints": ["node_a", "node_b"],
  "replace": true
}
```

**字段说明：**
- `breakpoints`：节点 id 数组
- `replace`：`true` 整体替换（默认）/ `false` 追加到现有集合

**响应：**
```json
{
  "execution_id": "exec_xxx",
  "breakpoints": ["node_a", "node_b"],
  "count": 2
}
```

### 1.2 恢复执行

```http
POST /neurflow/executions/{execution_id}/resume
Content-Type: application/json

{
  "step": "in"   // 可选："in" | "over" | "out"
}
```

**字段说明：**
- `step`：单步模式
  - `in`：进入子工作流
  - `over`：跳过当前节点（不进入子流程）
  - `out`：跳出当前子流程
  - `null`：直接继续到下一断点或完成

**响应：**
```json
{
  "execution_id": "exec_xxx",
  "resumed": true,
  "step_mode": "in"
}
```

### 1.3 查询变量

```http
GET /neurflow/executions/{execution_id}/variables
```

**响应：**
```json
{
  "execution_id": "exec_xxx",
  "inputs": { "query": "..." },
  "variables": { "user_msg": "..." },
  "node_results": {
    "node_a": {
      "status": "success",
      "output": "..."
    }
  }
}
```

### 1.4 设置 Mock 输出

```http
PUT /neurflow/nodes/{node_id}/mock
Content-Type: application/json

{
  "mock_output": { "answer": "mocked", "tokens": 42 },
  "clear": false
}
```

**字段说明：**
- `mock_output`：节点命中此 mock 时返回的输出（JSON 任意值，None 表示无 mock）
- `clear`：`true` 时清除 mock（恢复真实执行）

**响应：**
```json
{
  "node_id": "node_a",
  "mocked": true
}
```

**注意**：mock 命中判定是 `mock_output is not None`——`0` / `""` / `false` / `{}` 都是合法 mock 值，**不是** "清除"。

## 二、流式调试 API

后端 `WorkflowExecutor.execute_debug()` 是 async generator，按拓扑顺序 yield 事件：

```python
from neurova.collaboration.neurflow.execution_engine import (
    get_workflow_executor,
    DebugSession,
    ExecutionEventType,
)

executor = get_workflow_executor()
session = DebugSession(breakpoints={"node_a"})

async for event in executor.execute_debug(workflow, inputs, debug_session=session):
    if event.type == ExecutionEventType.BREAKPOINT_HIT:
        # 命中断点：当前节点暂停，外部可调 session.resume() 继续
        print(f"Paused at: {event.node_id}")
    elif event.type == ExecutionEventType.VARIABLE_SET:
        # 变量被设置（含 scope/value_preview）
        print(f"Var: {event.data}")
```

**事件类型枚举：**

| 事件 | 含义 | 触发时机 |
|---|---|---|
| `WORKFLOW_STARTED` | 工作流开始 | 入口 |
| `WORKFLOW_COMPLETED` | 工作流完成 | 全部节点完成 |
| `WORKFLOW_FAILED` | 工作流失败 | 任一节点抛错 |
| `NODE_STARTED` | 节点开始执行 | 节点执行前 |
| `NODE_COMPLETED` | 节点执行完成 | 节点执行后 |
| `NODE_FAILED` | 节点失败 | 节点抛错 |
| `NODE_SKIPPED` | 节点被跳过 | 条件分支未命中 |
| `BREAKPOINT_HIT` | **断点命中** | 节点执行前（若 node 在 breakpoints 集合） |
| `STEP_ADVANCED` | **单步推进** | resume 触发后 |
| `VARIABLE_SET` | 变量被设置 | variable 节点写入 |
| `VARIABLE_SCOPED` | **带 scope 的变量** | 含 local/global 区分 |

## 三、DebugSession API

`DebugSession` dataclass 是调试会话控制对象：

```python
from neurova.collaboration.neurflow.execution_engine import DebugSession

session = DebugSession(
    breakpoints={"node_a", "node_b"},   # 断点集合
    step_mode=None,                     # 单步模式（None/in/over/out）
)

# 阻塞等待恢复信号
await session.wait_resume()

# 同步触发恢复（不可 await）
session.resume()

# 重置 resume 事件（允许下一次阻塞）
session.reset()
```

## 四、前端使用

### 4.1 DebugPanel 组件

```vue
<script setup lang="ts">
import { ref } from 'vue'
import DebugPanel from '@/modules/collaboration/DebugPanel.vue'

const controller = createDebugController('exec_xxx')

function handleToggleBreakpoint(nodeId: string) {
  // 调用后端：POST /neurflow/executions/{id}/breakpoint
  // ...
}

function handleResume(payload: Record<string, unknown>) {
  // 调用后端：POST /neurflow/executions/{id}/resume
  // payload = { step: "in" } | {}
  // ...
}

function handleClearMock(nodeId: string) {
  // 调用后端：PUT /neurflow/nodes/{id}/mock { clear: true }
  // ...
}
</script>

<template>
  <DebugPanel
    :controller="controller"
    execution-id="exec_xxx"
    @toggle-breakpoint="handleToggleBreakpoint"
    @resume="handleResume"
    @clear-mock="handleClearMock"
  />
</template>
```

### 4.2 MockEditor 组件

```vue
<MockEditor
  :node-id="selectedNodeId"
  v-model="mockValue"
  @clear="handleClearMock"
/>
```

`MockEditor` 自动解析 JSON、显示错误；合法时 emit `update:modelValue` 给父组件。

### 4.3 控制器（composable）

```ts
import { createDebugController } from '@/modules/collaboration/DebugPanel'

const ctrl = createDebugController('exec_xxx')

// 切换断点
ctrl.toggleBreakpoint('node_a')

// 设置单步模式
ctrl.setStepMode('in')

// 设置 mock
ctrl.setMockOutput('node_a', { answer: 'mocked' })

// 清除 mock
ctrl.clearMock('node_a')

// 更新变量
ctrl.setVariables({ user_msg: '...' })

// 构造 resume 请求体
import { buildStepModePayload } from '@/modules/collaboration/DebugPanel'
const payload = buildStepModePayload(ctrl.stepMode.value)  // { step: "in" } | {}
```

## 五、典型调试流程

```text
1. 在画布设计工作流 → 保存
2. 启动调试执行：
   POST /neurflow/workflows/{wf_id}/execute
   → 返回 execution_id
3. 设置断点：
   POST /neurflow/executions/{exec_id}/breakpoint
   { "breakpoints": ["llm_node_1"] }
4. 启动流式执行（前端使用 DebugPanel + controller）
   后端走 execute_debug() 流式 yield
5. 命中断点：BREAKPOINT_HIT 事件 → 前端暂停
6. 检查变量：
   GET /neurflow/executions/{exec_id}/variables
7. 单步/继续：
   POST /neurflow/executions/{exec_id}/resume
   { "step": "over" }
8. 重复 5-7 直到完成
9. 若需替换某节点输出：
   PUT /neurflow/nodes/{node_id}/mock
   { "mock_output": { "answer": "mocked" } }
   然后重新执行验证下游逻辑
```

## 六、安全约束

- 断点 API 不暴露敏感数据（`variables` 字段按需返回，不放密码/token）
- 执行实例（executions）已有 user_id 隔离（`storage.get_execution` 默认按 user 过滤）
- mock 数据仅在内存（`_NODE_MOCKS` dict），不持久化到 DB——重启即失效
- HMAC 与触发器相关将在 P1 引入（参见 [触发器配置指南](./触发器配置指南.md)，待补）

---

## 七、已知限制（P0 范围）

1. **画布集成未交付**：右键菜单/属性面板 Mock 标签页未接入 `CanvasDesignerPage.vue`，需独立 PR
2. **执行引擎集成未完成**：`execute_debug()` 当前按拓扑序 yield 事件但未调用节点 executor——完整执行链路在 P0 后续 Step 完成
3. **Mock 不持久化**：in-memory dict，重启失效；若需持久化需扩展 `node_definitions.executor_body_json` 字段
4. **无 UI 实时推送**：变量监控需前端轮询 `GET /executions/{id}/variables`，未走 SSE/WebSocket
5. **单步粒度**：当前 step in/over/out 语义仅在 BREAKPOINT_HIT 触发后有效，未支持任意位置暂停
