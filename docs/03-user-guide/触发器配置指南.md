## 〇、功能总览

NeurFlow 工作流支持三种触发方式，形成"画布即自动化平台"形态：

| 触发方式 | 安全机制 | 典型场景 |
|---|---|---|
| **Webhook 入站** | HMAC-SHA256 验签 + 限流 | 外部系统（GitHub/飞书/自建服务）事件驱动 |
| **Cron 定时** | 仅已发布工作流 | 定时报表、轮询任务、日常自动化 |
| **Manual** | API 直调 | 测试、手工触发 |

**硬约束**：仅 `PUBLISHED` 状态的工作流可被任何触发器派发。

## 一、快速开始（Webhook + HMAC）

### 1.1 创建 webhook 触发器

```bash
curl -X POST http://localhost:9527/api/v1/neurflow/workflows/{workflow_id}/triggers \
  -H "Content-Type: application/json" \
  -d '{"type": "webhook", "rate_limit_per_minute": 30}'
```

**响应**（明文 secret 仅此一次返回，请妥善保存）：

```json
{
  "code": 0,
  "data": {
    "trigger": {
      "id": "trg_a1b2c3d4e5f6",
      "workflow_id": "wf_xxx",
      "type": "webhook",
      "rate_limit_per_minute": 30
    },
    "secret": "kR9xP2mQ..."
  }
}
```

### 1.2 计算签名并触发

签名格式为 GitHub 风格 `X-Hub-Signature-256: sha256=<hex>`（HMAC-SHA256，key=secret，message=原始请求体字节）：

```bash
SECRET="kR9xP2mQ..."
PAYLOAD='{"payload":{"message":"hello"}}'
SIG="sha256=$(printf '%s' "$PAYLOAD" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $2}')"

curl -X POST http://localhost:9527/api/v1/neurflow/triggers/webhook/{trigger_id}/receive \
  -H "Content-Type: application/json" \
  -H "X-Hub-Signature-256: $SIG" \
  -d "$PAYLOAD"
```

**响应**（202 语义，同步返回派发结果）：

```json
{
  "code": 0,
  "message": "Triggered",
  "data": {
    "trigger_id": "trg_a1b2c3d4e5f6",
    "execution_id": "exec_xxx",
    "status": "completed"
  }
}
```

Python 生成签名示例：

```python
import hmac, hashlib

def compute_signature(payload: bytes, secret: str) -> str:
    return "sha256=" + hmac.new(secret.encode(), payload, hashlib.sha256).hexdigest()
```

### 1.3 错误码

| 状态码 | reason | 说明 |
|---|---|---|
| 401 | `INVALID_SIGNATURE` | 签名缺失/错误/篡改 |
| 404 | `TRIGGER_NOT_FOUND` | 触发器不存在或未启用 |
| 404 | `WORKFLOW_NOT_PUBLISHED` | 绑定的工作流未发布 |
| 429 | `RATE_LIMIT_EXCEEDED` | 超过 rate_limit_per_minute |
| 400 | `INVALID_JSON` | 请求体不是合法 JSON |

## 二、安全语义

### 2.1 严格模式（配置了 secret）

创建 webhook 触发器时自动生成 secret。库中存储两份：

- **AES-GCM 密文**（`secret_encrypted`）：入站验签时解密还原原 secret 计算 HMAC
- **SHA-256 hash**（`secret_hash`）：审计比对用，不可逆

验签使用 `hmac.compare_digest` 常量时间比较（防时序侧信道）；hex 大小写不敏感。

### 2.2 宽松模式（未配置 secret 的开放 webhook）

当前 API 创建的 webhook 触发器一律自动生成 secret（严格模式）。开放模式预留于 `webhook_ingress.handle_webhook_ingress`：未配置 secret 的 trigger 仅拒绝**携带**签名头的请求（防止伪造头绕过）。

### 2.3 限流

Token bucket 实现（`neurova/core/trigger_rate_limiter.py`）：

- 容量 = `rate_limit_per_minute`，按流逝时间匀速回填
- 每 trigger_id 独立桶（跨请求共享，重启后重置）
- `rate_limit_per_minute: null` = 不限流

## 三、Cron 定时触发

### 3.1 创建

```bash
curl -X POST http://localhost:9527/api/v1/neurflow/workflows/{workflow_id}/triggers \
  -H "Content-Type: application/json" \
  -d '{"type": "cron", "config": {"cron": "0 9 * * 1-5"}}'
```

- `cron` 表达式为标准 5 段 crontab（分 时 日 月 周），经 `CronTrigger.from_crontab` 校验
- 创建成功即尝试注册 apscheduler job；调度器未就绪时在应用启动恢复阶段补齐

### 3.2 示例表达式

| 表达式 | 含义 |
|---|---|
| `0 9 * * 1-5` | 工作日每天 09:00 |
| `*/5 * * * *` | 每 5 分钟 |
| `0 0 1 * *` | 每月 1 日零点 |

## 四、管理 API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/neurflow/workflows/{wid}/triggers` | 列出触发器（secret 不回显） |
| POST | `/neurflow/workflows/{wid}/triggers` | 创建触发器 |
| DELETE | `/neurflow/triggers/{tid}` | 删除（同步移除 cron job） |
| POST | `/neurflow/triggers/{tid}/fire` | 手动触发（测试用） |
| GET | `/neurflow/triggers/{tid}/deliveries` | webhook 投递记录（倒序，limit 默认 50） |

投递记录字段：`trigger_id / signature_valid / execution_id / status_code / latency_ms / created_at`——401 拒绝与 429 超限同样可追溯。

## 五、架构说明（开发者）

```
外部系统 ──POST + X-Hub-Signature-256──▶ /triggers/webhook/{id}/receive   (FastAPI 薄壳)
                                              │
                                              ▼
                                   webhook_ingress.handle_webhook_ingress   (纯注入业务链)
                                              │
                              ┌───────────────┼────────────────┐
                              ▼               ▼                ▼
                     load_trigger     verify_signature   rate_limiter_for
                     (storage)       (webhook_security)  (trigger_rate_limiter)
                              │
                              ▼
                     load_published_workflow → run_workflow → WorkflowExecutor
```

- `webhook_ingress` 零存储 import（deps 注入），装配在 `neurflow_api._webhook_ingress_deps`
- Cron 派发统一走 P1 Step 1 的 `WorkflowTaskExecutor.dispatch_neurflow`（双引擎已统一）
- secret 加密复用 `neurova/llm/providers/secret_store.py`（AES-256-GCM，master key 走环境变量）
