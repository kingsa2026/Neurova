## 一、P0（任意文件写入 / 匿名消耗凭据 / 越权 / 跨会话 DoS）

### SEC-P0-1 生成产物落盘任意路径写入（X-Request-ID 路径穿越）✅主线复核
- 文件：`neurova/api/middleware.py:31`、`neurova/api/endpoints/generation.py:98,176,186,280`
- 根因：`RequestIDMiddleware` 从**客户端可控的 `X-Request-ID` 请求头**取值写入 `request.state.request_id`；`generation.py:280` 把 `_get_request_id(request)` 当 `task_id`，`_persist_media` 直接 `out_dir / f"{task_id}_{index}.{ext}"` 后 `write_bytes`，全程无 sanitize、无围栏。
- 触发：`POST /api/v1/generation/image`，头 `X-Request-ID: ../../../../tmp/pwn`（Windows 可用 `..\..\..\Users\Public\pwn`），图像生成成功返回任一产物即写盘。
- 后果：任意路径文件写入/覆盖，可覆盖配置与脚本，DoS 起步。
- 修法：`task_id` 一律 `uuid4().hex`，绝不复用 request_id；或对最终文件名 `re.sub(r"[^A-Za-z0-9_.-]", "_", task_id)` 并 `resolve().relative_to(out_dir)` 围栏（同 workspace_files 语义）。

### SEC-P0-2 generation 全部端点零鉴权 + 复用服务端 provider 凭据 ✅主线复核
- 文件：`neurova/api/endpoints/generation.py` 全文（`grep -c "Depends\|current_user\|require_admin"` = 0）
- 根因：`/text`、`/image`、`/audio`、`/video`、`/video/status`、`/tasks` 均无鉴权依赖；`_resolve_generation_creds`（:113-162）在 `provider_id` 缺省时按协议启发从 `provider_manager` 取出**已配置启用的服务商 key** 调用上游。全局鉴权中间件默认 `off`，无兜底。
- 触发：匿名 `POST /api/v1/generation/image`（仅带 prompt）。
- 后果：匿名盗刷服务端付费凭据（token/额度）；`/tasks` 泄露全部生成任务 prompt 与产物路径；放大 SEC-P0-1。
- 修法：generation router 统一挂 `Depends(get_current_user)`。

### SEC-P0-3 /console/chat/stop 与 /console/tasks 零鉴权 → 跨会话取消 DoS ✅主线复核
- 文件：`neurova/api/endpoints/console.py:764`（`post_console_chat_stop(session_id)` 无 current_user）、`:1771`（`list_console_running_tasks(request)` 无 current_user）
- 根因：两端点未声明鉴权依赖，与同文件 `/chat`（:456 有 `Depends(get_current_user)`）口径不一致；`request_session_stop` 按 session_id 取消该会话全部运行任务，无归属校验。
- 触发：匿名 `POST /api/v1/console/chat/stop?session_id=<他人会话>`。
- 后果：任意人可中断他人正在进行的对话；`/tasks` 匿名泄露全部运行中会话 id/kind/时长。
- 修法：补 `Depends(get_current_user)`，stop 前用 `repo.find_session` + 归属校验。

### SEC-P0-4 workspace API 跨 Agent 越权（IDOR）✅主线复核
- 文件：`neurova/api/endpoints/workspace_files.py:34-39,74-195`
- 根因：`_workspace_root(agent_id)` 只校验 agent_id 字符集（`^[a-zA-Z0-9_-]{1,64}$`），**不校验请求用户与 agent 的归属**；所有 handler 仅 `_ = current_user` 占位，从不使用身份。
- 触发：任意已认证用户 `GET /api/v1/workspace/{other_agent}/files` / `.../zip`。
- 后果：横向读取/打包下载任意 agent 工作区文件（记忆、产物）；`copy`/`move` 可跨工作区写入；`subdir=".git"` 可列/打包 `.git` 内容（token/凭据风险）。
- 修法：`_workspace_root` 注入 `user_id`，比对 `agent_config.json` 的 owner 后再放行；隐藏目录整棵子树拒绝而非仅过滤当前层。

### SEC-P0-5 约 40 个端点模块零鉴权引用（系统性裸奔）✅主线复核
- 文件：`neurova/api/endpoints/` 下零鉴权依赖模块清点：
  `acp_api / agent_communication_api / agent_enhancement / benchmark / builder / channel / channel_config / channel_sharing / experience_knowledge_api / file_flows_api / firewall / generation / growth / home / image / knowledge_integration / logs / media / memory_enhancement / memory_share_groups / memory_timeline_api / model_adapter / neuron / openplatform_keys / plugin / projects_api / rules_api / runtime / skill / skill_market / skill_version_api / skills_market / synonym_api / tasks_api / teams_api / tool_schema / user_group_api / webhooks`
- 根因：`app.py` 无全局 `dependencies`，端点是否鉴权全靠手写 `Depends`；新端点默认裸奔。`NEUROVA_GLOBAL_AUTH` 默认 `off`（`global_auth.py:64-67`），无兜底。
- 触发：任意匿名请求。
- 后果：其中含写操作（技能安装/卸载、插件、项目增删、技能市场、Webhook、用户组），属大面积未授权访问面。
- 修法：短期为上述 router 逐个补 `Depends(get_current_user)`；长期把全局鉴权切 `shadow` 取证后切 `enforce`。

## 二、P1（数据越权 / 静默丢失 / 功能失效）

### DATA-P1-1 add_message 新建会话不写 user_id → 会话跨用户可见 ✅主线复核
- 文件：`neurova/session_manager.py:410-420`（新建分支）、`~849`（过滤）
- 根因：`add_message` 在 `session_data is None` 时构造的 dict 只有 `agent_id/session_id/session_date/messages/created_at/updated_at/total_messages`，**缺 `user_id` 与 `title`**；而 `save_message`（:726+）与 `create_session`（:550+）都显式写这两字段（契约错位）。`_collect_summaries` 过滤为 `if user_id and s_user_id and s_user_id != user_id: continue` —— 空 `s_user_id` 不参与过滤。
- 触发：任何未先走 `create_session` 的会话（自动建会话）首次写入。
- 后果：该会话对**所有** user_id 的 `list_sessions` 可见（越权展示）；`find_session`/`get_session` 无属主校验。
- 修法：`add_message` 新建分支补 `user_id`/`title`，由调用方传入生效作用域身份；过滤侧把空属主改为拒绝。

### DATA-P1-2 知识库全量 JSON 落盘非原子，崩溃即整库不可见
- 文件：`neurova/knowledge/repository.py:281-288`（`_save` 直接 `write_text`）、`219-230`（`_load` 吞异常置空）
- 根因：`write_text(json.dumps(...))` 直接截断写；崩溃留半截 JSON → `_load` 异常后 `self._items` 保持 `{}`，下一次 `_save` 用空 dict 覆盖 → 数据永久丢失。同根因命中：`knowledge/storage.py:86-102`、`knowledge_graph/manager.py:_save`。
- 修法：统一 tmp + `os.replace` 原子写（项目内 `session_manager.py:302-312`、`muscle_memory.py:592-595` 已有正确范式）。

### DATA-P1-3 L0→L1 flush 无条件截断 WAL，与并发 store 竞态丢记忆
- 文件：`neurova/cognitive_layers/memory_layer/cognitive_storage_engine.py:322-338,340-394`
- 根因：`_flush_l0_to_l1` 快照 `nodes` 后写 L1，再取 `_wal_lock` **无条件清空 WAL**；快照与截断之间并发 `store()` 追加的节点不在快照里也未写 L1，随后 WAL 被截断 → 崩溃即永久丢失。
- 修法：截断前按「已写 L1 的 id 集合」重写 WAL，或把 `_wal_append` 与 flush 快照/截断放进同一 `_wal_lock` 临界区。

### DATA-P1-4 is_model_available 只判存在不判非空 → 0 字节模型永久通过（SUB-P1-8 同根因新命中）
- 文件：`neurova/tts/model_downloader.py:120-130`
- 根因：仅 `all((model_dir/f).exists())`；修复只覆盖 hf-mirror 引擎，`_download_via_modelscope`/`_download_via_huggingface` 仍直写无 `.part`/校验。中断留下的 0 字节/截断文件 `exists()` 为真。
- 后果：`ensure_model` 直接 return，重下永不触发，模型永久损坏且自愈失效。
- 修法：`is_model_available` 改为逐文件 `size > 0`；modelscope/HF 引擎下载到临时目录后 `os.replace`。

### DATA-P1-5 MoE 索引完成状态只按 persist 库路径哈希 → 跨 Agent 误判已索引
- 文件：`neurova/mem_core.py:307-310,284-289,313-322,814-829`
- 根因：`scope_key = str(memory_manager._persist_db_path)`，而 persist 库路径固定为 `dirname(db_path)/neurova_memories_persist.db` —— 同 cwd 多 Agent 共用同一路径。状态文件名只哈希该路径，不含 `agent_id`。
- 后果：Agent B 启动读到 A 写的状态文件 → 判定「已完成，跳过重扫」→ B 的 MoE 索引永远只有初始 500 条，后台全量索引不启动，语义召回长期残废且无日志异常。
- 修法：`_moe_scope_key` 拼入 `agent_id`。

### SEC-P1-6 ref_images 本地路径 → 本地文件外泄
- 文件：`neurova/api/endpoints/generation.py:70,94,272,391`
- 根因：`ref_images` 字段描述显式「URL 或本地路径」，直接传给 protocols，无 `check_outbound_url` 也无本地路径围栏；`base_url` 同样用户可控。
- 触发：`POST /generation/image`，`ref_images=["C:\\...\\data\\usage_history.db"]` + 自建回连端点。
- 后果：任意本地文件被读取并上传到攻击者端点（配合 SEC-P0-2 零鉴权可匿名利用）。
- 修法：`ref_images` 只接受 http(s) 且过 `check_outbound_url`；本地路径白名单到生成输出目录，否则 400。

### SEC-P1-7 _persist_media 无出网校验（SSRF）
- 文件：`neurova/api/endpoints/generation.py:179-187`
- 根因：对 provider 返回的 URL 直接 `session.get`，未走 `check_outbound_url`。
- 触发：用户自建 `base_url` 或上游被投毒，返回 `http://169.254.169.254/...` / 内网地址。
- 后果：服务端代为请求内网/元数据端点，响应写入 `data/generations` 并可下载。
- 修法：下载前 `check_outbound_url(url)`，禁跟随重定向到私网。

### API-P1-8 新增静态目录用相对路径，与既有绝对路径基准冲突
- 文件：`neurova/api/endpoints/workspace_files.py:37`（`Path("agent_workspaces") / agent_id`）、`neurova/api/app.py:1105-1119`（`StaticFiles(directory="data/generations")`）
- 根因：两处均以进程 CWD 为基准；而 app.py 加载 agent 用绝对路径（`app.py:379-380`），generation 落盘也是相对。
- 后果：CWD ≠ 仓库根时（打包/服务化/异地 `python start.py`），workspace API `mkdir` 出新的空目录、列表恒空、写操作落错位置；`StaticFiles(check_dir=True)` 抛错被 `except` 吞掉，`_local_url` 返回的 URL 恒 404。
- 修法：统一以 `PROJECT_ROOT` 绝对路径为基准。

### API-P1-9 /video/status/{task_id} 无归属校验
- 文件：`neurova/api/endpoints/generation.py:425-485`
- 根因：账本按 task_id 全局可查，端点无鉴权无 owner 比对。
- 后果：拿到/枚举 task_id 后匿名轮询他人生成结果 URL。
- 修法：`TaskRecord` 增 owner，查询比对。

### FE-P1-10 消息搜索高亮比较语义错位（相对/绝对下标混用新命中）
- 文件：`NeurUI/src/pages/ChatPage.vue:85`（模板）vs `:1933`（`msgSearchCursor` 定义）vs `:1948-1949`（`jumpToMatch`）
- 根因：`msgSearchCursor` 存的是「命中在 hits 数组中的序号」，模板却写 `absIdx(idx) === msgSearchCursor`，把序号当绝对下标比较。
- 后果：命中消息绝对下标 ≠ 命中序号时高亮落在错误消息或全不命中。DATA-P0-5 同根因新命中。
- 修法：光标改存绝对下标（`msgSearchCursor = hits[cursor]`），模板比较改为 `absIdx(idx) === msgSearchCursor`。

### FE-P1-11 切换 Agent 不中止在途流 → 新 Agent 被旧流 isStreaming 卡死
- 文件：`NeurUI/src/pages/ChatPage.vue:2238-2248`（`watch(agentId)`）vs `:1024-1029`（`switchSession` 有 abort）
- 根因：`switchSession` 已修「切走先 abort + setStreaming(false)」，但 `watch(agentId)` 只 `clearMessages/setCurrentSession/loadSessions`，未 abort、未复位 isStreaming、未保存草稿。
- 后果：旧 SSE 写进孤儿 assistant proxy；`isStreaming` 保持 true 直到旧流 finally，新 Agent 发送按钮禁用数十秒；旧会话草稿丢失。
- 修法：`watch(agentId)` 内先 abort + setStreaming(false) + stopStreamTTS，并保存旧草稿。

### FE-P1-12 新会话首轮流式中排队消息永不自动续发（drain 守卫恒假）
- 文件：`NeurUI/src/pages/ChatPage.vue:1171,1340,1539-1546`
- 根因：新会话首轮 `currentSessionId` 为 null → `activeStreamSessionId = null`；后端 `done` 才回传 session_id 并写 store，finally 比较变成 `"新id" === null` 恒 false，drain 被跳过。
- 后果：新对话里流式期间入队的消息不续发，需手动点「立即」。
- 修法：`done` 拿到 session_id 时同步 `activeStreamSessionId`。

### FE-P1-13 useSessionSendLock 声明卸载释放但从未接线 → 跨标签发送锁泄漏
- 文件：`NeurUI/src/composables/useSessionSendLock.ts:13`（导入 `onUnmounted` 未用）、`:52-58,84`
- 根因：模块注释要求「组件卸载自动释放」，实现只 import 未调用；单例 `sharedIsOwner/sharedReleaseLock` 模块级，组件销毁后锁仍被本标签持有。
- 后果：同浏览器其他标签永久抢不到该 session 锁，发送按钮恒禁用，直到刷新。
- 修法：composable 内 `onUnmounted(sharedRelease)` 或引用计数释放。

### FE-P1-14 ~~zh-CN 缺 canvas 凭证键~~（**误报更正**，修复轮实证推翻）
- 原判：zh-CN 缺 91 个 canvas cred/label 键（grep 计数 en-US=32 / zh-CN=0）。
- **更正**：zh-CN 的 canvas 块使用 `...STORE_CANVAS` spread（`i18n/locales/_canvasStores.ts`，本身即中文值），运行时键值齐全且为中文；en-US 在 spread 后有显式英文覆写，其余 9 外语各有完整本地化覆写（de-DE='Shop-Verwaltung'、ja-JP='店舗管理' 实证）。**11 语言 i18n 实际健康，无需修复。**静态 grep 不理解 spread 是误报根因。

## 三、P2（可观测性 / 内存 / 边界）

- **P2-1** `_PersistDbStore.execute`（`mem_core.py:124-151`）静默吞异常返回空行集 → MoE 下钻 SQL 出错表现与「无记忆」不可区分。修：`except` 内 `logger.warning(exc_info=True)`。
- **P2-2** `MemoryReadWriteManager`（`memory_rw_manager.py:107+`）整体调用不存在的 `MemoryManager` 方法名（`search/get_all/create/...` vs 实际 `recall/get_all_memories/remember/...`）→ 接线即 AttributeError。修：按真实方法名重写或删除孤儿模块。
- **P2-3** 全局 `SemanticSearch` 单例关键词倒排被多作用域共享（`memory_layer/manager.py:1084-1093`）→ 召回质量随跨作用域写入劣化。修：索引按作用域分片。
- **P2-4** 调度器 `input_override` 永久污染任务定义（`scheduler.py:905-906`）+ `_task_lock` 非重入锁内发事件（`:633-659`）→ 自死锁风险。修：override 合并到副本；锁改 RLock 或事件移锁外。
- **P2-5** `pending_memories` 升级路径唯一索引谓词含 rejected，存量多条 rejected 同分区 → `CREATE UNIQUE INDEX` 失败建库失败（`memory/pending_memory.py:129-132`）。
- **P2-6** usage `last_call` 进程级共享（`core/usage_accounting.py:101-116`）→ 并发会话用量串号。修：按 session 分桶。
- **P2-7** `api/index.ts:144-154` 401 刷新失败后并发重复硬跳转且丢 SPA 状态。修：跳转单飞 + `router.replace`。
