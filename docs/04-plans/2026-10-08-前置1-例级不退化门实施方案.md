# 前置条件 1（留出侧例级读数 + 例级不退化门）实施方案

> **执行须知**：按 `neurova-repair-batch-pipeline` 八段走，每 Task 独立红→绿→自证→提交。
> 纪律权威源是 `AGENTS.md`；本票面只给命令级与代码级细节。

**Goal:** 让技能文本进化的接受判据从"留出集均值涨没涨"升级到"有没有既有用例被改坏"，
并让这条门在**留出侧真的有例级读数**（今天没有）。

**Architecture:** `_evaluate` 的明细多带一个 `failed` 标记（判分失败的单例不得被读成退化）；
留出集两次评测由 `_evaluate_avg` 改走**同一条** `_evaluate` 路径（零额外评测成本，均值语义不变）；
在判定链 `no_improvement` 之后新增一道**例级不退化门**（拒绝理由 `case_regression`），
容忍度是 `EvolutionConfig` 上的一个数，与 `min_improvement` / `bench_tolerance` 同族同处；
门本轮拦没拦、退化了哪几条、几条没量出来，随 `EvolutionRunResult` 进提案读数面。

**Tech Stack:** Python 3.12 / pytest / 既有 `EvolutionConfig` + `EvolutionRunResult` 契约。

**Spec:** `docs/08-research/designer_rsi_paper_vs_neurova_rsi_comparison_2026-10-08.md`

拍板原文是"N 入 `EvolutionSettings` 单源"。实探结论：把 N 放进 `EvolutionSettings` 会造出

import asyncio

from neurova.evolution.eval.config import EvolutionConfig
from neurova.evolution.eval.dataset import EvalDataset, EvalExample
from neurova.evolution.eval.runner import SkillEvolutionRunner


class _ScriptedJudge:
    """按 (task_input → 分数) 脚本化判分；未列出的 task 视为已量出且零分。"""

    def __init__(self, scores):
        self._scores = scores
        self.calls = 0

    async def score(self, **kwargs):
        self.calls += 1
        score = self._scores.get(kwargs["task_input"], 0.0)
        return {"composite": score, "feedback": f"fb:{kwargs['task_input']}"}


class _Executor:
    def __init__(self, failOn: str = ""):
        self._failOn = failOn

    async def run(self, *, skill_text: str, task_input: str) -> str:
        if self._failOn and task_input == self._failOn:
            raise RuntimeError("boom")
        return f"out::{skill_text}"


def _dataset(tasks):
    examples = [
        EvalExample(task_input=t, expected_behavior=f"rubric-{t}") for t in tasks
    ]
    return EvalDataset(train=examples, val=[], holdout=list(examples), heldout=[])


def testEvaluateDetailsCarryFailedFlag():
    """判分/执行崩掉的单例必须带着 failed=True 出来，不得与真零分同形。"""
    runner = SkillEvolutionRunner(
        EvolutionConfig(), judge=_ScriptedJudge({"a": 0.9, "b": 0.9}),
        agent=_Executor(failOn="b"), mutate=lambda **kw: asyncio.sleep(0, "x"),
    )
    examples = _dataset(["a", "b"]).holdout
    _avg, details = asyncio.run(runner._evaluate("skill", examples, "skill"))
    flags = {ex.task_input: failed for ex, _s, _o, _f, failed in details}
    assert flags == {"a": False, "b": True}, flags

```python
    async def _evaluate(
        self, skill_text: str, examples: list[EvalExample], artifact_type: str
    ) -> tuple[float, list[tuple[EvalExample, float, str, str, bool]]]:
        """返回 (均分, 明细)。明细第 5 位 `failed` = 该单例执行或判分是否异常。

        带着它而不是只带 0.0：均分里 0.0 与"真考砸"同值，可一旦拿它去做
        **例级**判据（谁退化了），"没量出来"就会被读成"退化了"——
        三态契约在集合层面折叠过一次，本票不许它在单例层面再折一次。
        """
        if not examples:
            return 0.0, []
        details: list[tuple[EvalExample, float, str, str, bool]] = []
        eval_errors = 0
        for ex in examples:
            score, output, feedback, failed = await self._score_example(
                skill_text, ex, artifact_type)
            eval_errors += int(failed)
            details.append((ex, score, output, feedback, failed))
        self._run_eval_errors += eval_errors
        avg = sum(s for _ex, s, _o, _f, _failed in details) / len(details)
        return avg, details
```

```python
def _caseRegressionReadout(caseScores: dict) -> tuple[list[str], list[str]]:
    """留出例级读数 → (退化用例, 未量出用例)。

    退化 = 两侧都量到了，且候选分严格低于基线分（差值过 _EPS）。
    未量出 = 任一侧判分失败——这种条目**两个方向都不记账**：
    把它算成退化是拿器械故障当质量结论，算成没退化是把没测到当通过。
    """
    regressions: list[str] = []
    unevidenced: list[str] = []
    for task, readout in (caseScores or {}).items():
        if readout["baseline_failed"] or readout["candidate_failed"]:
            unevidenced.append(task)
            continue
        if readout["candidate"] < readout["baseline"] - _EPS:
            regressions.append(task)
    return regressions, unevidenced
```

## 风险与不做清单

- **吞吐会掉**：门默认开，历史上"均值涨但撞坏用例"的候选转为拒绝。这是判据强度换吞吐，
  正文里要给出本轮实测的拒绝率（跑一轮真实脚本化评测取数，不预估）。
  **实测拒绝形态（2026-10-09，脚本化 4×5 网格，取数即删探针）**：10 个留出用例，
  候选侧让前 `broken` 条从 0.5 掉到 0.1、其余涨到 0.9，`allowance ∈ {0,1,2,3} × broken ∈ {0..4}`
  共 20 格（`anchor_floor_enabled=False` 以隔离本门，其余走生产判定链）。结果：
  - **每一条被本门拦下的候选，留出均值都在涨**：0.5 → 0.82 / 0.74 / 0.66 / 0.58；
    即这些全是旧均值判据会**放行**的形态——门换掉的正是这一类吞吐；
  - 拦阻计数随容忍度线性收口：`allowance=0` 拦 4/5、`=1` 拦 3/5、`=2` 拦 2/5、`=3` 拦 1/5，
    合计 20 格里 10 格被拒；`broken ≤ allowance` 一律放行且 `caseRegressions` 仍如实外露；
  - 边界严格咬在 `broken > allowance`，没有 off-by-one。
  这组数是**门的咬合剖面**，不是生产流量的拒绝率——真实拒绝率取决于线上候选撞坏用例的频率，
  而那要等前置 2 把执行面接成真轨迹才有意义（模拟执行器下"撞坏用例"本身是构造出来的）。
- **不做**：把 `unpredicted_regressions`（tune 集归因）接成第二道门——它与本门作用域不同
  （tune vs holdout），接进来会让同一件事有两道判据、两套口径；本门只认留出侧。
- **不做**：成对判分顺序随机（论文为消位置偏置做的那一手）。本仓 judge 是
  `(task, output, rubric)` 单侧打分，没有 pairwise 通道；要随机化得先建 pairwise judge，
  属另一票面（§4 P1-B 的对照改造一起做更省）。
- **不做**：把容忍度做成按留出集大小自适应的比例。n 小时比例与计数近等价，
  而比例语义会让人误以为"留出集越大可以随便撞坏几条"——计数是把阈值摆在明面上。
