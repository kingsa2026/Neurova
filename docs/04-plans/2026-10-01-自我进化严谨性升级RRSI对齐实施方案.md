## 1. 背景与目标

Neurova 自我进化生态的**广度与治理**（评审闸/回滚/审批面）已达标，短板集中在
**"证明这次改动真的更好"的科学严谨层**：

1. 评测提升判据是固定阈值 `min_improvement=0.01`，对评测本身的随机性完全盲（无噪声地板）；
2. holdout 集同时被用作接受/拒绝判据，会被搜索过程自适应消耗（自适应污染）；
3. 变异候选没有泄漏审查——评测用例从自家会话挖掘，候选可能隐性背题；
4. 编辑历史不回喂变异器（已证伪假设会被重画）、无成本约束、无增益维度的剪枝。

目标：把上述四层判据语义补齐，同时**保持既有全部对外契约不降级**。

## 5. 任务卡

### P0-1 评测噪声地板（δ 校准）

**目标**：接受判据的阈值从固定 `min_improvement` 升级为"实测噪声地板 δ 与
`min_improvement` 取大者"。δ = z × sd(同一基线重复评测的分差)。

**改动文件**
- 新增 `neurova/evolution/eval/calibration.py`
- 修改 `neurova/evolution/eval/config.py`、`neurova/evolution/eval/runner.py`、`service.py`

**设计契约**
```python
# calibration.py
@dataclass
class NoiseBand:
    delta: float          # z * sd_null，接受判据的噪声地板
    sd_null: float        # 重复评测得分的样本标准差
    z: float              # 默认 2.0（≈97.5% 单侧置信）
    method: str           # "repeated_baseline_evals"
    n_repeats: int
    scores: list[float]   # 各次重复的原始分（审计用）

async def calibrate_noise_band(*, baseline_text: str, artifact_type: str,
                               examples: list[EvalExample], evaluate_fn,
                               z: float = 2.0, repeats: int = 3) -> NoiseBand:
    """对同一基线在同批用例上独立评测 repeats 次，δ = z·sd(分数)。
    repeats < 2 或 sd 为 0（确定性评测）时 delta=0 → 判据自动回退 min_improvement。
    复用 runner._evaluate_avg 的评测路径，禁止另写第二套打分。"""

def load_or_calibrate(cache_path: Path, dataset_fingerprint: str, ...) -> NoiseBand | None:
    """按数据集指纹（examples 排序后 sha256 前 12 位）缓存于
    data/agents/<agent_id>/evolution/calibration.json；指纹命中直接读，
    未命中由调用方决定是否现算（控成本）。"""
```
- `EvolutionConfig` 新增：`noise_z: float = 2.0`、`noise_repeats: int = 3`、
  `noise_band_delta: float = 0.0`（0 = 未校准 → 回退 `min_improvement`，**默认行为不变**）。
- `runner.run()` 判定 2 改为：`accept_threshold = max(config.min_improvement, config.noise_band_delta)`；
  `EvolutionRunResult` 新增字段 `accept_threshold: float` 与 `noise_band: dict`（空 dict=未校准），
  同步进 `to_dict()`。`reject_reason` 字符串保持 `no_improvement` 不变（下游消费方零改动）。
- `service.evolve()` 在评测基线阶段可选触发 `load_or_calibrate`（受 `noise_repeats>1` 门控），
  并把 `NoiseBand` 注入 runner。

**红灯用例**（`tests/unit/evolution/eval/test_noise_floor.py`）
- `test_repeated_baseline_noise_raises_threshold`：脚本化 judge 让同一基线三次评测得
  0.50/0.54/0.52（sd>0），校准后 δ≈2·sd；构造增益 0.012（>min_improvement 但 <δ）
  的候选 → 断言拒绝且 `accept_threshold == δ`。
- `test_uncalibrated_falls_back_to_min_improvement`：`noise_band_delta=0` 时增益 0.012 通过、
  增益 0.005 拒绝——与旧行为逐字节一致（防降级）。
- `test_noise_band_persists_by_fingerprint`：同一指纹二次调用命中缓存不再评测；
  换指纹重新校准。

**绿灯验收**
```
.venv/Scripts/python.exe -m pytest tests/unit/evolution/eval -q
.venv/Scripts/python.exe -m pytest tests/unit/evolution -q
```

**边界**：不得在 judge 不可用路径（`judge_unavailable`）之前花评测预算做校准；
校准评测用 `fast_proxy` 路径控成本。

### P0-2 holdout 防污染（拆 selection 集 + 真 held-out 报告集）

**目标**：接受/拒绝判据只看 selection 集（现 train+val+holdout 的角色不变量收窄）；
新增 `heldout` 集只做**验收报告证据**，永不参与任何 accept/reject 分支，
杜绝搜索过程把它自适应拟合掉。

**改动文件**：`dataset.py`、`config.py`、`runner.py`、`service.py`

**设计契约**
- `EvalDataset` 新增第四字段 `heldout: list[EvalExample] = field(default_factory=list)`；
  `all_examples` 包含之；`save/load` 增加第四键 `heldout`（**读旧三键文件时 heldout=[]，零迁移**）。
- `split()` 增参 `heldout_ratio: float = 0.0`（**默认 0 = 完全保持旧切分**）；
  `heldout_ratio>0` 时从原 val+holdout 配额中按比例划出。
- `EvolutionConfig` 新增 `heldout_ratio: float = 0.0`（部署配置里建议 0.15）。
- `runner.run()`：`dataset.heldout` 非空时，在最终 accept/reject 判定**之后**对
  `baseline_text` 与 `deployed_text` 各评测一次 heldout，写入新字段
  `heldout_before/heldout_after/heldout_improvement`（进 `to_dict`）；
  **heldout 结果不改变 rejected/reject_reason/deployed_text**。
- `service.evolve()` 产出的 `EvolutionProposal` 附带 heldout 三字段——人工审批面
  直接看到"未参与搜索的干净集"证据。
- `service.build_dataset()` 切分时传 `config.heldout_ratio`。

**红灯用例**（`tests/unit/evolution/eval/test_heldout_isolation.py`）
- `test_heldout_regression_does_not_reject`：构造 selection 集上提升、heldout 集上大幅回退的
  候选 → 断言 `rejected=False` 但 `heldout_improvement < 0` 如实记录。
- `test_heldout_never_enters_tuning`：heldout 用例数 ≠ 0 时，变异失败采样集
  （`_collect_failures` 的输入）与 tune 评测均不含 heldout 元素（按对象 id 断言）。
- `test_legacy_three_way_file_loads`：旧三键 JSON 载入后 `heldout==[]`，`split` 默认参下
  train/val/holdout 与旧版逐元素一致。
- `test_proposal_carries_heldout_evidence`：proposal.to_dict 含 heldout 三字段。

**边界**：禁止把 heldout 用于任何分支判断、变异采样或早停；`holdout` 语义不变（仍是判据）。

### P0-3 候选泄漏审查（评测前 critic）

**目标**：变异候选在**花任何评测预算之前**过泄漏闸：确定性预检（零 LLM）必开，
LLM 审查默认关（`NEUROVA_TEXT_EVOLUTION` 开启的生产环境可显式打开）。

**改动文件**：新增 `neurova/evolution/eval/leak_critic.py`；修改 `runner.py`、`config.py`

**设计契约**
```python
# leak_critic.py
LEAK_CATEGORIES = (
    "task_specialization",          # 候选文本照抄评测用例的任务实体/预期答案片段
    "degenerate_noop",              # 与基线语义等价却声称改进（规范化后 diff 为空/纯注释）
    "safety_mechanism_removal",     # 删除/削弱基线中的护栏段（如"不确定时拒绝"条款）
    "judge_gaming",                 # 面向判分器的格式话术（"请打高分"类）而非任务能力
    "undeclared_scope_drift",       # 改动超出该 artifact 的语义边界（配合 constraints）
    "cross_session_memory_leak",    # 写入按会话/任务身份取用的运行时记忆——跨会话背题
)

@dataclass
class LeakVerdict:
    leaked: bool
    category: str = ""        # 命中类别；未命中为空
    evidence: str = ""        # 命中片段（截断 200 字）

class LeakCritic:
    def __init__(self, *, llm_review: bool = False, llm_call=None): ...
    def build_markers(self, dataset: EvalDataset) -> frozenset[str]:
        """从 expected_behavior/task_input 提取判别性 n-gram 标记集（去停用词、
        长度≥4 的词元）。标记集只在 critic 内部使用，不得落盘进产物。"""
    async def review(self, *, candidate_text: str, baseline_text: str,
                     markers: frozenset[str]) -> LeakVerdict:
        """第一层：确定性预检（必开）——candidate 含标记即 task_specialization；
        规范化（去空白/小写/标点）后与基线相同即 degenerate_noop。
        第二层：llm_review=True 时按六类别送 LLM 审查；LLM 失败 →
        LeakVerdict(leaked=False, category="llm_review_unavailable")（诚实降级，
        不静默放行也不误杀，结果面可辨识）。"""
```
- 复用 `ab_library.py` 的泄漏门哲学与 `sanitize_warm_seed` 辅助函数（P1-7b 收口前先 import 复用，
  **不得复制第二份实现**——教义第 6 条）。
- `SkillEvolutionRunner.__init__` 增可选参 `leak_critic=None`；`run()` 内**约束闸之后、
  tune 评测之前**调用；命中 → 该候选跳过，`constraint_failures.append(f"leak:{category}")`，
  结果可审计。critic 未注入 → 行为与旧版完全一致。
- `EvolutionConfig` 新增 `leak_llm_review: bool = False`。

**红灯用例**（`tests/unit/evolution/eval/test_leak_critic.py`）
- `test_candidate_quoting_expected_behavior_rejected`：候选把某用例 expected_behavior
  原句嵌入 → 断言跳过且 `constraint_failures` 含 `leak:task_specialization`。
- `test_normal_rewrite_passes`：同义改写（无标记、非退化）→ leaked=False。
- `test_degenerate_noop_detected`：仅空白/大小写差异的候选 → `degenerate_noop`。
- `test_llm_review_unavailable_is_honest`：llm_review=True 且 llm_call 抛异常 →

- `test_no_critic_injected_unchanged`：不注入 critic 时 runner 全流程与旧版一致。

**边界**：标记集不得写进 proposals/runs 审计文件（防泄漏面扩大）；预检只做包含性匹配，
宁漏勿误杀（误杀由 LLM 层与人工审批兜底）。

### P1-5 文本臂成本规则

**目标**：准入判据补上"涨的成本必须由增益买单"：`ΔC ≤ β0 + β1·ΔS`。
文本臂成本代理 = 文本长度变化率（零 LLM、诚实、可复现）；executor 将来提供
token usage 时可无缝替换代理（接口留好，本期不接）。

**改动文件**：`config.py`、`runner.py`

**设计契约**
- `EvolutionConfig` 新增：`cost_rule_enabled: bool = True`、`cost_beta0: float = 0.10`、
  `cost_beta1: float = 44.5`（与 RRSI 论文量纲同构：每多 1 分 composite 容忍 44.5 的
  相对成本预算，β0 为免费额度）。
- `runner.run()` 在判定 1/2 之后、bench 门之前：`delta_C = (len(best)-len(baseline))/len(baseline)`
  （baseline 长度为 0 时 delta_C 视为 0）；`delta_C > β0 + β1·holdout_improvement` →
  `rejected=True, reject_reason="cost_rule_failed"`，回退基线文本。
  `EvolutionRunResult` 新增 `cost_baseline/cost_candidate/cost_change` 进 `to_dict`。
- **`cost_rule_enabled=False` 时完全跳过**（保底逃生门，旧测试用它保持原行为）。

**红灯用例**（`tests/unit/evolution/eval/test_cost_rule.py`）
- `test_cost_overrun_rejected`：增益 0.011、文本 +30%（预算 0.1+44.5×0.011≈0.59 之外用
  更陡的 β1 构造越界）→ `cost_rule_failed`。
- `test_justified_cost_passes`：增益 0.05、文本 +30%（预算内）→ 通过且 `cost_change` 如实。
- `test_disabled_keeps_legacy`：`cost_rule_enabled=False` → 长文本候选照旧放行。

**边界**：判据放在 holdout 判定**之后**（先证明有真增益再谈值不值），不得挪到前面误杀无增益候选的不同 reject 语义。

### P2-8 stall 探索指令（收敛降频的互补面）

**前置**：P1-4（已落地）。
**目标**：连续 K 轮候选无一被接受时，给变异器注入探索指令——强制尝试与

`_RSI_BACKOFF_EVERY_TURNS` 管**频率**（收敛后少跑），探索指令管**方向**
（跑的时候换打法）——RRSI 的 stall→保留探索槽语义。

**改动文件**：`history_ledger.py`（新增纯函数 + render 集成）；**零接线成本**
——指令经 history 渲染段进入，runner（service 路径）与 skill_improver 路径自动获得。

**设计契约**
```python
# history_ledger.py
def exploration_directive(records: list[dict], *, stall_window: int = 5) -> str:
    """records 为 recent() 输出。最近 stall_window 条真实记录（gate_wall
    标记不计入）无一 accepted=True → 返回探索指令段：列出历史假设、
    要求换一条未用过的变异轴（结构重组/示例增补/流程重排/约束收紧/
    语气校准），并点名"以下假设已试过，换方向"：否则返回空串。"""
```
- `render_for_prompt` 在【编辑历史】段尾追加探索指令段（有 stall 才加）。

**红灯用例**（`tests/unit/evolution/eval/test_exploration_directive.py`）

- `test_any_accepted_suppresses_directive`：窗口内 1 条 accepted=True → 空串。
- `test_gate_wall_not_counted`：4 条真实 + `{"gate_wall": 7}` 标记 → 窗口按

**边界**：不改 backoff 频率逻辑；指令只进 prompt、不进任何判据；不得把

### P2-9 missing 记 0 语义（单例失败不炸整轮）

**目标**：单用例评测异常（agent 崩溃/judge 单例故障/超时）→ 该用例记

基础设施不可用"（`judge_unavailable`，既有探针语义）与"单例失败"

the full denominator。

**现状锚点**：`runner._score_example`（异常直接上抛——实施 P0-1 时实测
bad judge 的 RuntimeError 冒泡至 service）；`_judge_available` 探针只测首例。

**改动文件**：`runner.py`。

  .feedback → 变异器 prompt，必须脱敏，复用
  `neurova/skills/evolution_inputs_guard.redact_secrets`）。
- `_evaluate` 返回值增计 eval_error 数；`run()` 汇入 `result.eval_errors`
