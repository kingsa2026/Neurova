# 四条自动化前置落成晋升判据（可红断言）实施方案

> **执行须知**：按 `neurova-repair-batch-pipeline` 八段走，每 Task 独立红→绿→自证→提交。
> 纪律权威源是 `AGENTS.md`；本票面只给命令级与代码级细节。

**Goal:** 把对照报告 §8 的四条「无人监督全自动」前置，从文档里的一句话变成
`RSIDeploymentController.evaluate_phase_transition` 里**会红的判据**：未满足即
`GateVerdict.failed` 并点名缺哪一条。

**Architecture:** 新增 `rsi/automation_prerequisites.py` 作四条前置状态的**唯一出口**，
每条给一个**无副作用的行为探针**（能在运行期证伪，不靠 grep 源码字符串）；
控制器在 `_current_phase >= 1` 时（即晋升目标为 2/3/4）取该格，未满足直接 `failed`。
控制器**不重算任何前置事实**，只搬运读数——与同文件既有的 `_experience_quality_guard`
「不重算、不另立阈值」同一纪律。

**Tech Stack:** Python 3.12 / pytest / 既有 `GateVerdict` 三态契约（`passed`/`failed`/`unevidenced`）。

**Spec:** 对照报告 `docs/08-research/designer_rsi_paper_vs_neurova_rsi_comparison_2026-10-08.md`
§8「前置条件要落成判据，不落成口头条件」+ §8 四条前置的现况（1、3、4 已满足，2 未满足）。

**用户拍板（2026-10-09）**
- **绑定范围：晋升目标 phase ∈ {2,3,4}**（即 `_current_phase >= 1` 起要求）。
  阶段语义现读自 `deployment_controller.py:40-46`：0 观察 / 1 只出建议人工审批 /
  2 低风险自动执行 / 3 中风险 / 4 完全自动。0→1 不授自动权，不该被挡；
  一旦要开始让系统自动改行为，判据输入必须做实。
- **未满足的语义：`GateVerdict.failed` 并点名缺哪一条**（不是 `unevidenced`，
  也不是"只外露读数"）。理由：前置项是**结构性事实**（有没有实装），不是本轮采样缺失；
  折叠成"无据"会让"压根没实装"与"这次没测到"同形——正是工单 003 点过的病。

## 四条前置各自的探针形态（关键设计点，逐条给可证伪判据）

| # | 前置 | 运行期探针（无副作用） | 现值 |
|---|---|---|---|
| 1 | 留出例级读数 + 例级门咬合 | 直接调 `eval.runner._caseRegressionReadout`：喂一条"两侧都量到且候选分更低"的读数，必须报退化；再看 `EvolutionConfig` 有 `case_regression_allowance` 字段 | 真 |
| 2 | 判据执行面 = 真 agent 轨迹 | 检查 `eval.runner` 的默认执行器：调其 `run(skill_text=..., task_input=...)`，**返回正文原样回显即未满足**；满足的判据是默认装配不再回显（前置 2 落地后自动翻真） | **假** |
| 3 | 呈现与采纳分离计数 | 调纯函数 `eval.skill_service.compute_skill_funnel_update([{...stage:"presented"}])`：必须 `presentations=1` 且 `selections=0` | 真 |
| 4 | 缺证据不给通过分 | `EvolutionRunResult.judge_available` 字段在 + `SkillEvolutionRunner._judge_available` 可取 + `EvolutionConfig.min_improvement > 0`（0/0 边界不再被当零增益放行） | 真 |

探针写在这一层是因为：**声明式旗标会说谎**。本批要求每条旗标都能被运行期证伪，
并由一格反向守卫钉住"旗标 = 探针结果"（有人把实装摘掉而旗标还写着真 → 当场红）。
