# 手机执行器预研与实施方案（安卓先行 · 2026-11-19）

> **性质**：预研 + 实施方案（待拍板排期）。背景对照材料：[reference_x vs Neurova 真机操控网关对照](../08-research/reference_x_vs_neurova_phone_gateway_comparison_2026-11-19.md)（docs/08-research，中性代号 reference_x）。
> **一句话**：把 Neurova 手机端从「用户的遥控器」升级为「agent 的手」——后端 agent 经既有移动 WS 通道，指挥手机端 App 通过系统无障碍能力代用户操作手机，全程人在环审批、凭据隔离、逐迹留痕。

---

## 1. 背景与动机

2026-11-19 对外部开源「AI 操作真机、人全程在环」网关项目（代号 reference_x）做了代码级对照（见 08-research 报告）。其结论：该项目的价值不在「接入 agent」（MCP 管道而已），而在它验证了一条**手机端执行器**的完整工程路径——

- 手机端伴生应用以系统无障碍能力读屏、注入手势；
- 凭据物理隔离（密码/验证码禁注入、验证码出屏打码、PIN 走系统钥匙串+本人生物识别）；
- 无障碍服务**按需开关**（任务期开、结束/接管/闲置 60s 关），规避金融类应用检测；
- 风险操作在网关扣住、弹卡片等人批、60s 超时即拒；
- 每步文字+截图+录屏留痕，可导出报告；任务按步数/时长/费用熔断。

对照本仓：**后端侧的治理、审批、账本、调度均已具备**（治理四级裁决、审批链 L0–L2、H-4 事件账本、APScheduler、token 保证金），**缺的只是「端上执行器」**。而本仓相对该网关有一项天然优势：**手机端与后端的实时通道已经建好**（安卓 WS 同源运行态、鸿蒙流式聊天），指令下发/结果回传的管道现成——该网关需要自研 adb/串流/socket，我们不需要。

## 2. 目标与非目标

**目标**
1. 安卓端最小闭环：agent 经后端指挥，在真机上完成一个真实任务，全程审批 + 留痕 + 熔断。
2. 安全底线四件套随最小闭环同步落地（见 §5），不是后续补丁。
3. 鸿蒙端产出可行性结论（能做什么/权限代价/建议形态），不盲目动代码。

**非目标（本轮不做）**
- 不自研「电脑控手机」驱动层（调试桥服务端、屏幕串流转发等）——我们的链路是 后端 agent → 手机端 App → 系统能力，比「电脑→调试桥→手机」更短，无需那套重资产。
- 不做 iOS 侧。
- 不做任何绕过应用反自动化机制的对抗；金融/密码管理类应用默认隐身。
- 鸿蒙端不做越权注入；权限不满足时退「读屏展示 + 引导人操作」形态。

## 3. 总体架构

```
Neurova 后端（agent 决策 · 治理四级裁决 · 审批链 L0–L2 · H-4 事件账本 · 熔断）
        │  既有移动 WS 通道（安卓同源运行态 / 鸿蒙流式聊天；新增「执行指令」消息族）
        ▼
手机端 App
   ├─ 安卓：AccessibilityService 执行器（读屏 / 手势注入 / 按需开关）
   ├─ 鸿蒙：AccessibilityExtensionAbility 预研（R 系列，见 §7）
   └─ 审批卡片 / 体检页 / 悬浮进度
        │  无障碍树读取 · 手势注入
        ▼
用户手机上的目标应用
```

职责切分：**后端只做决策与治理**（绝不直接触碰设备协议）；**手机端只做执行与上报**（不自行判断该不该做——风险判定单源在后端治理链）。

## 4. 安卓最小闭环拆卡（M 系列）

> 每卡独立可验；M1–M3 为安全地基，M4 起才允许接真实任务。

| 卡 | 内容 | 验收判据 |
| --- | --- | --- |
| **M1 执行器骨架** | AccessibilityService 声明与生命周期；**按需开关**（任务开始开启 / 结束·接管·闲置 60s 关闭）；读屏：节点树 → `{ref, role, label, bounds, state}` 投影 | 开关状态随任务生命周期正确翻转；读屏投影含坐标与文本 |
| **M2 指令协议** | 复用既有移动 WS：新增「执行指令」消息族（observe/tap/swipe/type… 每条带 `intent` 与序号）；手机端回执（屏幕投影/截图引用/错误码）；断线重连期间指令不重复执行（幂等序号） | 后端下发→端上执行→回执往返 ≤1s（USB/局域网）；断线重放不双击 |
| **M3 安全底线** | 密码框/验证码框**禁止注入**（字段类型识别，输错也进不去）；验证码文本出端前打码（多语言关键词 + 数字形态，排除电话/金额/日期）；敏感应用名单**隐身**（无元素、无截图、通知遮罩） | 密码/验证码在 屏幕投影、截图、事件账本、后端日志 四处均不可见 |
| **M4 审批链接通** | 风险操作（支付/发送/删除/安装/改设置）在执行前触发后端治理 ASK → 手机端审批卡片（含 intent、目标截图）+ 超时即拒；审批决定走既有 approval_manager 单源 | 一次支付类操作被扣住、超时自动拒、批准后仅该次放行 |
| **M5 事件账本** | 每步落 run 级 JSONL 事件（复用 H-4 通道）：intent、指令、状态、前后屏引用；不含敏感明文 | 任意一步可事后回放；账本中抽查无凭据明文 |
| **M6 任务熔断** | 步数 / 时长 / 费用三上限，先到先停；结束理由与余量入账 | 人为触顶后任务终止且手机端无残留操作 |
| **M7 体检与引导** | 端上能力自检页：无障碍开关、电池优化白名单、品牌差异步骤（国产 ROM 菜单名分品牌给） | 新装机按体检页指引一次走通 |
| **M8 演示模式** | 模拟屏幕源（虚拟 UI 场景），无真机跑通 M1–M6 全链，供自动化测试与对外演示 | 无真机环境完成全部回归 |
| **M9 端到端演示** | 一个真实任务全流程（建议：「打开设置，查看电池状态并回报」起步，再选一个跨应用任务），全程审批+留痕+熔断待命 | 真机演示成功；中途强杀/断线不产生不可恢复状态 |

**建议实施顺序**：M1→M2→M3→M8（无真机先跑通）→ M4→M5→M6→M7→M9。

## 5. 安全与合规红线（贯穿所有卡）

1. 凭据四可见面（投影/截图/账本/日志）零明文——作为 M3 的持久判据，任何一卡回归都复测。
2. 无障碍服务**绝不常开**；后台常驻唤醒策略仅限任务窗口。
3. 所有操作必须可归因到一次审批决定；无审批的高风险执行视为事故。
4. 屏幕数据最小化：截图按需索取、账本存引用不存原图、保留期沿用 S17 归档策略。
5. 用户随时接管：端上提供「停止/接管」入口，接管后 agent 侧一切调用立即挂起（对齐网关 `user_took_over` 语义）。

## 6. 与既有设施的关系（不新造平行体系）

- **审批**：复用 approval_manager / approval_chain L0–L2，手机端只是新增一种「审批呈现与作答渠道」。
- **留痕**：复用 H-4 run 级事件账本与 S17 归档，手机端是新的事件生产者。
- **熔断**：对齐 QwenPaw 借鉴批的 token 保证金/限流口径，手机侧增加步数/时长维。
- **指令通道**：复用移动 WS，不另起 socket/调试桥。

## 7. 鸿蒙端预研结论（R 系列，2026-11-19 已完成调研）

> 依据：OpenHarmony 官方开源文档仓（Gitee `openharmony/docs` master，`application-dev/reference/apis-accessibility-kit/`）。华为开发者官网文档中心为 JS 渲染单页应用，脚本直读仅得空壳；OpenHarmony 与商用 HarmonyOS NEXT 的 Accessibility Kit 同源，商用侧政策以官方站为准。

| 项 | 结论 |
| --- | --- |
| **R1 能力边界** | **API 12（HarmonyOS NEXT）起，无障碍扩展能力对三方应用收口**：公开版 `AccessibilityExtensionAbility` 全部生命周期回调与 `AccessibilityExtensionContext` 全部接口（读屏 `getWindowRootElement`/`getFocusElement`/`findElement`、动作执行 `performAction`（click/longClick/setText/scroll 等）、手势注入 `injectGesture(Sync)`）**自 API 12 起废弃，官方注明「系统不再开放相关能力」**。新接口自 **API 20** 起为 **systemapi**（`onAccessibilityEventInfo`/`onAccessibilityKeyEvent` 等），需系统应用 + `ohos.permission.ACCESSIBILITY_EXTENSION_ABILITY` 权限，非系统应用调用报错 202。三方应用（含本仓鸿蒙端）**无法再获得读屏/注入执行器能力**。 |
| **R2 运行时通道** | `uitest`/`hdc` 属测试/调试域（测试框架与开发者调试桥，需开发者模式/测试舱运行），不是面向用户设备的运行时自动化通道，不可作为产品能力依赖。 |
| **R3 退让形态** | 「读屏展示」同样依赖被收口的无障碍能力，**不可行**。鸿蒙端可行形态退化为：**审批终端 + 通知/卡片提醒 + 人工执行**（审批作答只需普通 UI 与生物确认，不依赖无障碍能力）。 |
| **R4 总结论** | **鸿蒙端执行器暂缓**。产品分工：安卓端承担「agent 代操作」，鸿蒙端承担「审批终端 + 任务提醒 + 状态展示」。 |
| **R5 小艺/意图框架通路** | **不能借系统 agent 绕过执行权限**。Intents Kit（意图框架）的调用方向是「应用按 Schema 开放业务意图 → 小艺（对话/搜索/建议三入口）理解用户话语后**调起应用**执行」，即小艺是调用方；官方文档无「应用向小艺下发任务/任意指令」的接口，小艺的系统级执行能力（通话/消息/设置等）也不对三方开放转发。附带约束：意图接入仅限企业开发者、仅中国大陆、HarmonyOS 5.0+、模拟器暂不支持。**可留的变体**：未来把「发起 Neurova 任务」注册为意图，用户可直接对小艺说「让 Neurova 帮我…」语音唤起本应用——只解决入口体验，不解决执行权限。 |

## 7.1 安卓侧对照佐证

Android 侧 `AccessibilityService` 对三方应用持续开放（仅需用户在系统设置中授权开启），读屏/节点查找/`performAction`/`dispatchGesture` 均可用——这正是参照项目在安卓真机上完整跑通的基础。两端能力不对称因此是**系统政策差异**，不是本仓工程差异；产品文案与市场材料应据实描述（安卓先行，鸿蒙端为审批与提醒终端）。

## 7.2 R5 证据注记

- 意图框架官方介绍：`developer.huawei.com/consumer/cn/doc/harmonyos-guides/intents-introduction`（官网为 JS 渲染单页，正文经其公开镜像核对）——系统入口为小艺对话/小艺搜索/小艺建议；意图由「动作 + 实体」构成，分「完成时/将来时」两种机制。
- 调用方向实证：官方示例「小艺出行」为用户对小艺说出行需求 → 小艺命中应用注册的意图（如 AddTrip）→ 拉起应用创建行程；即**小艺调应用**。
- 「吩咐小艺，5 分钟后自动关闭孩子正在使用的应用」一类跨应用执行能力属 HarmonyOS 7 系统侧小艺能力，未对三方应用开放程序化转发接口。

## 7.3 小艺接入渠道图景与鸿蒙端可接入性（R6，2026-11-19）

小艺对开发者的接入渠道共三个系统入口，均经 Intents Kit 意图框架、走「小艺开放平台」上架流程（管理中心 → 项目管理 → 资源库「意图框架」页签配置）：

| 渠道 | 机制 | 对鸿蒙端的价值 | 可接入性 |
| --- | --- | --- | --- |
| **小艺建议**（桌面/智慧搜索卡片） | 系统学习用户习惯与事件特征，主动推卡片；分「习惯推荐」「事件推荐」 | **审批提醒/任务状态可借卡片触达**——「Neurova 有任务等你审批」以系统级卡片出现在桌面，比应用内通知更靠前，且不依赖无障碍权限 | 需意图命中官方垂域 Schema（当前覆盖影音娱乐、出行导航等）；上架经审核。我们的「任务审批」场景未必在已开放垂域内，需按上架指导逐项申请 |
| **小艺对话** | 用户语音/文字 → 小艺理解 → 命中应用注册的意图 → 拉起应用执行 | **语音唤起入口**：用户对小艺说「让 Neurova 帮我…」即拉起鸿蒙端开始任务（仅入口，执行能力仍受 §7 R1 限制） | 同上；对话意图对垂域与调优要求更高 |
| **小艺搜索**（智慧搜索内模块） | 本地搜索命中应用意图/服务 | 补充曝光，价值次之 | 同上 |

**要点**：三个渠道都是「小艺 → 应用」的分发方向，执行方始终是应用自身——**小艺渠道解决「入口与触达」，不解决「代操作权限」**。对本仓鸿蒙端的落点：① 短期不做（预研阶段无企业上架流程）；② 产品化阶段把「审批提醒卡片」与「语音唤起」列为鸿蒙端增强项，依赖企业开发者资质与垂域申请；③ 执行权限缺口不因接入小艺而改变，安卓端承担代操作的结论不变。

## 8. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 国产 ROM 对无障碍/后台保活的限制差异大 | M7 体检页分品牌引导；体检不通过的能力诚实标灰 |
| 金融类应用检测无障碍服务拒绝运行 | 按需开关纪律（M1）+ 敏感应用默认隐身（M3）；用户知情条款写入产品文案 |
| 屏幕数据出手机的隐私顾虑 | 最小化（§5.4）+ 本地优先 + 账本无明文 |
| agent 误操作造成不可逆后果 | M4 审批扣住 + M6 熔断 + 随时接管（§5.5） |
| 鸿蒙权限不可得 | R 系列前置预研，结论前不动生产码 |

## 9. 里程碑

- **P0（预研）**：~~R1–R4 鸿蒙结论~~（**已完成，2026-11-19，见 §7：鸿蒙执行器不可行，定位审批终端**）+ 安卓 M1 技术验证（无障碍开关与读屏跑通）。
- **P1（最小闭环）**：M1–M6 + M8，无真机全链回归。
- **P2（真机演示）**：M7 + M9，真机演示任务成功 + 安全判据全过。
- **P3（产品化）**：多任务场景、定时任务接入（复用 scheduler）、报告导出面（对齐 P2-2）。
