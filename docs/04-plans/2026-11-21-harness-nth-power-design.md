## 0. 摘要与代号释义

Harness^N 是递归自演化的第二期：以第一期交付的治理框架为地基，把 **Neurova 整体作为可演化 harness**，追求"演化能力本身逐代增强"的递归形态。

**n 的三重含义 → 三个工程机制**：

| 含义 | 工程机制 |
|---|---|
| **无限演化可能** | 世代链无终点持续运转；可演化面随代际扩展（白名单逐批放开，禁改内核红线不动）；判据与任务分布随评测棘轮共同生长 |
| **一次演化后能力几何式增强** | **复合增益**：上代全部成果进入下代基线（prompt 更好 → 候选更好 → 判据更准 → 下一代更会改）；**演化工具链自身入注册表成为可演化对象**——递归的递归 |
| **n = Neurova** | 自指演化：Neurova 用自己体内的信号、判据、审批、回滚闭环改自己；不引入外部演化系统 |

**一句话定位**：第一期让 Neurova "能安全地改自己"；Harness^N 让 Neurova "越改越会改"。

## 1. 目标与非目标

**目标**：

1. L1/L1.5/L2/L3 全层演化常态运转，代码级演化从白名单试点扩展到注册表治理下的大范围代码面；
2. 多臂协同：一个世代可打包参数 + 文本 + 技能 + 代码的联合变更，统一验证、统一谱系；
3. 信号驱动持续演化：高严重度信号实时立案，演化从"手动一轮"走向"持续运转"（仍受预算/审批/相位约束）；
4. 演化工具链自身可演化（改进器版本自动升级、判据参数区间内自调、剪枝策略自适应）；
5. 复合增益可测、可视、可归因。

**非目标（红线）**：

- 不修改修复教义、审批链 L2 人工门、禁改内核清单——这些是演化的边界条件，不是演化对象；
- 不追求"无人监督失控自主"：全自动档仍受部署相位门（phase≥4）与 §8 四前置探针约束；
- 不承诺"几何倍数"指标：以复合增益曲线如实记录，按数据说话。

## 3. 核心机制设计

### 3.1 递归的递归：演化工具链自身可演化

这是 Harness^N 区别于第一期的核心。把"演化系统自己的部件"登记进 TargetRegistry（L3 层），在**人工划定的安全区间内**自演化：

| 可演化对象（L3） | 边界 | 判据 |
|---|---|---|
| 改进器版本（CandidatePolicy I_t） | ImproverVersionLedger 版本链；**升级须过配对探针 Γ 判据**（三臂对比已有），phase≥4 后转全自动档 | Γ 显著为正才入账 |
| 门禁阈值参数 | 仅"允许区间"内可调（如 G2 回退容忍度、金丝雀窗长）；区间边界 forbidden | 历史误报率/漏报率不恶化 |
| 剪枝器配置 | 棘轮轮数与每轮候选数（现 `rsi_ratchet_candidates=[50,10,3]`）的区间内自适应 | 被拒候选的事后复盘通过率 |
| 信号采样权重 | SignalBus 各路信号的立案权重（跨租户分布约束不变） | 立案精准度（人工复核抽样） |
| 评测 case 选择策略 | 评测棘轮的 case 选取/采样策略 | held-out 上不可作弊（leak_critic 既有件复用） |

**判据逻辑本体、注册表内容、区间边界、held-out 划分：一律 forbidden，只能人工改**——裁判永远在演化集合之外。

### 3.2 多臂协同世代

一期各臂（RSI 参数、文本/技能、工具、代码）独立产候选；Harness^N 允许**一个世代打包多臂变更**：

- 世代规划器按信号归因选择臂组合，显式声明臂间依赖与冲突（同文件、同参数互斥则拆分世代）；
- 联合验证：打包世代在影子环境一次性跑完整 G0-G4（避免多臂分别验证、合并后效果漂移）；
- 谱系归一：多臂变更在世代账本中按 change 记录各自 targetId 与臂来源，归因可分、谱系唯一。

### 3.3 执行体编排（多外部 agent 并行）

- neuacp 多成员并行产候选：同一任务书可派发给多个外部编码 agent（不同模型/不同策略），产出多候选；
- 候选统一进 swarm 候选 CAS 板（同基准冲突双保留、升级人工——既有纪律）；
- 执行体能力画像：按历史候选存活率/通过率给执行体打分，派活时加权选择（画像本身是 L3 观测对象，不自动淘汰执行体）；
- 租户红线不变：池键租户段首位、run 级 HMAC 凭据、跨租户不共享进程。

### 3.4 信号驱动持续演化

- **立案器**：SignalBus 高严重度信号（validated 的 error 反思、human_takeover、G2 例级回归聚集）实时创建世代提案；
- 节流与预算：沿 `rsi_event_throttle_seconds` / `rsi_backoff_every_turns` 范式扩展为全局演化预算门（token/时长/并发世代数上限）；
- 节奏：event-driven 为主，periodic 兜底轮（TaskScheduler addSystemJob）保证低信号期也有稳定迭代；
- 维护窗口：重验证（全门禁 + 影子启动）可配置在低峰窗口执行，避免挤占生产（多租户纪律，见一期详案 §10）。

### 3.5 复合增益度量（"几何式增强"的可测口径）

指标族（全部入世代账本与观测面）：

1. **候选存活率**：进入门禁的候选中通过 G0-G4 的比例（代际趋势）；
2. **门禁一次通过率**：首验即绿的比例（反映候选质量）；
3. **单位预算增益**：每千 token / 每分钟验证成本换来的 G2 分增益；
4. **改进器版本 Γ**：I_t 对 I_0 的配对增益（已有三臂探针）；
5. **可演化面覆盖率**：注册表中已激活对象占可登记对象的比例；
6. **世代复合基线**：每代 G2 绝对分（累计成果）。

归因：世代级按臂分解增益贡献（哪些臂带来多少），喂回 MetaEvaluator 调来源权重。

**诚实性纪律**：增益曲线如实记录；若代际增益趋平，如实呈现并归因（判据饱和/任务分布限制/改进器退化），不拟合"几何增长"叙事。

### 3.6 安全不变式（继承一期 + 强化）

- 禁改内核红线、存活探针每代必跑、审批链分级、租户 scope 纪律、金丝雀不碰生产流量：**全部继承一期，无例外**；
- 新增强化：L3 自演化对象的每次调参本身是一个微世代（入账本、可回滚）；改进器自动升级在 phase<4 时仍走人工批准（既有 `/rsi/improver-upgrade/approve` 端点语义不变）。

## 4. 分期卡位（P4–P6 草案）

| 期 | 卡 | 内容 | 依赖 | 验收 |
|---|---|---|---|---|
| P4 | P4-1 | 多臂协同世代规划器（打包/冲突检测/联合验证） | 一期 P1–P2 | 多臂打包世代全链跑通，谱系归一 |
| P4 | P4-2 | 执行体并行编排 + 能力画像 | P4-1 | 多外部 agent 并行产候选，CAS 合并，画像入观测面 |
| P5 | P5-1 | 信号驱动立案器 + 全局演化预算门 | 一期 P1 | 高严重度信号实时立案；预算熔断可演练 |
| P5 | P5-2 | 持续演化节奏（event-driven + periodic 兜底 + 维护窗） | P5-1 | 低干预连续运行 N 代，全程台账完整 |
| P6 | P6-1 | L3 自演化对象入注册表（改进器/阈值/剪枝/采样权重） | 一期 P3 | 区间内自调参入账本，越界被拒 |
| P6 | P6-2 | 改进器自动升级转全自动档（phase≥4） | P6-1 | Γ 判据自动升级演练；phase<4 仍走人工 |
| P6 | P6-3 | 复合增益观测面 + 归因报告 | P4 | 六指标族出街；归因喂回 MetaEvaluator |

**P6 完成即 Harness^N 形态闭环**：Neurova 持续运转的自演化系统，演化能力本身在被演化，且全程处于人工划定的安全边界内。
