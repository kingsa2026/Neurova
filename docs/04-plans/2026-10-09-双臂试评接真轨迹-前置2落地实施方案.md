# 双臂试评接真 agent 轨迹（§8 前置 2 落地）+ 前置探针口径修正 实施方案

> **执行须知**：按 `neurova-repair-batch-pipeline` 八段走，每 Task 独立红→绿→自证→提交。
> 纪律权威源是 `AGENTS.md`；本票面只给命令级与代码级细节。
> 立票日期 2026-10-09。用户裁决：**按丙（真轨迹只进人工审批前的双臂试评）+ 修 C（探针口径）**。

**Goal:** 让审批人在 `POST /skills/{agent_id}/ab` 上看到**真 agent 回合**产出的双臂差，
而不是单轮模拟分；同时把 §8 前置 2 的探针从"默认兜底执行器是否回显"改成
"**生产装配点实际注入的执行器是否跑真 agent**"——后者不修，前者一接线就会把旗标假翻真。

**Architecture:** 三层各补一件，不新造第四套体系：
① **执行器回落单源**（今天同一句 `agent or SimulatedAgent(...)` 写了两份）；
② **轮级候选正文覆盖槽**（`turn_context` 一枚 ContextVar，由技能正文的唯一取数口读取），
这是让"两份正文"在真 agent 上产生不同输出的**唯一同域形态**；
③ **评测只读闸门补全**（`save_memory=False` 覆盖面已在，缺漏斗账本与 RSI 迭代两步）。
执行入口走 `Agent.chat(..., save_memory=False)`，**不走** `process_message`（理由见「复核实状」第 3 条）。

**Tech Stack:** Python 3.12 / pytest / 既有 `turn_context` 轮级开关家族 / 既有 `ab_library` 双臂台架。

**Spec:** `docs/08-research/designer_rsi_paper_vs_neurova_rsi_comparison_2026-10-08.md`
§7-Q2（本票按丙收口）+ §7-Q3（维持默认，自动轮不动生产）+ §8 前置 2 + 台账 §6-97。

## Global Constraints（每个 Task 隐含遵守）

- 提交中文正文、Conventional Commits、单任务单 commit；`git commit --only -- <pathset>`，
  严禁 `git add -A`（工作树常含并发在途改动）。
- **`docs/0-index/README.md` 与 `docs/INDEX.md` 现含并发会话的未提交段**（Semantica 那一批）：
  本票与后续判据的索引登记**必须等那一段入库后**再动，否则 `--only` 会把别人的段落吞进我的 commit
  （本仓栽过，教训见记忆「同文件含他人未提交段须按 hunk 归属提交」）。
- 净生产 LOC 为正必须 `git diff --numstat` 实取后逐条列去向；红必须红在行为断言上。
- 判据里**不许**用 `hasattr(module, 名字)` 去证明装配还在——`monkeypatch.setattr(..., raising=False)`
  会自己造出那个名字（台账 §6-97 的第二条弯路）。要证明门在，就测**未桩掉的真实行为**。
- 副作用核销**不做目录清单集合差**（看不见原地改写）：按行数/md5/逐对象计数精确核。
- 真 LLM 不许进 CI：所有判据用注入替身；真轨迹只在 live-verify 里跑，且走
  `tests/manual/_liveVerifyIsolation.isolatedDataRoot()`。

## 复核实状（2026-10-09 现场实测，本票立论依据）

1. **"每轮自动评测"这个前提今天不存在**：`closed_loop.py:654` 的 `run_iteration()` 只做 RSI
   度量与阶段判定，`rsi/orchestrator.py` 全文零 `evolve`/`EvolutionService` 命中。文本进化在生产
   的**唯一入口**是 admin 端点 `text_evolution_api.py:187`。⇒ 原 Q2 的问法（"进不进每轮自动评测"）
   前提错位，本票按真实问法收口：**人工审批前的双臂试评跑不跑真轨迹**。
2. **现役执行器是单轮模拟，且回落写了两份**：端点 `:187` 不传 `agent=` ⇒ `service.py:253-256` 回落
   `SimulatedAgent`；`ab_compare` 在 `service.py:379` **又写了一遍同样的回落**。
   `SimulatedAgent.run`（`service.py:67-90`）= 把 `skill_text` 塞进 system 提示、单轮 chat，
   无工具、无上下文池、无技能召回 ⇒ 与线上行为不同域（§8 前置 2 的病）。
3. **`Agent.process_message` 是断链，本票不走它**：`agent_core.py:1688` 调
   `self._router.create_message(...)`，而 `_router` 是 `create_default_router` 返回的
   `MessageRouter`（`agent_core.py:1507-1516`、`router.py:514-532`），该类方法实测为
   `route/_route_command/_route_skill_request/_route_memory_request/_route_chat/register_*/get_route_stats/clear_stats`
   ——**没有 `create_message`**；`tests/unit/core/test_router.py:5-7` 的说明明写该 API 随异步化重构
   **已移除**。活体复现：`MessageRouter().create_message(...)` ⇒
   `AttributeError: 'MessageRouter' object has no attribute 'create_message'`。
   全仓唯一消费者是 `ab_library.py:134`（其调用方只有测试替身），而 `agent_core.py:7` 的模块 docstring
   仍宣称它是"统一入口，所有消息经过 Router 路由"。⇒ **单独立批处置，不并入本票**（决策点 D1）。
4. **真 turn 的副作用有一半已经能关**：`Agent.chat(..., save_memory=False)`（`agent_core.py:1702-1712`
   签名含 `save_memory`）在 `post_chat_pipeline.py` 已被四处尊重——
   `:963-970`（session 备份 SKIPPED）、`:1104-1111`（记忆保存跳过）、`:1686-1693`（经验记录跳过）、
   `:1981-1988`（`_step_p0_post_processing` 整段跳过，含 lifecycle / pattern_mining / genetic / marketplace）。
   **没被尊重的两处**：`_step_skill_funnel_flush`（`:1857`，形参里没有 `save_memory`）与
   `_step_rsi_iteration`（`:2749`，同）⇒ 评测轮会往**技能漏斗账本**和 **RSI 迭代台账**里落假样本。
   另两处不受 turn 级控制：trace 自动落盘（`core/trace_recorder.py:161` 写档、`:530/535` 只有实例级
   `set_enabled/set_auto_save`）、治理审计（`tool_executor.py:1933` → `AuditLogger`）。
   **零成本一条**：`agent_runs` 台账的准入调用全在传输面（`api/endpoints/chat.py:296,463`、
   `console.py:796`、`channels/channel_router.py:190`），直调 `agent.chat` 不产 run 行。
5. **候选正文进真 prompt 的通道今天不存在**：技能正文唯一取数口 `skills/skill_injection.py:47`
   `_skill_doc_text`（取 `skill.doc_text` → `skill_dir/SKILL.md` → description），全文注入只在
   本轮输入含 `$name`/`@name` 时发生（`:35` `_MENTION_RE`，拼进行为 `:373`，落点
   `agent/chat_pipeline.py:1420-1422`）；目录段（`context/orchestrator.py:2651/2709/2733`）只有
   name+description。现有两枚轮级技能槽都不具备覆盖面：`_skills_off_var`（`turn_context.py:68`，
   全有/全无）与 `_skill_view_var`（`:31`，其 `VisibleSkill` 见 `skill_visibility.py:43-79`
   **无正文字段**）。⇒ 必须新增一枚 turn 级覆盖槽（决策点 D2）。
6. **成本有界，这是选丙的量化理由**：双臂试评取 `dataset.heldout or evaluation_split(dataset)`
   （`service.py:367`），默认 `holdout_ratio=0.25`、`max_examples=50`（`miner.py:161`）⇒ 约 12 例 ×
   2 臂 ≈ **24 次真 turn**。对照：若按丁进每轮自动进化，按 `iterations=10`、`variants_per_round=1`
   逐站点算（`runner.py:525/532/597/608/687/743/745`）≈ **480 次执行 + 480 次判分**，
   其中执行面换成真 turn 即 480 个完整回合。

## 决策点（票面先给推荐，落刀前需用户点头；未点头的按推荐执行并在此处回写）

- **D1 `process_message` 断链**：三选一——(a) 重新提供 `create_message`（等于复活已移除 API，
  与 `test_router.py` 的说明相冲）；(b) `process_message` 自己构造 `Message`（改一处、保住"统一入口"
  的对外承诺）；(c) 退役 `process_message` 并清掉 `agent_core.py:7` 的宣称（`ab_library.py:134` 随之
  改指 `chat`）。**推荐 (b)**，且**独立成批**——它与"接真轨迹"不是同一根因，捆在一起会违反教义第 1 条
  的"根因处修"。本批只登记（台账 §6-98）。
- **D2 候选正文进 prompt 的形态**：**推荐新增 turn 级覆盖槽**（`turn_context` 一枚 ContextVar，
  由 `skill_injection.py:47` 在评测态读取）。备选 (b) 走全局 registry 物化
  （先例 `skills/market_registry.py:310 restore_library_skills_for_turn`）——但它写全局、无回滚，
  并发轮次会互相看见，不可接受；备选 (c) 把正文当 system 前缀塞进 `user_input`——**不同域**，
  它测的是"模型读这段指令"，不是"这段正文经技能管线后的线上行为"，若选它必须在前端与提案面上
  显式降级标注，前置 2 不得据此翻真。
- **D3 漏斗账本 / RSI 迭代两处闸门**：**推荐**给 `_step_skill_funnel_flush`、`_step_rsi_iteration`
  补 `save_memory` 尊重（同族于既有 `:1981` 的修法，不新造旗标）。备选是新增一枚 `eval_mode` 旗标
  ——那会是"评测态"的第二处定义，违反教义第 6 条，不作首选。
