
- Windows + Git Bash。控制台默认 GBK，探针输出请设 `PYTHONIOENCODING=utf-8`；
  **乱码不等于编码 bug**，别据此改源文件编码。
- **禁止裸跑全量 `pytest tests/`**：有两个用例会把 python 进程打死（`start_script` 那个会开浏览器）。
  按目录分块跑取摘要，全量回归须 `--deselect` 掉已知自杀用例。
- CRLF 噪声：`git diff` 出现整文件换行改动时，先确认不是自己引入的；提交用 `git add -p` 精准切分。
- 判断"是否已交付"看 git 树不看磁盘：`git show HEAD:<path>` 单独检出验一次。
- 远端陷阱：活跃远端是 `cnb`，GitHub `origin` 是过期镜像且是 main 的 upstream，`ahead` 数虚高。
  **任何 push 都要先问人**，本工单不含 push。

  `scripts/scan_docs_refs.py`，Windows 默认 GBK 解码会在 reader 线程抛 `UnicodeDecodeError`，
  伪造出 6 条红（实测：裸跑 6 failed / 2 passed，加 `PYTHONUTF8=1` 后 8 passed）。
  这是环境不是缺陷 —— 见到这批红先加环境变量重跑，再判定是否真红。
- **grep 假命中（务必排除这三处副本目录）**：`NeurUI/src/.mimosa/hook-state/**`（工具本地缓存，
  已被 `.gitignore:117` 的 `.*/` 规则忽略、未跟踪，2.6MB，内含前端源码历史副本）、

1. **先跑红**：每单第一个 commit 只能是测试（红），实现是后续 commit。红测试必须失败在根因上，

## 12. T-11 分层压缩与层索引（"分辨率指数衰减 + 层即索引"的达成路径）

> 来源：负责人提出的目标 —— "整个轨迹始终在上下文里，但分辨率呈指数级衰减，最近的完整保留、
> 老的逐步被摘要，这些层级同时充当索引，需要细节时可随时检索回原始内容"。
> 审计判定：这条目标里的 **分辨率梯度（C2）** 与 **层即索引（C4）** 两条，T-01…T-10 都不覆盖，
> 属新增能力而非缺陷修复，故立本族。

### 12.0 目标口径（**已采纳** —— 负责人 2026-09-21 确认验收标准）

原始表述"整个轨迹始终在上下文里，分辨率呈指数级衰减"拆成两条可测承诺：

- **A 可寻址**：任何已归档内容都存在一条**确定性**回取路径（不依赖语义召回碰运气）。
- **B 概览梯度常驻**：视图内每一分辨率档至少一个节点常驻，且越远的位置分辨率越低。

字面意义的"全部原文常驻视图"不成立也不追求（窗口预算有限）。本族按 A+B 验收，验收线见 §12.7。

### 12.1 术语与判据（每条都要有测试，不接受"感觉分层了"）

**分辨率档定义**（节点 `level` 字段的取值即档号）：

- **L0 原文**：未被折叠的会话消息与工具结果；
- **L1 轮段摘要**：覆盖连续 ≤4 轮；
- **L2 跨段概览**：覆盖 ≥2 个 L1 节点；
- **L3 轨迹顶概览**：covers 触达会话起点，每轮视图必须常驻（判据见 §12.7 第 4 条）。

- **C2 梯度**：视图内出现的不同 `level` 数 ≥ 3；相邻档实测 token 预算比 **1 : 4 : 16**（容差 ±25%）。
  测量口径必须是 T-01 之后的 EXACT/`o200k`，**禁止**用 BALANCED 自证。
  定比写成类常量并注明理由（常量集中处见 `orchestrator.py:984`、`:1113`、`:113`）。
  档数不设上限：轨迹越长档数自然增长，"指数衰减"由此成立而非由命名成立。
  （**2026-09-25 负责人裁定**：T-11a 交付时曾给进程内代际栈设过上限 5，该偏离已
  **撤销** —— 代际栈是"+1 新代 / 既有代各降一层"的等量代换，不是只增容器；
  上限的真实代价是丢弃当时最深一档。工单原话自此**不再有偏离记录**。）
- **C4 索引**：视图内每个摘要节点都能解析出 `covers`（turn 区间 + 下层条目 hash 列表），
  解析失败率必须为 0。
- **C1/C3/C5 由 T-01/T-02/T-03/T-04/T-07/T-08/T-10 保障，本族不得回退它们。**
