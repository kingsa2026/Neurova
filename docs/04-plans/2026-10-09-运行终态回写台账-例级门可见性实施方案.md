# 运行终态回写台账（例级门可见性）实施方案

> **执行须知**：按 `neurova-repair-batch-pipeline` 八段走，每 Task 独立红→绿→自证→提交。
> 纪律权威源是 `AGENTS.md`（核心原则 / 修复教义 / §2-§5），本票面只给命令级与代码级细节。

**Goal:** 让「一次进化运行最终部署了没有」这件事回写进台账，使三个既有读方（变异器提示词、
探索指令、产出剪枝）不再被假阳性骗到；顺带让 §8 前置 1 那道新门**拦了谁**变得可见——
不是靠新建通道，而是接进已经有人的那条线。

**Architecture:** 判定链的六处终局拒绝现在是四行同形的手抄（复位 `deployed_text` → 附 heldout 证据
→ 回填 → 返回），收成一个 `_rejectRun(...)` 出口；该出口在同批把胜者那条台账记录的
`accepted` 翻成 `False` 并带上 `reject_reason`，同时新增 `round_winner=True` 保留「它在 tune 集上是
argmax」这一事实——一格一义（教义第 6 条），不让同一个 `accepted` 既表「本轮赢」又表「被部署」。
`runs/*.json` 审计面仍无读方，本票**不**为它开 HTTP 通道（§6-9 的另一半留作可选后续）。

**Tech Stack:** Python 3.12 / pytest（`.venv/Scripts/python.exe -m pytest`）/ JSONL 台账
（`EvolutionLedger`）/ 既有 `patch(key, seq, dict)` 定点更新语义。

**Spec:** `docs/08-research/designer_rsi_paper_vs_neurova_rsi_comparison_2026-10-08.md`
§6-9（审计面只写不读）、§8 前置 1（例级门已满足）、§9 第 8 项（门越严，取数歧义越致命）。
本票是 §6-9 的落地票面。

## 复核实状（2026-10-09 现场实测，票面立论依据）

**台账 `accepted` 记的是「候选在本轮 tune 上赢了」，不是「运行部署了它」——而三个读方都按后者理解它。**

| 事实 | 出处（现读行号） |
|---|---|
| 胜者行在**评测期**就写 `accepted=is_winner` | `eval/runner.py:461`（并行轮）与 `:600`（单线轮 `accepted=improved`） |
| 终局拒绝后**只回填指标，从不翻 `accepted`** | `:630-633` 的 `patch(..., {"delta_holdout","holdout_after"})` |
| 六处终局拒绝同形四行（复位 → 附证据 → 返回） | `:640-642` `holdout_regression`、`:650-652` `no_improvement`、`:666-668` `case_regression`、`:688-690` `anchor_unreached`、`:706-708` `cost_rule_failed`、`:727-729` `bench_regression` |
| 两处早退**根本没有胜者行**（`best_seq` 仍 None） | `:497` `empty_dataset`、`:522` `judge_unavailable` |
| 读方 1：提示词把 `accepted` 当「已生效」并写「勿做无谓回退」 | `eval/history_ledger.py:149, 163-166` |
| 读方 2：窗口内只要有一条 `accepted` 就**抑制**探索指令 | `history_ledger.py:199-208`（`stall_window=5`，`any(r.get("accepted"))` 即返回空串） |
| 读方 3：产出剪枝见到 `accepted` 就跳过该 key | `evolution_yield_prune.py:51` |
| `patch` 是 `dict.update` 语义、seq 不存在则静默忽略 | `history_ledger.py:90-99` |
| 被门拒的运行**不出提案**，故提案端点看不见它 | `eval/service.py:287`（`if not result.rejected and result.changed`） |
| `runs/*.json` 全仓只有写方 | `service.py:501-505`；`grep -rn '_runs_dir\|evolution/runs' neurova/` 除写入外零命中（`neurova/` 与 `src/` 皆无读方） |

**骗局的实际形状**：一条被例级门拒掉的候选（撞坏既有用例），在台账里仍是
`accepted=True` → 下一轮变异器读到「这个假设已生效，勿做无谓回退」，**正是要它别再去修的那个方向**；
同时该技能的运行永远「有一条被接受」，探索指令永不触发、产出剪枝永不命中。
前置 1 那道门落地后，这条假阳性的**产生频率**从「几乎无」变成「凡撞坏用例必有」——
本票因此排在 §6-9 的另一半（给审计面开读口）之前：先让反馈不再说谎，再谈人怎么看。

from neurova.evolution.eval.config import EvolutionConfig
from neurova.evolution.eval.dataset import EvalDataset, EvalExample
from neurova.evolution.eval.fitness import FitnessScore
from neurova.evolution.eval.history_ledger import EvolutionLedger
from neurova.evolution.eval.runner import SkillEvolutionRunner

MARKER = "IMPROVED"
BASELINE = "基础技能正文。" + "补充说明文字用于满足增长闸的基线长度要求。" * 2


class _SplitJudge:
    """基线侧/候选侧分表：候选正文带 MARKER 时取 `candidateScores`。"""

    def __init__(self, base, candidate):
        self._base, self._candidate = dict(base), dict(candidate)

    async def score(self, *, task_input, expected_behavior, output, skill_text, **kw):
        table = self._candidate if MARKER in skill_text else self._base
        v = table.get(task_input, 0.0)
        return FitnessScore(correctness=v, procedure_following=v, conciseness=v, feedback="")


class _EchoAgent:
    async def run(self, *, skill_text, task_input):
        return f"out::{skill_text}"


async def _markerMutate(*, artifact_text, artifact_type, failures, **kw):
    return artifact_text + f"\n{MARKER}"


def _dataset(names):
    items = [EvalExample(task_input=n, expected_behavior="输出要点") for n in names]
    return EvalDataset(train=list(items), val=[], holdout=list(items))


def _runnerWithLedger(ledger, base, candidate, config):
    return SkillEvolutionRunner(
        config, judge=_SplitJudge(base, candidate), agent=_EchoAgent(),
        mutate=_markerMutate, ledger=ledger)


class TestRejectedRunFlipsLedgerOutcome:
    @pytest.mark.asyncio
    async def testCaseRegressionRejectionLandsInLedger(self, tmp_path):
        ledger = EvolutionLedger(tmp_path / "history")
        runner = _runnerWithLedger(
            ledger,
            {"a": 0.4, "b": 0.4, "c": 0.4},
            {"a": 0.9, "b": 0.9, "c": 0.1},
            EvolutionConfig(iterations=1, min_improvement=0.0, case_regression_allowance=0),
        )
        result = await runner.run(
            baseline_text=BASELINE, dataset=_dataset(["a", "b", "c"]),
            artifact_type="skill", ledger_key="s1")

        assert result.reject_reason == "case_regression"          # 门确实拦了
        rows = ledger.tail("s1", 10)
        assert rows, "台账应有本轮记录"
        assert not [r for r in rows if r.get("accepted")], \
            f"运行未部署，台账不得留着 accepted=True: {rows}"
        gated = [r for r in rows if r.get("reject_reason") == "case_regression"]
        assert gated, "被门拦这一事实必须落进台账，供既有读方回读"
        assert all(r.get("round_winner") is not False for r in gated)

    async def _rejectRun(self, result: EvolutionRunResult, *, reason: str,
                         baseline_text: str, dataset: EvalDataset, artifact_type: str,
                         ledger_key: str, best_seq: Optional[int]) -> EvolutionRunResult:
        """终局拒绝的唯一出口：落理由、复位部署正文、把台账结局改回「未部署」、附证据、返回。

        `accepted` 在这里被钉成**「该假设被部署」**而非「它在本轮 tune 上赢了」——后者由
        `round_winner` 保留。六个判据点过去各抄四行、且都不回写台账，于是「被拒的运行」
        在三个读方眼里仍是一条成功记录（§6-9）。
        """
        result.rejected = True
        result.reject_reason = reason
        result.deployed_text = baseline_text
        if self._ledger is not None and ledger_key and best_seq is not None:
            try:
                self._ledger.patch(ledger_key, best_seq,
                                   {"accepted": False, "reject_reason": reason,
                                    "round_winner": True})
            except OSError as e:
                logger.debug("运行终态回写台账失败: %s", e)
        await self._attach_heldout_evidence(result, dataset, artifact_type)
